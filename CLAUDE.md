# GameEngine

A from-scratch C++20 game engine. Long-term goal: support both **FPS** and **MOBA** style games by keeping the core genre-agnostic and putting genre-specific code (camera controllers, weapons, abilities, netcode style) in separate modules on top.

The roadmap is in `ROADMAP.md`. Phases 0-3 (foundations, GPU rendering and assets, core loop and input, engine architecture) are done; phase 4 (rendering upgrades) is next.

## Build and run

- `make` builds `build/game.exe` and compiles shaders (`glslc` -> `.spv`).
- `make run` builds and runs the game. Run it from the repo root: asset and shader paths are relative (`assets/...`).
- `make test` builds and runs `build/tests.exe`.
- The makefile finds `src/**/*.cpp` recursively (`rwildcard`) and `tests/*.cpp`, so new files are picked up automatically. Headers and the makefile are tracked as dependencies. Include roots are `-Isrc -Iexternal`.
- Flags are `-std=c++20 -Wall -Wextra -g` with no optimisation (-O0). A release target with `-O2` is a planned improvement.
- Dependencies: SDL3, SDL3_image, `glslc` (MSYS2 `shaderc` package here; the Vulkan SDK's also works), and cgltf (vendored in `external/cgltf`).
- `build/`, `*.exe` and `*.spv` are git-ignored.
- `python tools/package_demo.py` builds and packages `build/GameEngineDemo.zip` for a PC without MSYS2: stripped exe, DLLs found by following import tables with MSYS2 `objdump`, plus the SDL3_image decoder DLLs for the image formats the assets use (they are loaded at runtime, so import tables do not show them), all of `assets/` except shader sources, and a README. It fails if any imported DLL is neither packaged nor part of Windows.
- Source files use CRLF line endings. Preserve them when editing.

## Source layout

Code lives in layered folders under `src/`. Dependencies point downward only: a folder may include from folders below it, never above.

- `ecs/` (`Entity`, `ComponentStorage`, `World`), `core/` (`fixed_timestep`, `pixel`) and `math/` (vectors, `Mat4`, `Transform`, `Ray`): depend on nothing else.
- `input/` (`Key`, `Input`): SDL-free, depends on `math/`.
- `scene/` (meshes, `indexed_mesh`, models, `MaterialSource`, `Material`, `asset_handles`, `ModelRenderer`, `interpolation`, `light`, `lighting`, `Camera`, `camera_ray`) and `assets/` (`AssetManager`, loaders, cgltf). `scene/` and `render/` never include `assets/`.
- `gameplay/` (`CharacterMovement`, `Spinner`, `MoveToController`, `edge_pan`) and `gameplay/camera/` (`look_controls`, `FreeFlyCameraController`, `FirstPersonCameraController`, `MobaCameraController`).
- `platform/` (`Window`, `sdl_input`), `render/gpu/` (`GpuRenderer`, `GpuMesh`, `GpuTexture`), `render/software/` (reference rasterizer). `render/` takes a raw `SDL_Window*` and never includes `input/` or `platform/`.
- `engine/` (`Application`, the `Game` interface, `runFixedUpdate`): the loop and everything shared by all games. Never includes `games/`.
- `games/` (`demo/DemoGame`, `demo/ControlMode`): one folder per game, built on the `Game` interface. Games never include `platform/`, `render/` or SDL, so they can run headless.
- `app/` (`main`): picks a game and starts the engine; may include everything.

Write includes from the `src` root with the folder: `#include "math/vec3.h"`, `#include "cgltf/cgltf.h"`. Never use relative `../` includes.

## Architecture (current)

Live path: `main` creates a `DemoGame` and an `Application` (the engine), which drives the game through the `Game` hooks, fills `Input` from the `Window`, and draws the `World` with the `GpuRenderer`.

- `Application` (`engine/`) runs the main loop (fixed timestep, frame cap) for a borrowed `Game` (declare the game first so it outlives the engine). It owns the `Window`, `GpuRenderer`, `Input`, the `World` and the `AssetManager`. Before each frame it uploads every mesh and texture the `AssetManager` gained since the last frame (the ones past the renderer's counts), so games can load and spawn at any time. It applies `game.wantsMouseLook()` to the window only when it changes (re-applying would undo Escape).
- `Game` (`engine/game.h`) hooks, called each frame in this order: `onInput(world, input)` once, `onFixedUpdate(world, tickSeconds, simulationSeconds)` per tick (no `Input` parameter on purpose), `onUpdate(world, input, frameSeconds, alpha)` once; plus `onInit(world, assets)`, `getCamera()` (the engine sets its aspect ratio) and `wantsMouseLook()`. Always run ticks through `runFixedUpdate`, which saves previous transforms first; tests use it too. `DemoGame` (`games/demo/`) holds the camera, control modes, player and marker entities, and all demo input rules. `window` is declared first and `renderer` second: members are destroyed in reverse order, so the renderer goes before the window it draws into, and the GPU device outlives every uploaded mesh.
- `Window` (`platform/`) owns SDL video and the `SDL_Window`: event polling into `Input`, quit, focus loss (releases everything), click to capture (mouse look) or confine (MOBA cursor), Escape to release, Alt+Enter fullscreen. After the events it records the cursor position, window size, keyboard focus, mouse capture and cursor confinement into `Input`, so games read those facts from `Input` instead of the window. It reports raw facts only; game rules live in game code.
- `GpuRenderer` (`render/gpu/`) uses SDL3's GPU API (SDL_GPU) with the Vulkan backend and SPIR-V shaders, drawing into a window it does not own. It owns the device, pipeline, depth texture, and GPU copies of meshes and textures in arrays indexed exactly like the handles (`uploadMesh`, `uploadTexture`, `beginFrame`, `setCamera(camera)`, `setLighting(lighting)`, `drawMesh(MeshHandle, model, material)`, `endFrame`). It never reads files.
- Assets: `MeshHandle` and `TextureHandle` (`scene/asset_handles.h`) are typed indices; a default handle means "none" (no texture = plain colour). `AssetManager` (`assets/`) owns CPU-side meshes, images and imported models, loads each file once (`loadMesh` for OBJ, with optional `MeshLoadOptions{.smoothNormals, .creaseAngle}` that are part of the cache key, `loadTexture` by path+flip or embedded buffer, `loadModel` for glTF, which returns a stable `const Model&`), and gives the same handle for the same shared mesh pointer. Assets are append-only, so handles never go stale (add a generation like `Entity` if unloading is added). Loaders produce `Model`s whose parts hold a shared `Mesh` and a `MaterialSource` (colour + texture path or embedded bytes + flip); `AssetManager::makeMaterial` turns that into a `Material` (colour + `TextureHandle`, plus `specularStrength` 0.25 and `shininess` 32 by default; set the strength to 0 for matte surfaces). `packMaterial` (`render/gpu/material_uniforms`) turns a `Material` into `MaterialUniformData`, which mirrors the shader's `MaterialData` block (32 bytes, fragment slot 0, pushed per draw).
- `Input` is a once-per-frame snapshot with no SDL dependency: `isKeyHeld`, `wasKeyPressed`, `wasKeyReleased` take an engine `Key` (`key.h`, physical US-layout positions), plus accumulated `getMouseDelta`. Mouse buttons (`MouseButton`) work like keys, and each press is also recorded as a `MouseButtonPress` with the exact event position (window pixels) and timestamp (ns, `SDL_GetTicksNS` clock): use `getLastMouseButtonPress` for clicks, `getCursorPosition`/`isCursorInWindow`/`getWindowSize` for continuous things. It is filled through `pressKey`/`releaseKey`/`pressMouseButton`/`releaseMouseButton`/`addMouseMotion`/`setCursor`/`setWindowSize`. `sdl_input` is the only SDL-to-engine translation (`keyFromScancode`, `mouseButtonFromSdl`, `applySdlEvent`, which also drops key repeat). `Window::processEvents(input)` resets and fills it. Mouse motion is only forwarded while the mouse is captured, and is discarded when capture or control mode changes. Game code reads keys from `Input` as `Key` values, never SDL scancodes or `SDL_GetKeyboardState`.
- Entities and components (`ecs/`): an `Entity` is an index plus a generation (handles to destroyed entities go stale even after their slot is reused; `Entity{}` is never alive and means "none"). `World` creates/destroys entities and stores one `ComponentStorage<T>` (sparse set: packed `components`, owning `entities`, and a `sparse` index) per component type. Components are plain structs; systems are free functions run with `world.each<A, B>([](Entity, A&, B&) { ... })`, which walks the first type's packed array, so list the rarest component first. Inside `each`, do not add/remove components of the listed types or destroy entities.
- Components today: `Transform` (`math/`), `PreviousTransform`, `ModelRenderer`, `DirectionalLight`, `PointLight`, `SpotLight` and `AmbientLight` (`scene/`), `Spinner` and `CharacterMovement` (`gameplay/`). `ModelRenderer` is a list of `RenderPart`s (mesh, material, `localTransform` with the model's normalization folded in) plus `visible`; a multi-part model is one entity. Parts hold a `MeshHandle` and a `Material`, so the component is small and copyable. Build with `assets.makeModelRenderer(model, normalization)` or `makeMeshRenderer(meshHandle, material)`.
- Main loop: `FixedTimestep` (120 Hz, frame time clamped to 0.25 s) turns real frame time into a whole number of ticks plus an interpolation `alpha`. Each frame: `game.onInput` turns input into commands, `runFixedUpdate` runs zero or more ticks, `game.onUpdate` moves the camera, then `render(alpha)`. Never read `Input` inside a tick; key/click edges are handled once per frame and reach the simulation as commands. Mouse look and camera movement are per frame, not per tick.
- Each tick: `savePreviousTransforms` (engine), then `DemoGame::onFixedUpdate` runs `updateCharacters`, moves the player's torch to the player, then runs `updateSpinners`. Interpolation: only entities that move continuously get a `PreviousTransform`; `getRenderTransform(world, entity, alpha)` blends it with `Transform` (`interpolate` takes the shortest way around for angles), and entities without one are drawn at their `Transform`. Things that teleport (the destination marker) therefore have no `PreviousTransform`. Create moving entities with `PreviousTransform` equal to their starting `Transform`.
- Cameras: `Camera` (`scene/`) is a plain lens: position, forward, up, vertical FOV, aspect, near/far; view and projection matrices are built on request, so `setVerticalFov` works (aim-down-sights zoom). It has no movement logic. Controllers in `gameplay/camera/` move it, each a concrete class with no shared interface (a real game uses one): `FreeFlyCameraController` (look + fly, Space/Ctrl up/down), `FirstPersonCameraController` (look + walk on the ground plane), `MobaCameraController` (fixed-angle offset; follows an optional target, otherwise edge-pans while the cursor is confined). Look controllers store yaw/pitch as `ViewAngles` (spherical coordinates, yaw 0 = -Z, positive yaw turns right, pitch clamped to 89 degrees) and pause while the mouse is not captured; `takeOver(camera)` continues from the camera's current direction.
- Control modes (`ControlMode`, demo only): F1 first-person, F2 MOBA, F3 free camera (debug switching, the `DemoGame` constructor's `debugModeSwitching`). MOBA mode uses a confined visible cursor, edge panning (`gameplay/edge_pan`, from the cursor in `Input`), Space to lock the camera on the player, and right-click (or hold) to move the player (`DemoGame::updatePlayerCommands`: a click uses its exact event position; holding steers towards the live cursor via `groundSteeringActive`).
- Characters: `spawnCharacter(world, assets, model, config, position)` creates an entity with `Transform`, `PreviousTransform`, `ModelRenderer` and `CharacterMovement` (a `MoveToController` plus turning state; `moveTo`/`stop`/`isMoving`). `updateCharacters` moves them and turns them towards their heading at `turnSpeed`; `getCharacterVisualCentre(world, entity, alpha)` gives the interpolated camera target. `math/ray` provides `Ray` and `intersectGround`; `scene/camera_ray` provides `makeCameraRay`. Together they turn mouse clicks into ground positions.
- Meshes: `Mesh` (`scene/`) is the import format: `Vec4` positions plus triangles with an optional normal and UV per corner. Loaders, bounds and the software renderer use it. `buildIndexedMesh` (`scene/indexed_mesh`) turns it into the render format, `IndexedMesh`: unique `MeshVertex` (position, normal, UV; the exact GPU vertex layout, read with `offsetof`) plus 32-bit indices. Each corner gets its file normal or its face normal and its UV or (0,0); corners identical in every component are merged (the key normalises -0.0 to +0.0). Files without normals stay flat shaded, so their corners rarely merge, unless loaded with `smoothNormals`: `generateSmoothNormals(mesh, creaseAngle)` (`scene/smooth_normals`) fills in missing corner normals by averaging the faces around each position (grouped by exact position, so seams with duplicated vertices smooth too), weighted by corner angle, counting only faces within the crease angle (default 60 degrees) of the corner's own face. It is opt-in because only the game knows whether a shape is meant to be faceted. `faceNormal` lives in `scene/mesh`. The engine builds the `IndexedMesh` once when a mesh is first uploaded; `GpuMesh` only validates and uploads it. `GpuTexture` uploads RGBA pixels with a full mip chain (`mipLevelCount`, `render/gpu/mip_levels`; the texture is also a colour target so `SDL_GenerateMipmapsForGPUTexture` can build the smaller levels) and samples them with trilinear and 16x anisotropic filtering (`max_lod` must be raised, its default 0 locks sampling to the full-size level). `Material::unlit` is TEMPORARY: it skips lighting in the shader (`specular.z`), used only by the demo's MOBA marker so it keeps its colour at night; delete it when the marker becomes a HUD element (ROADMAP phase 6).
- Loaders: `obj_loader` (quads/convex polygons, normals, UVs), `gltf_loader` (cgltf; returns a `Model` of `ModelPart`s with world transforms, base colour and base colour texture, external or embedded in `.glb`). glTF texture transforms are not supported.

Software renderer (reference path, used only by tests): `Renderer`, `Display`, `PixelBuffer`, `DepthBuffer`, `rasterizer`, `clipper`, `shading`. It does flat shading only and ignores per-vertex normals and UVs.

## Conventions

- **Math:** `Mat4` is row-major `values[row][column]` and multiplies column vectors (`M * v`). Right-handed coordinates, camera looks down -Z. `Mat4::perspective` produces OpenGL-style clip depth (-w..w). `GpuRenderer::setCamera` converts it to the GPU's 0..1 range with `toGpuDepthRange` (`render/gpu/gpu_depth_range`); nothing outside `render/` knows about GPU depth.
- **GPU uniforms:** matrices are transposed to column-major when pushed to the shader (see `GpuRenderer::drawMesh`). Each draw pushes three: the full transform, the model matrix, and the normal matrix. `normalMatrix(model)` (`math/mat4`) is the inverse transpose of the 3x3 part, computed once per object as the cofactor matrix times the sign of the determinant (only the sign matters, since normals are normalised; it keeps mirrored objects' normals outward), zero for a matrix that squashes space flat.
- **UVs:** bottom-left origin (OBJ convention). `loadImage` flips rows vertically by default to match. glTF uses a top-left origin, so glTF textures need `flipVertically = false`. The `AssetManager` caches textures by (path, flip setting) or by embedded image buffer.
- **Light:** lights are components (`scene/light.h`): `DirectionalLight` (stores the direction the light travels; no `Transform` needed), `PointLight` (position from the entity's `Transform`, fades to exactly zero at `range`), `SpotLight` (a point light in a cone: stores its `direction`, full brightness inside `innerAngle`, smoothly fading to zero at `outerAngle`, and a `sourceRadius` that softens the falloff up close, `intensity / (d² + r²)`; the shader compares cosines, which `packLighting` precomputes and clamps inner to outer) and `AmbientLight` (several add up). Colours are 0..1 tints with a separate unbounded `intensity`. Each frame `Application::render` calls `collectLighting(world, alpha)` (`scene/lighting`, point light positions interpolated like meshes) and `GpuRenderer::setLighting(lighting, cameraPosition)`, which uses `packLighting` (`render/gpu/light_uniforms`) to fill `LightUniformData` and pushes it once to fragment uniform slot 1. That struct mirrors the `LightData` block in `triangle.frag` byte for byte (all `vec4`, `static_assert` 944 bytes) and includes the camera position for specular highlights. Shading is Lambert diffuse plus Blinn-Phong specular per light: `albedo * (ambient + diffuse) + specular`, so highlights keep the light's colour; limits are 4 directional, 16 point and 4 spotlights (944 bytes), extra ones are dropped. `beginFrame` starts with no lights. The software renderer still hardcodes a light at `(-1, 2, 1)`. The demo's ambient 0.2 plus sun 0.8 reproduces the old hardcoded look; it is night (ambient 0.06, no sun); the player carries a torch (a `PointLight` entity copied to the player each tick, since there are no hierarchies yet), and F toggles a flashlight (a `SpotLight` entity, removed when off) that `DemoGame::updateFlashlight` places every frame in `onUpdate`: at the camera, or in MOBA mode held by the duck using its interpolated pose and `getCharacterFacing` (`gameplay/character`), tilted down 20 degrees.
- **Style:** descriptive names, a block comment above each function explaining why, braces on every branch, RAII for SDL resources, exceptions for errors (constructors clean up with `cleanup()` and rethrow). Match the existing style.
- **Branches:** one branch per feature, with descriptive commit messages.

## Tests

- Plain `assert`-based tests, one `testXxx()` function per file in `tests/`.
- **Register every new test** by adding a forward declaration and a call in `tests/test_main.cpp`. The makefile compiles the file automatically, but it will not run unless registered.
- Tests do not need a GPU or window.
- Do not compile with `-DNDEBUG`, because it turns every assert into a no-op.
- Known issue: the glTF tests use a fixed temp directory and throw if it exists. A failed assert leaves it behind and breaks the next run (delete `game_engine_gltf_*` in the system temp folder).

## Known small issues and ideas

- Add a `release` make target (`-O2`); move small vec/mat operators into headers so they can inline.
- Latency: `GpuRenderer` allows one frame in flight, and `Application` requests `PresentMode::Mailbox` (falls back to vsync if unsupported), so `targetFPS = 240` is the real frame cap. `PresentMode::Immediate` is lower latency still but tears.
- GPU device is created with debug mode hardcoded on.
