# GameEngine

A from-scratch C++20 game engine. Long-term goal: support both **FPS** and **MOBA** style games, and eventually a dressmaking game with real cloth physics (ROADMAP phases 7 and 10) and a real-scale solar system (phase 13), by keeping the core genre-agnostic and putting genre-specific code (camera controllers, weapons, abilities, netcode style, cloth, orbital mechanics) in separate modules on top.

The roadmap is in `ROADMAP.md`. Phases 0-5 (foundations, GPU rendering and assets, core loop and input, engine architecture, rendering upgrades, collision and movement) are done. Phase 6 (rendering foundations, lighting and global illumination) is current; it was re-planned on Oct 18, 2026: first groundwork that does not touch the graphics API (6a: engine hygiene, quaternions, reversed-Z, an ImGui debug UI, normal maps), then the engine's own Vulkan 1.3 renderer replacing SDL_GPU (6b), the GPU scene, compute and clustered lights (6c), DDGI traced with hardware ray queries (6d) and image quality (6e: TAA, reflections, transparency). Then phase 7 (cloth simulation) and phase 8 (Euphoria-style active ragdolls: plan and research in `docs/RAGDOLLPLAN.md`). Optional ideas wait in phase 14.

## Build and run

- `make` builds `build/game.exe` and compiles shaders (`glslc -Isrc` -> `.spv`). Shaders `#include` the macro-only headers they share with C++ (`render/gpu/shader_shared.h`: light array sizes and soft-shadow filter limits; `core/dither_shared.h`: the dither step; `render/gpu/tone_mapping_shared.h`: the tone mapping curves' numbers; `render/gpu/bloom_shared.h`: the bloom filters' weights, luminance and level limits; `render/gpu/brdf_shared.h`: physically based shading's reflectance, roughness and table limits; `render/gpu/depth_shared.h`: the reversed-Z near and far depths), and glslc's `-MD` dependency files in `build/obj/shaders/` rebuild a shader when one changes. Such headers hold only `#define`s of plain numbers behind an include guard, since GLSL reads them too; C++ uses typed constants built from them.
- `make run` builds and runs the game. Run it from the repo root: asset and shader paths are relative (`assets/...`).
- `make test` builds and runs `build/tests.exe`.
- The makefile finds `src/**/*.cpp` recursively (`rwildcard`) and `tests/*.cpp`, so new files are picked up automatically. Each source compiles to its own object in `build/obj/` (mirroring the source folders), and the game and tests link the same engine objects. Header dependencies come from GCC's `-MMD -MP` `.d` files, so a header change rebuilds exactly the files that include it; changing the makefile rebuilds everything. It builds in parallel on every core (`MAKEFLAGS += -j$(nproc) --output-sync=target`; override with `make JOBS=1`). A one-file change rebuilds in about 2 s (it was about 76 s when everything compiled in one `g++` call). Include roots are `-Isrc -Iexternal`.
- Two builds from the same sources, each in its own folder so switching never rebuilds the other: `make` is the debug build (`-std=c++20 -Wall -Wextra -g -O0`, `build/`), and `make release`, `make run-release`, `make test-release` build with `-O2` into `build/release/` (the makefile's `BUILD=debug|release` picks `OPTIMISATION` and `BUILD_DIR`; the release targets re-run make with `BUILD=release`). Both keep `-g`, never `-DNDEBUG` (tests rely on `assert`) and never `-ffast-math`. Run the tests in both: `-O2` exposes bugs and warnings `-O0` hides. `Vec2`, `Vec3`, `Vec4`, `Mat4 * Vec4`, `transformPoint` and `transformDirection` are defined in their headers so they inline (the vec `.cpp` files are gone); keep new tiny maths there too. Measured on 40 characters and 200 bouncing balls per tick: `-O2` alone made them 5-6 times faster, inlining the vector operators another 1.4 times (about 7-8 times in all); `-flto` added only 3-9% while a one-file rebuild took 20 s instead of 3 s, so it is not used. `tools/package_demo.py` ships the release exe.
- Dependencies: SDL3, SDL3_image, `glslc` (MSYS2 `shaderc` package here; the Vulkan SDK's also works), cgltf (vendored in `external/cgltf`) and Dear ImGui 1.92.9b with its SDL3 and SDL_GPU backends (vendored unmodified in `external/imgui`, compiled with the engine; `-Warray-bounds` off for those files only).
- Fresh Windows machine: `winget install MSYS2.MSYS2` (installs to `C:\msys64`), then in `C:\msys64\usr\bin\bash.exe -lc` run `pacman -Syu --noconfirm` twice (the first run updates the core and stops) and `pacman -S --needed --noconfirm make mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-sdl3 mingw-w64-ucrt-x86_64-sdl3-image mingw-w64-ucrt-x86_64-shaderc`. `tools/package_demo.py` needs a real Python (`winget install Python.Python.3.13`); the `python` in `WindowsApps` is only the Microsoft Store placeholder.
- MSYS2 is not on the permanent `PATH`. From PowerShell (the tool shell here), prefix each build command with `$env:PATH = "C:\msys64\ucrt64\bin;C:\msys64\usr\bin;" + $env:PATH;`, since shell state does not carry between commands. The game also needs `C:\msys64\ucrt64\bin` on the `PATH` for its DLLs (the packaged zip does not).
- `build/`, `*.exe` and `*.spv` are git-ignored.
- `python tools/package_demo.py` builds and packages `build/GameEngineDemo.zip` for a PC without MSYS2: stripped release exe (`make release`, `build/release/game.exe`), DLLs found by following import tables with MSYS2 `objdump`, plus the SDL3_image decoder DLLs for the image formats the assets use (they are loaded at runtime, so import tables do not show them), all of `assets/` except shader sources, and a README whose controls are generated from `README.md`'s `## Controls` section (`readme_controls`), so keep that section current and the zip follows. It fails if any imported DLL is neither packaged nor part of Windows. `--anonymous` (for sharing without a link to the public repo) makes `build/Demo.zip` instead: named Demo, controls shortened to their first phrase (`brief_action`) with no paragraphs, zip entries dated 1980-01-01 and the exe's PE timestamp zeroed (`clear_build_time`).
- Source files use CRLF line endings. Preserve them when editing.

## Source layout

Code lives in layered folders under `src/`. Dependencies point downward only: a folder may include from folders below it, never above.

- `ecs/` (`Entity`, `ComponentStorage`, `World`), `core/` (`fixed_timestep`, `profiler`, `pixel`, `srgb`, `dither`, `hash` (`Fnv1aHash`), `build_info` (`isDebugBuild`), `settings_visitor` (`SettingsVisitor`, `settingKey`)) and `math/` (vectors, `Mat4`, `Quat`, `Transform`, `Ray`, `Frustum`, `Aabb`, `closest_points`, `angles`: `fullTurnRadians`, `radiansFromDegrees`, `wrapAngle` to -pi..pi, used wherever angles wrap or convert): depend on nothing else.
- `physics/` (`shapes`: `Sphere`, `Capsule`, the `Shape` variant; `overlap`; `raycast`; `triangle_mesh`; `collider`: the `Collider` component; `collider_raycast`; `uniform_grid`; `collision_settings`; `collision_scene`; `query_stats`; `triangle_contact`; `static_level`; `character_controller`; `particle`): depends on `math/`, `ecs/` and `core/`. Collision and, later, particles and the character controller.
- `input/` (`Key`, `MouseButton`, `Input`): SDL-free, depends on `math/`.
- `scene/` (meshes, `indexed_mesh`, models, `MaterialSource`, `Material`, `asset_handles`, `ModelRenderer`, `interpolation`, `light`, `lighting`, `frame_description`, `debug_draw`, `debug_text`, `culling`, `Camera`, `camera_ray`, `collision_mesh`) and `assets/` (`AssetManager`, loaders, cgltf). `scene/` and `render/` never include `assets/`.
- `gameplay/` (`CharacterMovement` and `CharacterConfig` in `character`/`character_config`, `FirstPersonBody`, `Spinner`, `Firefly`, `Grenade`, `MoveToController`, `edge_pan`) and `gameplay/camera/` (`look_controls`, `FreeFlyCameraController`, `FirstPersonCameraController`, `MobaCameraController`).
- `platform/` (`Window`, `sdl_input`), `render/gpu/` (`GpuRenderer`, `GpuMesh`, `GpuTexture`, `DebugLineRenderer`, uniform packing (`light_uniforms`, `material_uniforms`, `uniform_limits`, `shader_shared.h`), `render_settings`, `light_priority`, `shadow_map`, `shadow_atlas` (persistent tile layout), `shadow_cache` (tile memory), `soft_shadow` (PCSS arithmetic mirrored for tests), `tone_mapping` (`ToneMappingSettings`, `toneMap` mirroring `tone_map.frag`, `validateToneMapping`), `tone_map_uniforms` (`packToneMapping`), `bloom` (`BloomSettings`, the CPU mirror of the bloom chain and `packBloomPass`), `bloom_renderer` (`BloomRenderer`), `brdf` (physically based shading: the CPU mirror of the shader's BRDF, `BrdfTable` and `buildBrdfTable`), `display_output` (HDR output: `DisplaySettings`, `DisplayCapabilities`, `chooseDisplayOutput`), `overlay_renderer` (the debug UI's own image, laid over everything last), `overlay_composite` (its blend, mirrored), `quality_preset` (Low, Medium, High), `mip_levels`, `gpu_depth_range` (reversed-Z), `camera_relative` (`cameraRelativeViewProjection`, `relativeTo`), `debug_line_vertices`, `gpu_helpers` for `gpuError`, `loadShader` and `writeColumnMajor`), `render/software/` (reference rasterizer), and `render/render_stats.h` (`RenderStats`, shared by both). `render/` takes a raw `SDL_Window*` and never includes `input/` or `platform/`.
- `engine/` (`Application`, the `Game` interface, `runFixedUpdate`, `debug_views`, `state_hash` (`hashSimulationState`, for determinism checks), `settings_file` (`settings.cfg`: capture, apply, format, parse), `debug_ui` (`DebugUi`, F5, Dear ImGui)): the loop and everything shared by all games. Never includes `games/`.
- `games/` (`demo/DemoGame`, `demo/ControlMode`): one folder per game, built on the `Game` interface. Games never include `platform/`, `render/` or SDL, so they can run headless.
- `app/` (`main`): picks a game and starts the engine; may include everything.

Write includes from the `src` root with the folder: `#include "math/vec3.h"`, `#include "cgltf/cgltf.h"`. Never use relative `../` includes.

## Architecture (summary)

The full reference, with every name, file and number, is `docs/ARCHITECTURE.md`, one section per system: read the section for a system before changing it, and update it in the same branch. The essentials:

- **Live path:** `main` creates a `DemoGame` and an `Application` (the engine), which owns the `Window`, `GpuRenderer`, `Input`, `World` and `AssetManager`, drives the game through the `Game` hooks (`engine/game.h`: `onInit`, then each frame `onInput` once, `onFixedUpdate` per tick through `runFixedUpdate`, `onUpdate` once, `onDebugDraw`), and draws the `World`. Declare the game before the engine so it outlives it.
- **Main loop:** `FixedTimestep` turns frame time into whole 120 Hz ticks plus an interpolation `alpha`. Never read `Input` inside a tick: key and click edges are handled once per frame and reach the simulation as commands. Mouse look and camera movement are per frame. Entities that move continuously have a `PreviousTransform` and are drawn interpolated (`getRenderTransform`); things that teleport have none. Spinners and fireflies compute their pose from the total simulation time.
- **Settings:** every value a game, the debug UI or a player may tune lives in one settings struct owned by its system, read every frame unless noted, defaults = the engine's values: `EngineSettings` (owned by `Application`), `RenderSettings` (lights, shadows, bloom, tone mapping, display; passed to `GpuRenderer::render` each frame), and each camera controller's settings. Fixed capacities (shader array sizes, atlas size, tile counts) are compile-time constants. Each settings struct has a `visit(settings, SettingsVisitor&)` next to it naming every field once (label, hard limits, slider range, unit, start-up only or not); that one list drives the debug UI (F5), the settings file (`settings.cfg`, only values changed from the defaults, loaded by `Application` before anything reads them) and the tests of the defaults, so a new field needs only a line in `visit()`. Games add theirs through `Game::visitSettings`.
- **Game to renderer:** the engine builds a `FrameDescription` (`scene/frame_description`: camera copy, `FrameLighting`, `DrawItem`s of {mesh, model matrix, material, castsShadows, bounds}, debug lines) and hands it to `GpuRenderer::render(frame, settings)`. It holds no GPU types and games never include `render/`, `platform/` or SDL, so games run headless and the renderer can change behind this seam.
- **Renderer today (SDL_GPU on Vulkan, to be replaced by the engine's own Vulkan 1.3 renderer in phase 6b):** a shadow pass into one cached D32 atlas, the main forward pass into an `R16G16B16A16_FLOAT` scene image, bloom, then tone mapping into the swapchain (SDR or scRGB HDR) with debug lines and then the debug UI (drawn into its own 8-bit overlay image, decoded and scaled to the white level) on top. Depth is reversed-Z and the main pass is camera-relative (see Math below). Lights are ranked by `prioritizeLights` (seats, shadow caps, hysteresis, fades) before `packLighting` and `planShadows`. Shading is physically based (glTF metallic-roughness, `render/gpu/brdf`). **Uniform blocks must stay at or under 4096 bytes** (`maxUniformBlockBytes`): SDL's Vulkan backend reads nothing past that, and every uniform struct has a `static_assert`.
- **Shader maths is mirrored on the CPU and tested** (`brdf`, `tone_mapping`, `bloom`, `soft_shadow`, `core/dither`); numbers both sides use live once in macro-only headers (`*_shared.h`).
- **Assets:** `MeshHandle` and `TextureHandle` are typed indices (default = none); the `AssetManager` loads each file once and is append-only, and `Application` uploads whatever it gained before each frame. Textures carry a `TextureEncoding` (sRGB colour or linear data).
- **ECS:** generational `Entity` handles, one sparse-set `ComponentStorage<T>` per type in `World`; systems are free functions run with `world.each<A, B>(...)` (list the rarest component first; inside `each`, `destroy` and `remove` are queued until the outermost walk ends, adding a component of a walked type throws, and `addLater` queues it).
- **Physics:** shapes (`Sphere`, `Capsule`, `Aabb`, the `Shape` variant) with exact overlaps and raycasts, `Collider` components and picking through a `UniformGrid` broad phase (`CollisionScene`, rebuilt rather than updated), the `StaticLevel` (world triangles in their own grid), sphere sweeps, particles and the kinematic character controller (Overwatch-like tuning, approved: ask before retuning).
- **Demo:** `DemoGame` (`games/demo/`) holds the camera, control modes (F1 first person, F2 MOBA, F3 free camera), the player, the scene and all demo input rules.

Software renderer (reference path, used only by tests): `Renderer`, `Display`, `PixelBuffer`, `DepthBuffer`, `rasterizer`, `clipper`, `shading`. It does flat shading only and ignores per-vertex normals and UVs.

## Conventions

- **Math:** `Mat4` is row-major `values[row][column]` and multiplies column vectors (`M * v`). Right-handed coordinates, camera looks down -Z. Rotations are unit quaternions (`math/quat`, stored x y z w as glTF; `a * b` turns by b first, like matrices); Euler angles only describe poses (`Quat::fromEulerAngles`, x first, then y, then z), and anything that turns or blends stays a `Quat`. Characters and cameras keep their yaw (and pitch) as angles of their own and build the rotation from them. `Mat4::perspective` produces OpenGL-style clip depth (-w..w). `GpuRenderer::render` converts it to the GPU's range with `toGpuDepthRange` (`render/gpu/gpu_depth_range`), reversed-Z: near at 1, far at 0, so depth tests are `GREATER`, depth clears and resets go to `gpuFarDepth` and shadow comparisons are flipped too; nothing outside `render/` knows about GPU depth. The main pass is camera-relative: everything its shaders see (model matrices, fragment and light positions, shadow lookup matrices) is measured from the camera, while culling and the shadow pass (whose cache keys on world matrices) stay in world space.
- **GPU uniforms:** matrices are transposed to column-major when pushed to the shader (see `GpuRenderer::drawMesh`). Each draw pushes three: the full transform, the model matrix, and the normal matrix. `normalMatrix(model)` (`math/mat4`) is the inverse transpose of the 3x3 part, computed once per object as the cofactor matrix times the sign of the determinant (only the sign matters, since normals are normalised; it keeps mirrored objects' normals outward), zero for a matrix that squashes space flat.
- **UVs:** bottom-left origin (OBJ convention). `loadImage` flips rows vertically by default to match. glTF uses a top-left origin, so glTF textures need `flipVertically = false`. The `AssetManager` caches textures by (path, flip setting) or by embedded image buffer.
- **Light:** light colours, intensities and `emissive` are linear; `Material::colour` bytes are sRGB like image files (decoded by `packMaterial`). Shading happens in linear light into an HDR float image, which tone mapping turns into the screen image. The light components, falloff, shadows, HDR output, bloom and the physically based model and its units are described in `docs/ARCHITECTURE.md`.
- **Style:** descriptive names, a block comment above each function explaining why, braces on every branch, RAII for SDL resources, exceptions for errors (constructors clean up with `cleanup()` and rethrow). Match the existing style.
- **No duplication:** before writing a function, search for one that already does it and reuse or generalise it; when two places grow the same logic, merge them into one shared function rather than keeping near-copies. Tuning values a game, the debug UI or a player might change (speeds, light and shadow limits, fade times, physics constants) live in one obvious place, a named constant or a settings struct next to the system that uses it, never repeated as literals, so each value is edited in exactly one spot. The exception is performance: when removing duplication or centralising a value would cost speed (a hot loop that would read a runtime setting the compiler could otherwise fold, shader sizes that must stay compile-time, an abstraction that blocks inlining), keep the faster form and note why in a comment.
- **Branches:** one branch per feature, with descriptive commit messages. Merge into `main` with `--no-ff` (the merge commit keeps the branch name, and `<merge>^2` can recreate the branch), push, then delete the feature branch locally and on GitHub.

## Tests

- Plain `assert`-based tests, one `testXxx()` function per file in `tests/`. Small levels and comparisons shared by the physics tests (`near`, `block`, `flatLevel`, `addRamp`) live in `tests/test_levels.h`; driving the demo game headless (`tickSeconds`, `mobaInput`, `firstPersonInput`, `runTicks`, `runFrame`) lives in `tests/demo_helpers.h`; add to it rather than copying helpers between test files.
- **Register every new test** by adding a forward declaration and a call in `tests/test_main.cpp`. The makefile compiles the file automatically, but it will not run unless registered.
- Tests do not need a GPU or window.
- Do not compile with `-DNDEBUG`, because it turns every assert into a no-op.
- Known issue: the glTF tests use a fixed temp directory and throw if it exists. A failed assert leaves it behind and breaks the next run (delete `game_engine_gltf_*` in the system temp folder).

## Known small issues and ideas

- Latency: `GpuRenderer` allows one frame in flight, and `Application` requests `PresentMode::Mailbox` (falls back to vsync if unsupported), so `EngineSettings::targetFPS` (240) is the real frame cap. `PresentMode::Immediate` is lower latency still but tears.
