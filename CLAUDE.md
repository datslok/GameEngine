# GameEngine

A from-scratch C++20 game engine. Long-term goal: support both **FPS** and **MOBA** style games, and eventually a dressmaking game with real cloth physics (ROADMAP phases 7 and 10) and a real-scale solar system (phase 13), by keeping the core genre-agnostic and putting genre-specific code (camera controllers, weapons, abilities, netcode style, cloth, orbital mechanics) in separate modules on top.

The roadmap is in `ROADMAP.md`. Phases 0-5 (foundations, GPU rendering and assets, core loop and input, engine architecture, rendering upgrades, collision and movement) are done. Phase 6 (rendering foundations, lighting and global illumination) is current; it was re-planned on Oct 18, 2026: first groundwork that does not touch the graphics API (6a, done: engine hygiene, quaternions, reversed-Z, an ImGui debug UI, normal maps), then the engine's own Vulkan 1.3 renderer replacing SDL_GPU (6b, done: the port, GPU timestamps, frames in flight and the GPU test tier), the GPU scene, compute and clustered lights (6c: GPU scene, depth prepass, clustered shading and cascaded sun shadows fitted to the screen's depths (sample distribution shadow maps) done), DDGI traced with hardware ray queries (6d: ray queries and acceleration structures done, with a debug view; the probe grid, its rays (sunlight by shadow rays) and update, with a debug view of balls, done; sampling the probes in `triangle.frag` (Chebyshev visibility against leaks), with the brightest lamps and infinite bounces at probe hits, done; fast lights without trails (a second irradiance atlas with a short memory) done; scene events (the game's `ProbeEvent`s restart the probes in a region) done; probe relocation and states (probes move off the static level, only those a surface reads are traced) done; the sky and atmosphere (Hillaire 2020) done; cascades for large worlds (nested grids following the camera, no probes placed per level) done; the software tracer, a global distance field, moved to phase 14 on Oct 23 2026) and image quality (6e: TAA, the upscalers (TAAU, FSR, DLSS) and normal map filtering and reflections (screen-space, then a probe round the camera) done; AO, transparency next). Then phase 7 (cloth simulation) and phase 8 (Euphoria-style active ragdolls: plan and research in `docs/RAGDOLLPLAN.md`). Optional ideas wait in phase 14.

## Build and run

- `make` builds `build/game.exe` and compiles shaders (`glslc --target-env=vulkan1.3 -Isrc` -> `.spv`; `.vert`, `.frag` and `.comp` in `assets/shaders/`). Shaders `#include` the macro-only headers they share with C++ (`render/gpu/shader_shared.h`: soft-shadow filter limits and the sun bias's slope cap; `core/dither_shared.h`: the dither step; `render/gpu/tone_mapping_shared.h`: the tone mapping curves' numbers and night vision's; `render/gpu/eye_adaptation_shared.h`: the brightness histogram's bins, range, shares and group size; `render/gpu/bloom_shared.h`: the bloom filters' weights, luminance and level limits; `render/gpu/brdf_shared.h`: physically based shading's reflectance, roughness and table limits; `render/gpu/normal_mapping_shared.h`: the 8-bit rounding slack normal map filtering ignores; `render/gpu/depth_shared.h`: the reversed-Z near and far depths; `render/gpu/taa_shared.h`: temporal anti-aliasing's jitter cycle, no-motion value, group size and motion view scale; `render/gpu/screen_reflections_shared.h`: screen-space reflections' group size, pyramid limit, cell crossing, nearest w, start offset, cone spread and fades; `render/gpu/reflection_probe_shared.h`: the reflection probe's near plane, search steps and match shares, prefilter samples, smallest level, sun ray offsets, group size and the vertex shader's capture constant; `render/gpu/clusters_shared.h`: clustered shading's tile size, slices, words per cluster, bounds margin, group size and heatmap scale; `render/gpu/depth_range_shared.h`: the depth measurement's group size and empty range; `render/gpu/ray_tracing_shared.h`: the ray masks, a mesh vertex's float layout and the ray debug views; `render/gpu/atmosphere_shared.h`: the sky's table sizes, steps, sample offset, ambient directions and least altitude; `render/gpu/ddgi_shared.h`: the light probes' texel counts, ray limits, ray cycle, update weights, thresholds, atlas limit, sampling weights, the volume's edge, the cascades' limit, fade and edge, the seeds' frames and room, the most lights a hit keeps, the main pass's probe specialization constant, the adaptive memory's change floor and history cap, sharing's visibility share and neighbour count, and relocation's rays, steps and limits and the probe states), and glslc's `-MD` dependency files in `build/obj/shaders/` rebuild a shader when one changes. Such headers hold only `#define`s of plain numbers behind an include guard, since GLSL reads them too; C++ uses typed constants built from them.
- `make run` builds and runs the game. Run it from the repo root: asset and shader paths are relative (`assets/...`).
- `make test` builds and runs `build/tests.exe`.
- `make golden` renders every game's golden views and compares them with `tests/golden/<GPU>/<game>/` (captures and difference heatmaps in `build/golden/<GPU>/<game>/`); `make golden-save` makes the captures the references (`make golden-save GAME=<name>` for one game, e.g. a new one; `GAME=` also picks the game for `make run` and `make run-release`). Needs a GPU, so it is not part of `make test`. Run it, or save new references, only when the user asks (golden runs take long; the user checks the picture by hand). The same GPU, driver and shaders reproduce the references bit for bit, so any difference is a real change. When saving new references for a change meant to alter the picture, say so in the commit. The references were made on SDL_GPU, and the Vulkan renderer matched them bit for bit before SDL_GPU was removed.
- `make gputest` (`make gputest-release`) builds `build/gputests.exe` from `tests/gpu/*.cpp`, compiles `tests/gpu/shaders/*.comp`, runs every shader library's functions in compute shaders on fixed inputs against their C++ mirrors (a report of each group's worst share of its tolerance; any validation error fails it), then the golden images. Needs a GPU. Run it only when the user asks, even after changing a shader library or its mirror; a new library function gets a case in its `tests/gpu/<library>_gpu_test.cpp`, a number in `tests/gpu/gpu_test_functions.h` and a branch in its test shader.
- The makefile finds `src/**/*.cpp` recursively (`rwildcard`) `tests/*.cpp` and `tests/gpu/*.cpp` (the GPU tests' own program), so new files are picked up automatically. Each source compiles to its own object in `build/obj/` (mirroring the source folders), and the game and tests link the same engine objects. Header dependencies come from GCC's `-MMD -MP` `.d` files, so a header change rebuilds exactly the files that include it; changing the makefile rebuilds everything. It builds in parallel on every core (`MAKEFLAGS += -j$(nproc) --output-sync=target`; override with `make JOBS=1`). A one-file change rebuilds in about 2 s (it was about 76 s when everything compiled in one `g++` call). Include roots are `-Isrc -Iexternal`.
- Two builds from the same sources, each in its own folder so switching never rebuilds the other: `make` is the debug build (`-std=c++20 -Wall -Wextra -g -O0`, `build/`), and `make release`, `make run-release`, `make test-release` build with `-O2` into `build/release/` (the makefile's `BUILD=debug|release` picks `OPTIMISATION` and `BUILD_DIR`; the release targets re-run make with `BUILD=release`). Both keep `-g`, never `-DNDEBUG` (tests rely on `assert`) and never `-ffast-math`. Run the tests in both: `-O2` exposes bugs and warnings `-O0` hides. `Vec2`, `Vec3`, `Vec4`, `Mat4 * Vec4`, `transformPoint` and `transformDirection` are defined in their headers so they inline (the vec `.cpp` files are gone); keep new tiny maths there too. Measured on 40 characters and 200 bouncing balls per tick: `-O2` alone made them 5-6 times faster, inlining the vector operators another 1.4 times (about 7-8 times in all); `-flto` added only 3-9% while a one-file rebuild took 20 s instead of 3 s, so it is not used. `tools/package_demo.py` ships the release exe.
- Dependencies: SDL3, SDL3_image, `glslc` (MSYS2 `shaderc` package here; the Vulkan SDK's also works), cgltf (vendored in `external/cgltf`), MikkTSpace (vendored unmodified in `external/mikktspace`, the makefile's one C file: `gcc -std=c99`) Dear ImGui 1.92.9b with its SDL3 and Vulkan backends (vendored unmodified in `external/imgui`, compiled with the engine; `-Warray-bounds` off for those files only), and for the renderer volk (C), vk-bootstrap and the Vulkan Memory Allocator (vendored unmodified in `external/volk`, `external/vk-bootstrap`, `external/vma`, versions in each `VERSION.txt`, matched to MSYS2's Vulkan headers) plus MSYS2's `vulkan-headers` and `vulkan-validation-layers`, and AMD's FidelityFX API headers with its signed `amd_fidelityfx_vk.dll` (FSR 3.1, SDK v1.1.4, the last with Vulkan; `external/fidelityfx`, committed, the one `*.dll` `.gitignore` lets through), loaded at run time with `SDL_LoadObject` (a C interface, so MSVC's DLL works from GCC) and copied beside each build's exe by the makefile; without it FSR is unavailable. The validation callback skips one warning, `rw_luma_history`: a bug in AMD's DLL. NVIDIA Streamline (DLSS): its MIT headers committed in `external/streamline/include`, its signed DLLs (DLSS itself under the NVIDIA RTX SDK licence) fetched by `python tools/fetch_streamline.py` into git-ignored `external/streamline/bin` and copied beside the exe by the makefile; loaded at run time after a signature check (`-lwintrust -lcrypt32`), started before the device (`StreamlineLibrary`, whose extensions `VulkanDevice` turns on); without the DLLs DLSS is unavailable. Every Vulkan call goes through volk (`-DVK_NO_PROTOTYPES`), so nothing links against the loader. The validation layers sit in `C:\msys64\ucrt64\bin`, where the Vulkan loader does not look, so the makefile exports `VK_ADD_LAYER_PATH` for what it runs; set it yourself to get them when starting `game.exe` another way.
- Fresh Windows machine: `winget install MSYS2.MSYS2` (installs to `C:\msys64`), then in `C:\msys64\usr\bin\bash.exe -lc` run `pacman -Syu --noconfirm` twice (the first run updates the core and stops) and `pacman -S --needed --noconfirm make mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-sdl3 mingw-w64-ucrt-x86_64-sdl3-image mingw-w64-ucrt-x86_64-shaderc mingw-w64-ucrt-x86_64-vulkan-headers mingw-w64-ucrt-x86_64-vulkan-validation-layers`. `tools/package_demo.py` needs a real Python (`winget install Python.Python.3.13`); the `python` in `WindowsApps` is only the Microsoft Store placeholder.
- MSYS2 is not on the permanent `PATH`. From PowerShell (the tool shell here), prefix each build command with `$env:PATH = "C:\msys64\ucrt64\bin;C:\msys64\usr\bin;" + $env:PATH;`, since shell state does not carry between commands. The game also needs `C:\msys64\ucrt64\bin` on the `PATH` for its DLLs (the packaged zip does not).
- `build/`, `*.exe` and `*.spv` are git-ignored.
- `python tools/package_demo.py` builds and packages `build/GameEngineDemo.zip` for a PC without MSYS2: stripped release exe (`make release`, `build/release/game.exe`), DLLs found by following import tables with MSYS2 `objdump`, plus the SDL3_image decoder DLLs for the image formats the assets use (they are loaded at runtime, so import tables do not show them), all of `assets/` except shader sources, and a README whose controls are generated from `README.md`'s `## Controls` section (`readme_controls`), so keep that section current and the zip follows. It fails if any imported DLL is neither packaged nor part of Windows. `--anonymous` (for sharing without a link to the public repo) makes `build/Demo.zip` instead: named Demo, controls shortened to their first phrase (`brief_action`) with no paragraphs, zip entries dated 1980-01-01 and the exe's PE timestamp zeroed (`clear_build_time`).
- Source files use CRLF line endings. Preserve them when editing.

## Architecture (summary)

The full reference, with every name, file and number, is `docs/ARCHITECTURE.md`, one section per system: read the section for a system before changing it, and update it in the same branch. The essentials:

- **Live path:** `main` makes the game named with `--game` (`app/game_registry`; the light lab by default) and an `Application` (the engine), which owns the `Window`, `VulkanRenderer`, `Input`, `World` and `AssetManager`, drives the game through the `Game` hooks (`engine/game.h`: `onInit`, then each frame `onInput` once, `onFixedUpdate` per tick through `runFixedUpdate`, `onUpdate` once, `onDebugDraw`), and draws the `World`. Declare the game before the engine so it outlives it.
- **Main loop:** `FixedTimestep` turns frame time into whole 120 Hz ticks plus an interpolation `alpha`. Never read `Input` inside a tick: key and click edges are handled once per frame and reach the simulation as commands. Mouse look and camera movement are per frame. Entities that move continuously have a `PreviousTransform` and are drawn interpolated (`getRenderTransform`); things that teleport have none. Spinners and fireflies compute their pose from the total simulation time.
- **Settings:** every value a game, the debug UI or a player may tune lives in one settings struct owned by its system, read every frame unless noted, defaults = the engine's values: `EngineSettings` (owned by `Application`), `RenderSettings` (lights, shadows, bloom, tone mapping, display; passed to `VulkanRenderer::render` each frame), and each camera controller's settings. Fixed capacities (shader array sizes, atlas size, tile counts) are compile-time constants. Each settings struct has a `visit(settings, SettingsVisitor&)` next to it naming every field once (label, hard limits, slider range, unit, start-up only or not); that one list drives the debug UI (F5), the settings file (`settings.cfg`, only values changed from the defaults, loaded by `Application` before anything reads them; each game's under its own section, named by `Game::title()`, and other games' sections kept when one saves) and the tests of the defaults, so a new field needs only a line in `visit()`. Games add theirs through `Game::visitSettings`.
- **Game to renderer:** the engine builds a `FrameDescription` (`scene/frame_description`: camera copy, `FrameLighting`, `DrawItem`s of {mesh, model matrix, material, castsShadows, bounds}, debug lines) and hands it to `VulkanRenderer::render(frame, settings)`. It holds no GPU types and games never include `render/`, `platform/` or SDL, so games run headless and the renderer can change behind this seam.
- **Renderer today (the engine's own Vulkan 1.3 `VulkanRenderer`, which replaced SDL_GPU in phase 6b drawing every golden image bit for bit the same, and still keeps SDL_GPU's fixed-function choices, and its descriptor layout for every pass but the scene's):** a compute pass listing, as one bit per light, the lights that may reach each cluster of the view (`cluster_lights.comp`: 64-pixel tiles by 24 exponential depth slices), a shadow pass into one cached D32 atlas (the sun in four cascades of 4096 by default, which grows the atlas to 384 MB; Medium uses 2048 in 128 MB; the default is the Ultra quality preset (1024 probe rays; High traces 256)), a depth prepass (the main pass's own vertex shader with no fragment shader; `gl_Position` is `invariant`, so keep both passes on `triangle.vert`), the main forward pass into an `R16G16B16A16_SFLOAT` scene image with an `EQUAL` depth test (each pixel shaded once), a compute pass measuring the farthest surface on screen (`depth_range.comp`; the sun's cascades end there, a frame or two later, on a ladder of fixed steps: sample distribution shadow maps), temporal anti-aliasing (on by default: the main pass jittered on a 16-frame Halton cycle, a velocity pass redrawing only the objects that moved (set 1 binding 21, last frame's model matrices) over the main pass's depth, and `taa.comp` blending each pixel into its reprojected history (from the velocity image, or from depth and last frame's camera), clipped into its neighbours' colour box; it also upscales: `RenderSettings::upscaling.renderScale` (1 by default) draws the scene, depth and velocity smaller, each output pixel rebuilding the frame from its nearest jittered render pixels into the output-sized history, which is the finished picture eye adaptation, bloom, tone mapping and captures read, with a mip bias to match; or AMD's FSR 3.1 or NVIDIA's DLSS (through Streamline; the default, at full size: DLAA) upscales instead (`upscaling.upscaler`, the one anti-aliasing choice: Off, TAA, FSR or DLSS, after a camera motion pass gives every velocity pixel a motion), falling back to TAA where their DLLs are missing; captures settle it over 32 frames first), reflections just before it (on by default with any anti-aliasing: the main pass (`triangle_surfaces.frag`) also writes each pixel's normal, specular albedo and roughness and its probe stand-in for the reflection into three small targets, with the sky and stars then in a pass of their own; a reflection probe is captured at the camera every frame, six cube faces drawn with the main pass's shading (`probe_capture.frag`, or `probe_capture_rays.frag` tracing the sun's shadow past its cascades), then their distances and GGX-prefiltered levels; `reflections.comp` swaps each glossy pixel's stand-in first for the probe's light, found by a parallax search through its distances, then for last frame's finished picture where its mirror ray, marched through a depth pyramid (Hi-Z), hits, read from a colour pyramid as blurred as the roughness, each faded by a confidence), eye adaptation (a histogram of the scene's brightness and the exposure easing towards it, on the GPU, read by tone mapping the same frame, which can also fade dim light towards the rods' blue-grey while the eye is set for the dark: night vision, off by default), bloom, then tone mapping into the swapchain (SDR or scRGB HDR) with debug lines and then the debug UI (drawn into its own 8-bit overlay image, decoded and scaled to the white level) on top. Depth is reversed-Z and the main pass is camera-relative (see Math below). Ray tracing is optional (GPUs with ray queries): `VulkanRayTracing` keeps a compacted bottom-level acceleration structure per mesh and rebuilds a top-level one from every draw each frame while something traces rays (for now the F5 ray debug view); shadow casters are solid (`RAY_MASK_SOLID`), the rest visual-only, so light-gathering rays skip the glowing stand-ins for lights. The light probes (`VulkanDdgi`) live in cascades round what the frame's `ProbeCascades` follows (the camera; `render/gpu/probe_cascades`: six by default, from 0.5 m to 16 m apart, the densest 31 x 17 x 31 probes (lighting 6.1 m round the camera at full weight, 2.6 m up and down) and the coarser five 21 x 13 x 21 (the sixth reaching 116 m; beyond, the flat sky ambient), each twice as far apart as the last, the quality presets fewer; each a window on a lattice fixed in the world, kept as a circular buffer (`ProbeScroll`), so a move brings in one plane of new probes, which wait off for their relocation and then start seeded from the coarser cascades' light (`ddgi_seed.comp`, `seedProbes`); blended densest first, each weighted round the camera, ending far enough inside its window that no point reads a new plane; one set of atlases holds every cascade's probes one after another, wrapped into a near-square sheet (`probeAtlasGrid`), and a per-frame buffer of cascade records, set 1 binding 20, says where each is and its size; a probe's cascade is found by walking them, `probeCascadeHolding`). They trace 1024 rays a probe each frame by default (the Ultra preset; High 256) (16 to 1024; rays kept only for the frame's list of traced probes, at most 8,192, taking turns past it, and the update streaming them through shared memory 256 at a time) (a ray budget of 60 updates a second halves or quarters them above that frame rate; `ddgi_trace.comp`: misses bring back the sky, back faces nothing, front faces their glow and the sun through a shadow ray, not the shadow atlas, which only covers the view), then blend them (linearly) into an irradiance atlas (RGBA16F) and a distance atlas (RG16F) in place, as storage images (`ddgi_update_*.comp`, one workgroup per probe), with hysteresis from time constants in seconds. Hits also add the brightest few point and spot lights near the volume (each by a shadow ray) and last frame's probes (one more bounce a frame). The main pass samples them (`scene_probes.glsl`: 8 corner probes weighted by nearness, side and Chebyshev visibility, for diffuse, and in the mirror direction for specular until reflections) only in its probe pipelines (a specialization constant, so frames without probes draw exactly as before); golden views with probes are drawn 960 frames before their capture. With an `Atmosphere` in the frame, its sky (`VulkanAtmosphere`: transmittance and multiple scattering tables when the air changes, a sky view table and the flat ambient every frame) is drawn over the background, probe rays that escape bring it back, every directional light is dimmed by the air on its way down, and the flat ambient (set 1 binding 17, `flatAmbient()`) gains the sky's. Probes move off the static level (`ddgi_relocate.comp` against the draws a game marks `isStatic`, each frame in flight's records read when it comes round again, so moving never waits for the GPU; a buried one is off), and only those a surface reads are traced and read: vigilant (a static surface within their cells) and awake (something that moves nearby), the rest asleep (`probeRelocation`, `probeStates`). Probe rays take turns through one long Fibonacci spiral, 16 frames a cycle (`DDGI_RAY_CYCLE`, `probeRayFrame`; probes near fast lights too, since shorter cycles fitted to their short memory measured worse; the ray budget, `probeUpdatesPerSecond`, 60 by default, divides the still rays above that frame rate, since noise goes with rays a second; the adaptive memory, `adaptiveMemory`, on by default with an 8 sd threshold, lets each irradiance texel keep a long memory while its light only wobbles within its own measured noise and restart its average when the light really changes, its history in the atlas's alpha and the change window's mean and noise in a change statistics image; scene events (`ProbeEvent`, `sceneEvents` on by default): each texel in an event's region checks for 0.5 s whether its light really changed (the mean since the event against its stored light, past 4 of its own noise units, `eventChangeThreshold`) and only then restarts, its memory growing as half the time since its restart (`eventMemoryGrowth`) so the old light is soon forgotten; unchanged light keeps its memory, so dim areas do not flicker; probes in the region share more meanwhile (`eventProbeSharing`, 0.5, fading back to the preset's); the fixed memory and distances restart outright, softly (`eventMemorySeconds`), and the fast atlas outright, with the flashlight's switch an event; and sharing, `probeSharing`, off by default (the presets: Low 0.5, Medium 0.3, High 0.1, Ultra 0; the fast atlas on its own `fastProbeSharing`, 0.5 on every preset): each probe turns its rays its own way (`probeRayTurn`, a per-probe buffer of identity rows when off) and `ddgi_share.comp` writes shared copies of both irradiance atlases, each probe's light averaged with its visible face neighbours', which everything reads while sharing is on), and the irradiance time constant is 2 s: chosen by eye against flicker in the light lab's dark back room. Fast lights (`PointLight::fast`, `SpotLight::fast`: the flashlight) keep their bounce in a second irradiance atlas with a 0.1 s time constant (first 0.05 s), summed where the probes are read, so a swung flashlight's bounce does not trail; probes within reach of one trace `fastRaysPerProbe` (256 by default, 1024 on Ultra; `scheduleProbeFrame`; frames without fast lights draw exactly as before). Lights are ranked by `prioritizeLights` (seats, shadow caps, hysteresis, fades) before `packLighting` and `planShadows`; every light the buffers hold (1024 point, 256 spot) is seated by default, since with clustered shading each pixel walks only its cluster's bits, lowest first, which is slot order, so it adds the same lights in the same order as a loop over all of them (the golden images are identical with `RenderSettings::clusteredShading` on and off). The scene is a GPU scene: one world-space instance per object, materials, lights (with their shadows) and shadow tiles in storage buffers written once per frame, every texture in one bindless array (set 0), the frame's scene in set 1, and one instanced draw per mesh per view through a draw list of instance numbers (`docs/ARCHITECTURE.md`, GPU scene); nothing is bound per object. Shading is physically based (glTF metallic-roughness, `render/gpu/brdf`), with normal maps (`MeshVertex::tangent`, MikkTSpace or the file's). **Uniform blocks must stay at or under 4096 bytes** (`maxUniformBlockBytes`): `FrameUniforms` (the other passes' blocks) binds each block with a 4 KB range, so a shader reading past it reads garbage with no error, and every uniform struct has a `static_assert`; anything bigger or per object belongs in a storage buffer, std430, its C++ mirror's size checked too.
- **Shader maths is mirrored on the CPU and tested** (`brdf`, `normal_mapping`, `tone_mapping`, `bloom`, `soft_shadow`, `light_falloff`, `overlay_composite`, `clusters`, `cascades`, `depth_range`, `ray_tracing`, `ddgi`, `ddgi_sampling`, `taa`, `screen_reflections`, `reflection_probe`, `core/dither`); numbers both sides use live once in macro-only headers (`*_shared.h`). The GLSL side lives in libraries of pure functions in `assets/shaders/*.glsl` (`brdf`, `normal_mapping`, `lighting`, `soft_shadow`, `tone_mapping`, `bloom`, `dither`, `overlay`, `clusters`, `cascades`, `depth_range`, `ray_tracing`, `ddgi`, `ddgi_sampling`, `taa`, `screen_reflections`, `reflection_probe`; no texture reads, `gl_FragCoord` or derivatives inside, so compute shaders can run them), included by the passes and by the GPU tests, which check each against its mirror (`make gputest`). Shader maths goes into a library, not into a pass's `main`.
- **Assets:** `MeshHandle` and `TextureHandle` are typed indices (default = none); the `AssetManager` loads each file once and is append-only, and `Application` uploads whatever it gained before each frame. Textures carry a `TextureEncoding` (sRGB colour or linear data).
- **ECS:** generational `Entity` handles, one sparse-set `ComponentStorage<T>` per type in `World`; systems are free functions run with `world.each<A, B>(...)` (list the rarest component first; inside `each`, `destroy` and `remove` are queued until the outermost walk ends, adding a component of a walked type throws, and `addLater` queues it).
- **Physics:** shapes (`Sphere`, `Capsule`, `Aabb`, the `Shape` variant) with exact overlaps and raycasts, `Collider` components and picking through a `UniformGrid` broad phase (`CollisionScene`, rebuilt rather than updated), the `StaticLevel` (world triangles in their own grid), sphere sweeps, particles and the kinematic character controller (Overwatch-like tuning, approved: ask before retuning).
- **Games:** `DemoGame` (`games/demo/`) holds its `PlayerControls` (camera and control modes: F1 first person, F2 MOBA, F3 free camera), the player, the scene and all demo input rules; it has light probe cascades too (its ground and obstacle course static, its flying lamps `fast`, each lamp field and floodlight switch a scene event). `LightLabGame` (`games/lightlab/`, `--game lightlab`) is a sunlit test ground for shadows and GI: towers at doubling distances, a thin fence to the horizon, a forest and a two-room building with one window, a sun placed by astronomy with a clock and a real sky (an `Atmosphere`; at night the moon (a `DirectionalLight` with `reflectsSun`) and the real stars (a `StarrySky`), their brightness artistic dials; its hand-made day without), light probe cascades following the camera (`ProbeCascades`; its ground and blocks marked static, `ModelRenderer::isStatic`, so the probes move off them), a flashlight (F, off at the start), a ceiling lamp in the back room (L, off at the start; each switch, the flashlight's too, sends a scene event), a 300 m street south of the start with 60 shadowed lamps and lit windows (static glowing panes lighting it through the probes alone), on at dusk or flipped with K, one scene event per switch, and the same controls; build and judge cascaded shadows and DDGI there.

Software renderer (reference path, used only by tests): `Renderer`, `Display`, `PixelBuffer`, `DepthBuffer`, `rasterizer`, `clipper`, `shading`. It does flat shading only and ignores per-vertex normals and UVs.

## Conventions

- **Math:** `Mat4` is row-major `values[row][column]` and multiplies column vectors (`M * v`). Right-handed coordinates, camera looks down -Z. Rotations are unit quaternions (`math/quat`, stored x y z w as glTF; `a * b` turns by b first, like matrices); Euler angles only describe poses (`Quat::fromEulerAngles`, x first, then y, then z), and anything that turns or blends stays a `Quat`. Characters and cameras keep their yaw (and pitch) as angles of their own and build the rotation from them. `Mat4::perspective` produces OpenGL-style clip depth (-w..w). `VulkanRenderer::render` converts it to the GPU's range with `toGpuDepthRange` (`render/gpu/gpu_depth_range`), reversed-Z: near at 1, far at 0, so depth tests are `GREATER`, depth clears and resets go to `gpuFarDepth` and shadow comparisons are flipped too; nothing outside `render/` knows about GPU depth. The main pass is camera-relative: everything its shaders see (model matrices, fragment and light positions, shadow lookup matrices) is measured from the camera, while culling and the shadow pass (whose cache keys on world matrices) stay in world space.
- **GPU matrices:** matrices are transposed to column-major for shaders (`writeColumnMajor`). Each object's instance holds its world model matrix and its normal matrix; the vertex shader subtracts the camera from the model's translation (exactly `relativeTo`) and multiplies by the camera-relative view-projection, and the shadow pass multiplies by each tile's world view. `normalMatrix(model)` (`math/mat4`) is the inverse transpose of the 3x3 part, computed once per object as the cofactor matrix times the sign of the determinant (only the sign matters, since normals are normalised; it keeps mirrored objects' normals outward), zero for a matrix that squashes space flat.
- **UVs:** bottom-left origin (OBJ convention); `Mesh::uvOrigin` says which a mesh uses (glTF: `TopLeft`), and tangents are generated with v counted up the picture either way. `loadImage` flips rows vertically by default to match. glTF uses a top-left origin, so glTF textures need `flipVertically = false`. The `AssetManager` caches textures by (path, flip setting) or by embedded image buffer.
- **Light:** light colours, intensities and `emissive` are linear; `Material::colour` bytes are sRGB like image files (decoded by `packMaterial`). Shading happens in linear light into an HDR float image, which tone mapping turns into the screen image. The light components, falloff, shadows, HDR output, bloom and the physically based model and its units are described in `docs/ARCHITECTURE.md`.
- **Style:** descriptive names, a block comment above each function explaining why, braces on every branch, RAII for SDL resources, exceptions for errors (constructors clean up with `cleanup()` and rethrow). Match the existing style.
- **No duplication:** before writing a function, search for one that already does it and reuse or generalise it; when two places grow the same logic, merge them into one shared function rather than keeping near-copies. Tuning values a game, the debug UI or a player might change (speeds, light and shadow limits, fade times, physics constants) live in one obvious place, a named constant or a settings struct next to the system that uses it, never repeated as literals, so each value is edited in exactly one spot. The exception is performance: when removing duplication or centralising a value would cost speed (a hot loop that would read a runtime setting the compiler could otherwise fold, shader sizes that must stay compile-time, an abstraction that blocks inlining), keep the faster form and note why in a comment.
- **Branches:** one branch per feature, with descriptive commit messages. Merge into `main` with `--no-ff` (the merge commit keeps the branch name, and `<merge>^2` can recreate the branch), push, then delete the feature branch locally and on GitHub.

## Tests

- Plain `assert`-based tests, one `testXxx()` function per file in `tests/`. Small levels and comparisons shared by the physics tests (`near`, `block`, `flatLevel`, `addRamp`) live in `tests/test_levels.h`; driving the demo game headless (`tickSeconds`, `mobaInput`, `firstPersonInput`, `runTicks`, `runFrame`) lives in `tests/demo_helpers.h`; add to it rather than copying helpers between test files.
- **Register every new test** by adding a forward declaration and a call in `tests/test_main.cpp`. The makefile compiles the file automatically, but it will not run unless registered.
- Tests do not need a GPU or window. The GPU tests (`tests/gpu/`, `make gputest`) are a separate program, never registered in `test_main.cpp`.
- Do not compile with `-DNDEBUG`, because it turns every assert into a no-op.
- Known issue: the glTF tests use a fixed temp directory and throw if it exists. A failed assert leaves it behind and breaks the next run (delete `game_engine_gltf_*` in the system temp folder).

## Known small issues and ideas

- Latency: the renderer allows two frames in flight by default (`EngineSettings::framesInFlight`, 1 for the least latency, switchable live), and `Application` requests `PresentMode::Mailbox` (falls back to vsync if unsupported), so `EngineSettings::targetFPS` (240) is the real frame cap. `PresentMode::Immediate` is lower latency still but tears.
