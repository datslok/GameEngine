# Architecture reference

The detailed reference for how each system is built today: names, files, numbers and the reasons behind them. `CLAUDE.md` holds the rules and a short summary and points here; `docs/ENGINE_GUIDE.md` explains the concepts for a human reader; `docs/BUILDLOG.md` keeps the history (when each part was built, what was measured then, what was tried and dropped). Read the section for a system before changing it, and keep it in sync in the branch that changes it.

Live path: `main` picks a game from the game registry (`app/game_registry`: the demo, or another named with `--game`), makes it, then creates an `Application` (the engine), which drives the game through the `Game` hooks, fills `Input` from the `Window`, and draws the `World` with the renderer (`VulkanRenderer`, the engine's own Vulkan 1.3 renderer).

## Settings

Settings: every value a game, the debug UI or a player may tune lives in one settings struct owned by its system, read every frame unless noted, with defaults that are the engine's values. `EngineSettings` (`engine/engine_settings.h`: `ticksPerSecond` 120 and `maxFrameSeconds` 0.25, both read only at start-up; `targetFPS` 240, 0 = unlimited; `presentMode`, applied when it changes; `framesInFlight` (2), applied when it changes; `gpuValidation`, read at start-up and passed to the renderer's constructor (Vulkan's validation layers when installed; MSYS2's, which the makefile points the loader at; see VulkanRenderer), defaulting to `isDebugBuild` from `core/build_info.h`, which the makefile sets by defining `ENGINE_DEBUG_BUILD` in debug builds only; and `render`) is owned by `Application` (constructor argument, `getSettings()`). `RenderSettings` (`render/gpu/render_settings.h`) = `LightPrioritySettings lights` + `ShadowSettings shadows` + `BloomSettings bloom` + `ToneMappingSettings toneMapping` + `DisplaySettings display`, passed to `VulkanRenderer::render(frame, settings)` each frame. Camera controllers each own a settings struct (`FreeFlyCameraSettings`, `FirstPersonCameraSettings`, `MobaCameraSettings`; the look ones nest the shared `LookSettings`: `radiansPerPixel`, `sprintMultiplier`), passed to the constructor and editable through `getSettings()`. Fixed capacities (shader array sizes, atlas size, tile counts) stay compile-time constants. Games cannot reach `EngineSettings` yet (it pulls in `render/` headers); `main` uses the defaults, and the saved settings file is loaded over them (see Debug UI and the settings file). Every settings struct has a `visit(Settings&, SettingsVisitor&)` next to it, in its system's `.cpp` (`RenderSettings` in `render/gpu/render_settings.cpp`, `EngineSettings` in `engine/engine_settings.cpp`), and the demo's are reached through `Game::visitSettings`.

## Debug UI and the settings file

One description of every tunable value, walked by several visitors. `SettingsVisitor` (`core/settings_visitor.h`) has public `field` overloads for `float` (`FloatLimits`), `int` (`IntLimits`), `bool`, `double` (seen as a float, written back only when changed, so looking never rounds it), `std::uint32_t` and `std::uint64_t` (seen as ints), `choice` for enums whose values are 0, 1, 2... with a `std::array` of names, and `group` (a label and a callback); a visitor implements the protected `visitFloat`, `visitInt`, `visitBool`, `visitChoice` and `visitGroup`. Limits: `min`/`max` are hard limits (the file clamps to them, tests check defaults lie within them), `sliderMin`/`sliderMax` the useful range (default the hard limits; a field without finite hard limits must give them), `unit` (shown after the number), and `applies` (`FieldApplies::EveryFrame` or `AtStartup`). `SettingsWalk` is a `std::function<void(SettingsVisitor&)>`. File keys come from labels (`settingKey`: words in lower camel case, the first lowered whole: "GPU validation" is `gpuValidation`, "Target FPS" `targetFPS`), joined with dots through groups (`engine.render.bloom.strength`); keep labels named after their members. Hard limits that the renderer also checks share a constant (`maxBloomStrength`, `BLOOM_LEVEL_LIMIT`), and a test checks the ends pass `validateBloom`/`validateToneMapping`.

`engine/settings_file`: `captureSettings(walk)` lists every field as `SettingEntry {key, value}` (floats as the shortest text that reads back exactly, `std::to_chars`; bools `true`/`false`; enums by name); `applySettings(entries, walk, StartupFields)` sets the named fields, clamping to hard limits, skipping text that does not read as its kind, ignoring unknown keys, with a warning for each, and leaving start-up fields alone with `StartupFields::Keep`; `formatSettingsText(current, defaults, kept)` writes a two-line comment, each `key = value` whose text differs from the default's, then the `kept` entries as they are; `separateSections(entries, walk)` splits saved entries into `own` (their first key part is a section the walk has, or they have no dot, so a stray key is still warned about) and `others` (a section the walk lacks: another game's); `parseSettingsText` reads `key = value` lines (blank lines and `#` comments skipped, `\r\n` accepted, malformed lines warned with their number); `findLimitProblems` (tests); `engineAndGameSettings(settings, game)` is the whole tree, `Engine` then a group named by `Game::title()` (keys `demo.grenade.throwSpeed`, `lightLab.sun.solarHours`), so every game has its own section of the one shared file; `readSettingsFile` (nothing when the file is absent) and `writeSettingsFile`. The file is `savedSettingsPath` = `settings.cfg` in the working directory (git-ignored). `Application::captureDefaultsAndLoad` captures the defaults, then loads the file's own sections over them, leaving other games' alone (problems are logged with `SDL_Log`, never fatal). Save writes the changed values plus the other games' sections, read afresh from the file; Reset applies the captured defaults with start-up fields kept.

`DebugUi` (`engine/debug_ui`): owns the ImGui context and the SDL3 platform backend, and starts the renderer's half (`VulkanRenderer::startDebugUi`: ImGui's Vulkan backend, see VulkanRenderer; the SDL3 backend starts with `ImGui_ImplSDL3_InitForVulkan`); its destructor stops the renderer's half first (`stopDebugUi` waits for the GPU to go idle). No `imgui.ini`, keyboard navigation off (the game keeps its keys), sizes and font scaled by `SDL_GetWindowDisplayScale`. `build(walk, render, requests)` returns `nullptr` while closed (nothing runs); open, it runs the backends' `NewFrame`s (the renderer's through `beginDebugUiFrame`), one window "Settings (F5)" with the quality preset combo (`Custom` when `matchingQualityPreset` finds none), Save and Reset buttons (reported in `DebugUiRequests`, carried out by `Application`, which sets the status line), then the walk through `ImGuiSettingsVisitor`: top-level groups are collapsing headers (open), deeper ones tree nodes, each with its own ID scope; floats and ints are sliders (`%.4g` plus unit), clamped to the hard limits after Ctrl+click typing; start-up fields are disabled with a tooltip. Quality presets (`render/gpu/quality_preset`): `QualityPreset` Low, Medium, High, Ultra (`qualityPresetNames`); one table sets the shadowed point and spot light caps, both texel targets, the sun's shadow distance, cascade count and cascade resolution, and bloom's level count (Low 8, 4, 0.1, 0.05, 60, 2, 1024, 4; Medium 24, 8, 0.06, 0.03, 120, 3, 2048, 5; High = `RenderSettings{}` with 2048 cascades in the usual 128 MB atlas; Ultra = `RenderSettings{}`, the default, with 4096 cascades in the grown 384 MB atlas); `applyQualityPreset` and `matchingQualityPreset` read the same table, and taste settings are never touched.

Drawing: `VulkanRenderer::render(frame, settings, ui)` with `ui` = `ImDrawData*` or null. `VulkanOverlay` (`render/vulkan/vulkan_overlay`, its composite pipeline remade with the screen pipelines when the swapchain format changes): `drawUi`, called in `drawScene` before the shadow pass, while no pass is open, uploads ImGui's changed textures and draws the UI with `ImGui_ImplVulkan_RenderDrawData` into the overlay image (`R8G8B8A8_UNORM`, `vulkanOverlayFormat`, the frame's size, cleared to transparent, so it ends up premultiplied); `composite`, after the debug lines in the tone mapping pass, draws `fullscreen_triangle.vert` + `overlay.frag` (sampler 0 the overlay, nearest; uniform `OverlayData` with the white level) with blending `ONE, ONE_MINUS_SRC_ALPHA`: each texel's colour divided by its alpha (capped at 1), decoded from sRGB (`srgbToLinear` from `dither.glsl`), scaled by alpha and `DisplayOutput::whiteLevel`. Mirrored in `render/gpu/overlay_composite` (`overlayOutput`, `blendOverlay`). Dear ImGui 1.92.9b is vendored unmodified in `external/imgui` (core files, `imgui_impl_sdl3`, `imgui_impl_vulkan`; `VERSION.txt`); the makefile adds its `.cpp` files to the engine sources and turns off `-Warray-bounds` for them only (GCC's false positives at `-O2`).

## Golden images

Golden images (`engine/golden`, `engine/golden_capture`, `VulkanRenderer::capture`) check that the renderer keeps drawing fixed scenes the same. The references were made on SDL_GPU before the Vulkan port, and the port matched them bit for bit. A game lists its views with `Game::goldenViews()` (`GoldenView` in `engine/golden_view.h`: `name`, lower-case letters, digits and dashes (`isGoldenViewName`); `simulationSeconds`; `hdr`) and sets one up in a world fresh from `onInit` with `Game::prepareGoldenView` (the demo: free camera at a fixed pose via `PlayerControls::poseFreeCamera`, lamps and flashlight switched to the view's choice; six views: `start`, `start-hdr`, `gallery`, `lamp-field`, `floodlights`, `moon`; the light lab: the sun's solar time and a free camera pose; five views: `towers`, `overview`, `sunlit-room`, `sunset-hdr`, `sun-disc` (the camera facing the sun wherever it stands at that hour)). `advanceToGoldenView(game, world, view, ticksPerSecond)` prepares the view, runs `round(seconds × rate)` ticks through `runFixedUpdate` and one `onUpdate` with an empty `Input`; `golden_views_test` uses it to check each view is deterministic. `runGoldenImages(makeGame, gameFolder, mode)` (`main`: `--golden-save`, `--golden-check`, for every registered game or only the one named with `--game`, each in a folder named by its registry name; `make golden-save`, `make golden`) builds a fresh game and `Application` per view (window 640x360, `EngineSettings{}`, `SavedSettings::Ignore`, so `settings.cfg` never changes a capture, and a cold shadow cache and light history like a first frame; with `fitCascadesToDepth` the renderer first draws the frame once to measure its depths for the sun's cascades and then undoes everything else that frame changed, `measureDepthsBeforeCapture`) and calls `Application::captureGoldenView`: advance, upload new assets, `describeFrame(1, tick)` (shared with `render`), then `VulkanRenderer::capture(frame, settings, 1280, 720, goldenDisplayOutput(hdr))`. `capture` runs `drawScene` (shared with `render`: light priority, shadows, main pass, bloom) into frame images resized to 1280x720, tone maps into an off-screen target (`captureFormat`: `R8G8B8A8_SRGB` like the SDR swapchain, or `R16G16B16A16_SFLOAT` scRGB) with a tone mapping pipeline built for that format (`createToneMapPipeline`), copies the scene image and the target into a read-back buffer, waits for the GPU and returns a `CapturedFrame` (`render/captured_frame.h`: two `RawImage`s); it restores the display output so the next real frame is unaffected, and draws no debug lines or UI. `goldenDisplayOutput` fixes the screen: SDR, or HDR with SDR white at scRGB 2.5 (200 nits) and headroom 4. Files: `tests/golden/<goldenFolderName(GPU name)>/<game>/<view>-scene.png` and `<view>-final.png`; half-float images are packed losslessly into 8-bit PNGs twice as wide (`packHalfImage`, `unpackHalfImage` in `core/raw_image`; `saveRawImagePng`, `loadRawImagePng` in `assets/image_loader`). A check writes its captures and, for any image that differs, a heatmap (black equal, yellow within tolerance, red beyond) to `build/golden/<GPU>/<game>/`, prints one line per image and exits with 1 if any failed. `compareImages` (`core/image_compare`) counts differences in steps (bytes, or half-float ulps through `halfStepDistance` in `core/half_float`, where +0 and -0 are equal and NaN is never close); `ImageTolerance` defaults: at most 1 step, in at most 0.1% of pixels. The references are valid only for the GPU and driver that made them; on this one two runs, and the debug and release builds, match bit for bit.

## GPU tests and shader libraries

The shaders' maths lives in pure-function libraries in `assets/shaders/`, included by the passes and by the GPU tests, each mirrored in C++: `brdf.glsl` (`ggxDistribution`, `smithVisibility`, `schlickFresnel`, `viewCosine`, `ShadingPoint` and `prepareShading(baseColour, metallic, roughness, normal, toCamera, tableEntry)`, `facesLight`, `addLight`, `shadeAmbient`; `render/gpu/brdf`), `normal_mapping.glsl` (`decodeNormalTexel`, `perturbNormal`; `render/gpu/normal_mapping`), `lighting.glsl` (`distanceFalloff`, `spotCone`, `pointShadowFace`; `render/gpu/light_falloff` and `shadow_map`), `soft_shadow.glsl` (`linearShadowDepth`, `blockerSearchTexels`, `penumbraTexels`, the sun's `boxShadowDistance`, `sunBlockerSearchTexels` and `sunPenumbraTexels`, and the filter limits; `render/gpu/soft_shadow`), `tone_mapping.glsl` (the curves, `applyCurve`, `toneMap(linear, exposure, peak, curve)`; `render/gpu/tone_mapping`, whose `toneMap` also clamps negative light, which `tone_map.frag` does before mixing in bloom), `bloom.glsl` (`karisWeight`, `mixBloom`; `render/gpu/bloom`), `dither.glsl` (`linearToSrgb`, `srgbToLinear`, `interleavedGradientNoise`, `ditherForEightBits(linear, noise)`; `core/srgb`, `core/dither`), `overlay.glsl` (`overlayOutput`; `render/gpu/overlay_composite`) and `clusters.glsl` (the `ClusterGrid` struct, `toClusterView`, `clusterSlice`, `sliceStartDepth`, `clusterIndex`, `clusterOfPixel`, `clusterBounds`, `sphereTouchesBox`, `coneTouchesSphere`, `clusterHeatRamp`, `clusterHeatColour`; `render/gpu/clusters`, see Clustered shading), `cascades.glsl` (`cascadeEdgeDistance`, `cascadeBlendWeight`, `cascadeDitherKeeps`, `sunShadowBias`; `render/gpu/cascades`, see Cascaded sun shadows), `depth_range.glsl` (`includeDepth`; `render/gpu/depth_range`), `ray_tracing.glsl` (`cameraRayDirection`, `hitCornerWeights`; `render/gpu/ray_tracing`, see Ray tracing). Each has an include guard and includes the `*_shared.h` headers it needs. Library functions take everything as arguments: no texture reads, no `gl_FragCoord`, no derivatives (compute shaders have none of them), so `triangle.frag` reads the BRDF table (`sampleBrdfTable`) and `tone_map.frag` the pixel's noise and pass them in. Moving the functions into libraries left every golden image bit for bit the same. Only `.vert`, `.frag` and `.comp` files are compiled (for Vulkan 1.3, `--target-env=vulkan1.3`, which subgroup operations need); `.glsl` files are included.

`make gputest` (`make gputest-release` for the release build) builds `build/gputests.exe` from `tests/gpu/*.cpp` and the engine objects (not part of `tests.exe`, so `make test` needs no GPU), compiles `tests/gpu/shaders/*.comp` (with `-Isrc -Iassets/shaders -Itests/gpu`; glslc's dependency files in `build/obj/shaders/gpu_tests/`), runs it, then `game.exe --golden-check`. `gpu_test_main` makes a windowless `VulkanDevice{nullptr, true}` (validation on; any validation error fails the run), runs one `gpuTestXxx(runner, report)` per library (`brdf_gpu_test`, `normal_mapping_gpu_test`, `lighting_gpu_test`, `soft_shadow_gpu_test`, `tone_mapping_gpu_test`, `bloom_gpu_test`, `dither_gpu_test`, `overlay_gpu_test`, `clusters_gpu_test`, `cascades_gpu_test`), then `gpuTestDepthRange` (`depth_range_gpu_test`: the real `VulkanDepthRange` pass on depth images of known values uploaded through a buffer, sizes cut off mid-group, a lone surface in the last pixel, the near plane and the smallest normal float (depth images may flush denormals), and sky only, each compared bit for bit with the CPU range), then `gpuTestRayTracing` (`ray_tracing_gpu_test`: `ray_tracing.glsl` through the runner, then, on a GPU with ray queries, real structures for a cube, a sphere and a plane placed five times (turned and stretched, mirrored, one visual-only, a floor) traced by `ray_query_test.comp` (`RAY_SCENE_SET` 0, its buffers by address in push constants) and compared ray by ray with the CPU's `raycastTriangle` over the same triangles: hit or miss, instance, triangle and facing exactly, distance and interpolated normal within a tolerance growing with 1/cosine, since rounding of where a plane is moves a grazing hit along the ray; 2,000 rays from in front of the scene and from inside the cube, each solid-only or seeing everything), prints the report and exits with 1 on any failure.

- `GpuFunctionRunner::run(shader, function, inputs, inputsPerCase, outputsPerCase)` (`tests/gpu/gpu_function_runner`): inputs as `GpuVec4` (`std::array<float, 4>`, 16 bytes like a std430 `vec4`) in an upload storage buffer, outputs in a read-back storage buffer, one descriptor set from a one-set pool reset per run, push constants `{count, function, inputsPerCase, outputsPerCase}`, `vkCmdDispatch(workgroupCount(count, GPU_TEST_GROUP_SIZE))`, then a memory barrier compute shader storage writes to host reads, `ImmediateCommands::run` (submit and wait) and `invalidate`. Host writes need no barrier: submitting makes them visible (after `flush`). One `ComputePipeline` per shader, made on first use.
- Test shaders: `tests/gpu/shaders/gpu_test.glsl` (the buffers, the push constant block `TestCase`, `local_size_x = GPU_TEST_GROUP_SIZE` (64), `outsideTheCases`, `testInput(index)`, `testOutput(index, value)`) and one `<library>_test.comp` per library, which switches on `function` and calls the library. Function numbers and the group size: `tests/gpu/gpu_test_functions.h` (macro-only, read by both sides).
- `tests/gpu/gpu_check`: `CaseRandom` (xorshift32, the same inputs every run; `between`, `direction` uniform on the sphere), `gpuVec4`, `vec3From`, `gpuTestShader(name)` (`tests/gpu/shaders/<name>.comp.spv`), and `GpuCheckReport` (`section`, `check(name, tolerance, expected, actual)` for floats and `Vec3`s, grouped by name per section; `print` shows per group the values checked, pass or FAIL, and the worst comparison's share of its tolerance with both values; `failedGroups`).
- Tolerances (`core/float_tolerance`): `FloatTolerance{absolute, relative}`, allowed difference `absolute + relative * |expected|`; `toleranceUsed` (0 equal, including equal infinities; infinite for a NaN or a difference where nothing is allowed), `withinTolerance` (used share at most 1), `ToleranceTally` (`checked`, `failures`, `worstUse` with `worstExpected` and `worstActual`; `add` with the tally's tolerance or one per comparison). The tests use `arithmeticTolerance` (1e-6 absolute, 1e-5 relative: + - * / and sqrt), `transcendentalTolerance` (1e-6, 1e-4: pow, exp2, log2) and `exactTolerance` (cube faces, copies). Two follow the problem: `interleavedGradientNoise` is compared around the circle (it wraps at 1) within 4e-3, since at 4K pixel coordinates its inner product keeps only a few digits; `addLight` specular adds `4 * 4 epsilon / d` relative, with d = 1 - nDotH^2 (1 - alpha^2) GGX's denominator, because near a sharp highlight's peak a float step in nDotH changes the result by about 4 delta / d.
- What is compared: GGX over 41 halfway cosines by 11 roughnesses, Smith, Fresnel (cosines past both ends), 400 random surfaces through `prepareShading` (the table entry looked up on the CPU and passed in), `addLight`, `shadeAmbient` and `facesLight` (a fifth of them with the eye or light behind the surface; `facesLight` exactly, except within 1e-6 of grazing, plus one light exactly along the surface), normal texels and 300 perturbed frames (plus a zero one), falloff, spot cones, cube faces (random and on every edge and corner, exactly), the soft shadow arithmetic over both clamps, every tone mapping curve over 2^-12 to 2^10 at two exposures and peaks, the Karis weight and bloom mix, the sRGB curves, noise across a 4K screen, the dither, and overlay texels at every fifth alpha step and three white levels. Texture filtering (bloom's filters, PCSS's sampling, the BRDF table lookup) is left to the golden images.
- First results on the RTX 5080: every group within 16% of its tolerance except the noise (40%); planting a bug (Fresnel's power 5 changed to 4, the falloff window's fourth power to a cube) failed at 4,000 to 27,000 times the tolerance.

Compute pipelines: `ComputePipeline` (`render/vulkan/vulkan_compute`, from `ComputePipelineDescription{shader, storageBuffers, pushConstantBytes, sampledImages, sharedLayout}`): set 0 with storage buffers at bindings 0.., then `sampledImages` combined image samplers, a push constant range for the compute stage, `vkCreateComputePipelines`; or, with `sharedLayout` (not owned), a layout made elsewhere and only the pipeline built (`getResourceLayout` is then null); `get`, `getLayout`, `getResourceLayout`, `getPushConstantBytes`. `workgroupCount(count, groupSize)` (`render/gpu/compute_dispatch`, tested in `compute_dispatch_test`): groups to cover `count` items, rounded up without overflow. Users: the GPU tests (their own layouts), the renderer's cluster pass (the scene's layout; see Clustered shading) and the depth measurement (its own layout with a sampled image; see Cascaded sun shadows).

## Application (the engine)

`Application` (`engine/`) runs the main loop (fixed timestep, frame cap) for a borrowed `Game` (declare the game first so it outlives the engine). It owns the `Window`, the renderer (`VulkanRenderer`), `Input`, the `World` and the `AssetManager`. Members, in order: the borrowed `game`, `settings` and `defaultSettings` (initialised by `captureDefaultsAndLoad`, so the saved file is applied before the renderer reads `gpuValidation` and the timestep its rate), `window`, `renderer`, ..., `debugUi` (after the window and renderer, so it is destroyed first). Each frame, after the events, `updateDebugUi` handles F5 and builds the UI before `game.onInput`, so a changed setting applies that frame; its draw data goes to `render` and on to `VulkanRenderer::render`. While the UI is open the mouse is freed (`applyMouseMode` asks for mouse look only when the game wants it and the UI is closed). Before each frame it uploads every mesh and texture the `AssetManager` gained since the last frame (the ones past the renderer's counts), so games can load and spawn at any time. It applies `game.wantsMouseLook()` to the window only when it changes (re-applying would undo Escape).

## The Game interface, debug drawing, culling and render stats

`Game` (`engine/game.h`) has a `title()` (for people: the window title, after "My Engine: ", and the settings section) and hooks, called each frame in this order: `onInput(world, input)` once, `onFixedUpdate(world, tickSeconds, simulationSeconds)` per tick (no `Input` parameter on purpose), `onUpdate(world, input, frameSeconds, alpha)` once; plus `onInit(world, assets)`, `getCamera()` (the engine sets its aspect ratio), `wantsMouseLook()` and optional `getLightFocus()` (where lights are ranked, default the camera position); optional `onDebugDraw(const World&, DebugDraw&, alpha)` (called every frame after `onUpdate`) and `wantsDebugView()`. Debug drawing: `DebugDraw` (`scene/debug_draw`) collects `DebugLine`s (`line`, `box(bounds, transform)`, `sphere` as three circles, `capsule`); `Application` clears it every frame, adds `drawBoundingBoxes` (`engine/debug_views`, from `boundsByMesh`, filled with `meshBounds` as meshes upload) and `drawRenderStats` (last frame's `RenderStats`, `render/render_stats.h`, as text in the top-left) when the game wants the debug view, calls `onDebugDraw`, and puts the lines in `FrameDescription::debugLines` and `debugScreenLines`. `DebugDraw::screenLine` adds lines in window pixels (top-left origin); `debugText`/`debugTextWidth` (`scene/debug_text`) write text with a stroke font (A-Z, 0-9, : - / . ?, on a 4x6 grid; lower case drawn as upper, unknown characters as ?), a stopgap until phase 9's font rendering. The renderer draws world lines with the camera and screen lines with a flipped pixel orthographic matrix (`Mat4::orthographic` accepts flipped boxes, rejects empty ones). `VulkanRenderer` hands them to its `VulkanDebugLines` (`render/vulkan/vulkan_debug_lines`: owns the line pipeline and a growing upload vertex buffer per frame in flight; `upload` writes the vertices from `buildDebugLineVertices` straight into it before the render passes, `draw` runs in the tone mapping pass, after the scene is tone mapped, so line colours are exact), which draws them last as a line list with no depth test, so they show through everything; colours are linear. `World::each` has a const overload that passes const components. Culling: `Frustum::fromClipMatrix(viewProjection, ClipDepth)` (`math/frustum`; six inward unit-normal planes from the matrix rows, either depth convention; the renderer's matrices are `ZeroToOne`) and `intersectsSphere`, plus `corners` and `mayIntersect` (false only when one view lies wholly outside a side of the other, tested both ways). Each `DrawItem` has a `BoundingSphere bounds` (radius < 0 = unknown, never culled); `Application` fills it with `attachBoundingSpheres(frame.draws, boundsByMesh)` (`scene/culling`: the box's centre through the model matrix, half-diagonal times the largest axis scale). The renderer draws only `visibleDraws(draws, cameraFrustum)` in the main pass and only `shadowCasters(draws, tileFrustum)` in each shadow tile; shadow passes must never use the camera's frustum (off-screen casters still throw shadows into view). `getLastFrameStats()` returns `RenderStats` (drawn, culled, shadowDrawn, shadowCulled, and point lights total, in view, lit and shadowed, shown as a third line of the debug readout; then shadowTilesDrawn, shadowTilesCached and shadowTilesSkipped, a fourth line, ending with `sunShadowDistance` (SUN TO, where the sun's cascades end) when a sun is shadowed; then `gpu`, the GPU timings per pass, see VulkanRenderer; then `videoMemory`, a fifth line, `videoMemoryReadoutLine` (4): `videoMemoryText` writes "VRAM used / budget MB  ENGINE n MB" in megabytes of 2^20 bytes, or "VRAM ENGINE n MB  NO DRIVER BUDGET" without the driver's figures. `render/gpu/video_memory` (`HeapMemory`, `VideoMemory`, `summariseVideoMemory`: the device-local heaps added up, so system memory the GPU can reach is left out and an integrated GPU's one heap counts) is filled at the start of each `drawScene` from `VulkanDevice::getHeapMemory` (VMA's `vmaGetHeapBudgets`: the engine's share is each heap's `blockBytes`, the memory VMA took from Vulkan; `usage` and `budget` are the driver's for the whole process with `VK_EXT_memory_budget`, which the device turns on when present (`reportsMemoryBudget`), and VMA's estimates without it), after `startMemoryFrame` (`vmaSetCurrentFrameIndex` with a frame count, which makes VMA fetch the driver's figures again). The demo toggles its debug view with F4 (bounding boxes, the culling readout, a sphere in its colour at each point and spot light, a beam line for spotlights, and a line to the walk target). Always run ticks through `runFixedUpdate`, which saves previous transforms first; tests use it too. `DemoGame` (`games/demo/`) holds the player controls (camera, control modes, body), the player and marker entities, and all demo input rules; `LightLabGame` (`games/lightlab/`) is the second game (see Games and the light lab). `window` is declared first and `renderer` second: members are destroyed in reverse order, so the renderer goes before the window it draws into, and the GPU device outlives every uploaded mesh.

## Window

`Window` (`platform/`) owns SDL video and the `SDL_Window`: event polling into `Input`, quit, focus loss (releases everything), click to capture (mouse look) or confine (MOBA cursor), Escape to release, Alt+Enter fullscreen. While the debug UI has started (ImGui's SDL backend is running), every event goes to `ImGui_ImplSDL3_ProcessEvent` first, releases included; while it is open (`setDebugUiOpen`), key presses and mouse button presses ImGui wants (`WantCaptureKeyboard`, `WantCaptureMouse`, read once per frame) do not reach `Input`, and a click it takes neither captures nor confines the mouse. After the events it records the cursor position, window size, keyboard focus, mouse capture and cursor confinement into `Input`, so games read those facts from `Input` instead of the window. It reports raw facts only; game rules live in game code.

## The renderer, shadows and light priority

The renderer (`VulkanRenderer`, `render/vulkan/`, next section, with the API-free parts in `render/gpu/`) draws with SPIR-V shaders into a window it does not own. It owns the device, pipelines, frame images, and GPU copies of meshes and textures in arrays indexed exactly like the handles (`uploadMesh`, `uploadTexture`). Each frame it gets one call, `render(frame, settings)` (the frame plus `RenderSettings`), with a `FrameDescription` (`scene/frame_description`: a copy of the camera, the `FrameLighting` and a list of `DrawItem`s, each `{MeshHandle, model matrix, Material}`), built by `buildFrame(world, camera, alpha)` from every visible `ModelRenderer` with a `Transform` (one item per part, interpolated). Having the whole frame lets it draw the scene more than once (shadow maps) and cull; the per-frame steps (`beginFrame`, `drawScene`, `prepareShadowDraws`, `writeScene`, `drawShadows`, `drawMainPass`, `drawBatches`, `drawToneMap`, `submitFrame`, and `abandonFrame` to submit after an error; see GPU scene below) are private. Shadows: every light casts shadows unless its `castsShadows` is off (default on for directional, point and spot lights; `ModelRenderer::castsShadows`, default true, carried on each `DrawItem`, decides which meshes block light). `planShadows(lighting, camera)` (`render/gpu/shadow_map`) hands out square tiles of one D32 depth atlas (8192 x 4096, 128 MB; one 2D image because SDL_GPU could not draw into one layer of an array texture, kept through the port; 8192 x 12288, 384 MB, with the default 4096 cascades: `shadowAtlasSizeFor(ShadowSettings)`, see Cascaded sun shadows), numbered sun first, then spotlights, then point lights, in slot order: 1 per cascade of the brightest directional light (`maxShadowedDirectionalLights` = 1, up to `maxShadowCascades` = 4 texel-snapped boxes of `cascadeTilePixels(ShadowSettings::cascadeResolution)` each, see Cascaded sun shadows; other directional lights still light, unshadowed), 1 per spotlight (perspective down the beam, `spotShadowMatrix`), 6 per point light (cube faces, `pointShadowFace` = largest axis, mirrored in the shader; a face whose widest view misses the camera frustum, by `mayIntersect`, gets no atlas square and no draw: it keeps its place in `tiles`/`tileData` with size 0 and an empty rect, which the shader counts as lit, so `firstTile + face` still works). Shadow caching: the renderer keeps a `ShadowAtlasLayout` (`render/gpu/shadow_atlas`; `planShadows(lighting, camera, layout)` asks it for squares by `ShadowTileKey` = light kind, entity (slot when the entity is `Entity{}`) and face, and gets last frame's square back for the same size; a buddy `ShadowAtlasAllocator` merges freed quarters; on fragmentation it repacks everything once; the two-argument `planShadows` uses a fresh layout) and a `ShadowTileMemory` (`render/gpu/shadow_cache`: per square, the matrix and `shadowCasterSignature`, an FNV-1a hash of each caster's mesh index and model matrix; `remember` forgets overlapped squares; `forgetAll` after any render error). `prepareShadowDraws` finds each tile's casters in two steps, `castersInReach(draws, tile.reach)` (a bounding sphere against the light's range sphere, one test per caster, computed once for the consecutive tiles of one light) and then `shadowCasters(draws, candidates, frustum)` for the tile's own view, and skips tiles whose matrix and signature match; a caster wholly beyond a light's range cannot block it where it shines (only a soft shadow's wide filter could still reach one, where the falloff is all but zero: this changed 6 pixels of one golden image by at most 3 half-float steps). `drawShadows` loads the atlas (kept between frames), resets each redrawn tile with `shadowClearPipeline` (`fullscreen_triangle.vert`, a viewport-covering triangle at the far depth `GPU_FAR_DEPTH` (0), also used by the tone mapping pass, compare `ALWAYS`) and skips the pass when nothing changed; up to 1 sun, 8 spot and 64 point lights (`maxShadowTiles` = 396; at most 4 x 16 + 8 + 64 x 6 = 456 of the 512 smallest-tile places with the cascades at 1024, so everything fits at the smallest size; with 4096 cascades 4 x 256 + 392 of the grown atlas's 1536, so the cascades keep their size); lights past that still light, unshadowed. Tile size: `shadowTileSizeFor(halfWidth, range, texelTarget, largestSize)` picks a power of two from 256 px up to `largestSize` (1024 `standardShadowTileSize` for point faces, 2048 `largestShadowTileSize` for spotlights) so one texel covers about `ShadowSettings::texelTarget` = 0.04 units (`spotTexelTarget` = 0.02 for spotlights, whose beams land at a slant short of their reach; the floodlights get 2048, the flashlight 512) across the far end of the view; if the total would overflow, `shrinkToFit` halves the least important (last) requests first, so every point light reaches the smallest size before a spotlight shrinks, and the sun's cascades shrink last, never below 1024; the `ShadowAtlasLayout` places them, largest first, with its buddy `ShadowAtlasAllocator` (power-of-two squares split into quarters and merged back), so they never leave gaps. `ShadowPlan::tiles` holds each `ShadowTile` (matrix, x, y, size in pixels) for the shadow pass's viewports; matrices and offsets depend on the tile size (`pointShadowFaceMatrix`/`spotShadowMatrix` take it, default 1024; the `ShadowAtlasAllocator` starts as squares of its `ShadowAtlasSize::largestSquare`: 8 of 2048, or 6 of 4096 in the grown atlas). Perspective views are a little wider than needed so 3x3 PCF never leaves a tile. `selectDrawableLights` (`light_uniforms`, with `canBeDrawn` per light) is the single rule for which lights reach the shader and in which slot, used by both `packLighting` and `planShadows`. Before them, `drawScene` runs `prioritizeLights(lighting, frame.lightFocus, cameraFrustum, lightHistory)` (`render/gpu/light_priority`): it drops lights whose range sphere misses the camera frustum, ranks the rest by `priority` (an int on `PointLight` and `SpotLight`, default 0; higher always wins), then by `lightImportance` at the focus (`intensity * brightest channel / (d² + r²)`, no range window so far lights do not tie at zero; directional lights by brightness alone), seats the top lights up to the seats (by default every light the buffers hold), gives shadows to the top seated casters up to the shadow caps (`LightPrioritySettings`, an optional last parameter: seats defaulting to `defaultPointSeats` and `defaultSpotSeats`, equal to the buffers' room since clustered shading, and clamped to the light buffers' room, `maxPointLights` (1024) and `maxSpotLights` (256), and the shadow caps, clamped to theirs, plus `incumbentAdvantage` and `fadeSeconds`; tests lower the point shadow cap to 16 to exercise shadow-only handovers; the shader skips a light, and so its shadow lookups, for pixels beyond its range) (switching `castsShadows` off on the others' copies, so `planShadows` needs no change), and returns a `LightHistory` (entities in view, and each seat holder's `LightFade`: entity, light and shadow strength 0..1) that the renderer keeps. Handovers fade over `fadeSeconds` (0.25; 0 hands over at once): a holder that is no longer wanted keeps its seat or shadow while fading out and frees it at zero, then the wanted newcomer fades in (from 0 if it was on screen last frame, at full if not: a light just switched on or come into view appears at once); a light leaving the view is dropped at once. The strengths reach the GPU as `PlacedPointLight`/`PlacedSpotLight::fade` (multiplied into the radiance by `packLighting`) and `shadowFade` (`LightShadow::strength` in the plan, copied with `emitterRadius` for soft shadows into each light's record by `attachShadows`; the shader mixes the shadow towards lit). `prioritizeLights` takes the frame time, from `FrameDescription::frameSeconds` (set by `Application` from the timestep); last frame's choices count `incumbentAdvantage` (1.25, `LightPrioritySettings`) times as much (hysteresis, between equal priorities only). `PlacedPointLight`/`PlacedSpotLight` carry their `Entity` for this (`Entity{}` never counts as last frame's). `FrameDescription::lightFocus` is the camera position from `buildFrame`, then `Application` sets it from `Game::getLightFocus()` (default: camera position; `DemoGame` returns `MobaCameraController::getLookPoint` in MOBA mode, the ground point the camera looks at). `ShadowPlan` holds one `LightShadow` per light the shader gets, in slot order (`directional`, `spots`, `points`: first tile, -1 for none; strength; emitter radius), which `attachShadows(GpuLights&, plan)` copies into the light records (see GPU scene). Per-tile data, `ShadowTileData` (112 bytes: column-major matrix, normal offset per unit of distance for perspective tiles or fixed for boxes, atlas rectangle 0..1, and `lens`: near, far and world size of a texel per unit of distance for perspective tiles; for a sun's cascade boxes 0, the box's depth, its texel's world size and its radius), goes to the scene's `ShadowTiles` storage buffer (std430, set 1 binding 6). Each `ShadowTile` also carries `reach`, the sphere its light lights (centre at the light, the range as radius; radius -1 for the sun's cascades, which reach everywhere). **Uniform blocks must stay at or under 4096 bytes** (`maxUniformBlockBytes`, `render/gpu/uniform_limits.h`): `FrameUniforms` binds each block with a 4 KB range (SDL_GPU's window, kept from the port), and a shader reading past it reads outside the range with no error anywhere; every uniform struct has a `static_assert` on it. The shadow pass is one render pass with a depth-only pipeline (`shadow.vert`/`shadow.frag`, positions only, no culling, no hardware depth bias: its slope-scaled part detached shadows from pillars seen edge-on by small tiles), the viewport moved to each tile, the tile's world view pushed as a push constant (`GpuShadowView`) and its casters drawn one instanced draw per mesh. The main shader samples the atlas as `sampler2DShadow` (fragment sampler slot 1, compare `GREATER_OR_EQUAL` for reversed-Z, linear), after offsetting the point along its normal by 2.5 texels of its tile (`ShadowSettings::normalOffsetTexels`, the only bias; the sun's lookups move towards the sun instead, see Cascaded sun shadows), and treats points outside a tile's view as lit. Point and spot lights get soft shadows (PCSS, `softShadowFromTile`; the arithmetic is mirrored and tested in `render/gpu/soft_shadow`): a 16-sample Poisson-disc blocker search in the atlas read as raw depths (`shadowDepths`, fragment sampler slot 2, a nearest non-comparison `shadowDepthSampler`), the penumbra `emitterRadius * (receiver - blocker) / blocker` in texels (1 to 12), then 16 comparison samples over it, rotated per pixel by interleaved gradient noise, clamped a texel inside the tile, each compared against the receiver's plane (receiver plane depth bias from `dFdx`/`dFdy` of the camera-relative position, taken at the start of `main` in uniform control flow and projected through the tile). `PointLight::emitterRadius` (0.05) and `SpotLight::emitterRadius` (0.025) are the glowing size for shadows, separate from `sourceRadius`, which only shapes the falloff (the demo flashlight's is 4.5). `Mat4::orthographic` builds the box projection (OpenGL depth convention like `perspective`). It fits its camera copy's aspect ratio to the acquired frame, and `Application` then copies that ratio into the game's camera for click rays. It never reads files.

## VulkanRenderer

`VulkanRenderer` (`render/vulkan/`) is the engine's own Vulkan 1.3 renderer (phase 6b). It replaced SDL_GPU's `GpuRenderer` one pass at a time, with the same compiled shaders: all twelve golden images matched SDL_GPU's bit for bit (debug and release) before SDL_GPU was removed, so several of SDL_GPU's choices are kept on purpose (see Kept from SDL_GPU). Public calls: the constructor (`SDL_Window*`, `validation`), `render`, `capture`, `uploadMesh`, `uploadTexture` and their counts, `startDebugUi`, `beginDebugUiFrame`, `stopDebugUi`, `setPresentMode`/`getPresentMode`, `getLastFrameStats`, `getDisplayOutput`, `getFrameAspectRatio` and `getDeviceName` (the golden folder's name).

Libraries (vendored unmodified, versions in each folder's `VERSION.txt`, matched to MSYS2's Vulkan headers 1.4.363): volk (`external/volk`, C) loads every Vulkan function from the driver at run time, so the makefile defines `VK_NO_PROTOTYPES` everywhere and nothing links against the loader; vk-bootstrap (`external/vk-bootstrap`) builds the instance, picks the GPU and makes the device; VMA (`external/vma`, implementation compiled once in `vk_mem_alloc.cpp` with dynamic function fetching, three warnings silenced for it) allocates memory; ImGui's Vulkan backend (`external/imgui/imgui_impl_vulkan.cpp`, built with `IMGUI_IMPL_VULKAN_USE_VOLK`). Validation layers come from MSYS2 (`mingw-w64-ucrt-x86_64-vulkan-validation-layers`, in `C:\msys64\ucrt64\bin`, which the loader does not search, so the makefile exports `VK_ADD_LAYER_PATH`).

Files: `vulkan_device` (`VulkanDevice`: `volkInitialize` once per process, since vk-bootstrap caches the loader's first functions for good and SDL unloads its own copy whenever video shuts down; SDL's library loaded per device for `SDL_Vulkan_CreateSurface` and its instance extensions; without a window (`nullptr`, the GPU tests) no SDL at all: vk-bootstrap's headless mode (no surface extensions), no surface, no present support asked of the GPU or checked on the queue; Vulkan 1.3 with `VK_EXT_swapchain_colorspace` when present; validation layers when `validation` and installed, errors counted, validation and performance warnings logged, the loader's own warnings dropped; required features `dynamicRendering`, `synchronization2`, `samplerAnisotropy`, `depthClamp`, and for bindless textures `runtimeDescriptorArray`, `shaderSampledImageArrayNonUniformIndexing`, `descriptorBindingPartiallyBound`, `descriptorBindingSampledImageUpdateAfterBind`, `descriptorBindingUpdateUnusedWhilePending`, and `bufferDeviceAddress` (required by Vulkan 1.3 itself); optional ray queries (see Ray tracing) (`getBindlessTextureLimit`: the smallest update-after-bind sampler and sampled image limit); discrete GPU preferred; one queue for drawing, copies and presenting; VMA; helpers for semaphores, fences, samplers, command pools and SPIR-V modules), `owned_handle` (`OwnedHandle<T>`: one device object and its destroy function), `vulkan_check` (`vulkanCheck`: a `VkResult` other than success becomes an exception naming it), `vulkan_memory` (`VulkanBuffer` in `BufferMemory::Gpu`, `Upload` (mapped, sequential writes) or `Readback` (mapped, cached); `VulkanImage`, a 2D image with a view of all levels and its current `ImageState`), `image_state` (below), `immediate_commands` (`ImmediateCommands::run`: record, submit, wait; uploads, the atlas clear and the GPU tests' dispatches), `vulkan_compute` (`ComputePipeline`, see GPU tests and shader libraries), `vulkan_swapchain` with `swapchain_choice` (below), `vulkan_pipeline` (below), `frame_descriptors` (`FrameDescriptors`, `FrameUniforms`), `uniform_ring`, `bindless_textures` and `scene_layout` (GPU scene below), `render_pass` (`beginRendering`, `bindFragmentResources`, `drawFullScreenTriangle`), `vulkan_mesh`, `vulkan_texture`, `vulkan_bloom`, `vulkan_debug_lines`, `vulkan_overlay`, `vulkan_renderer`. Outside the folder: `render/window_display` (`readWindowDisplay`, the window's HDR properties), `render/mesh_upload` (`checkMeshUpload`), `render/present_mode.h` and `render/gpu/column_major.h` (`writeColumnMajor`, matrices for GLSL).

Kept from SDL_GPU, so the port drew the same pictures: the shaders of bloom, tone mapping, debug lines and the overlay keep SDL's descriptor layout (set 0 vertex textures, unused; set 1 vertex uniform blocks; set 2 fragment textures as combined image samplers, then storage buffers; set 3 fragment uniform blocks), described per pipeline by `ShaderResources`, with set layouts shared through `DescriptorLayouts`; the scene's pipelines (main, shadow, tile reset) left it for the GPU scene's layout (`PipelineDescription::sharedLayout`, see GPU scene). Every pipeline has depth clamping on (SDL's `enable_depth_clip` defaults to false), counter-clockwise front faces, line width 1 and dynamic viewport and scissor; `setViewport` flips the viewport (y at `y + height`, negative height) as SDL does, and `beginRendering` sets the whole target as viewport and scissor. Formats: swapchain `B8G8R8A8_SRGB` (fallback `R8G8B8A8_SRGB`) in sRGB, or `R16G16B16A16_SFLOAT` in `EXTENDED_SRGB_LINEAR` for HDR; captures `R8G8B8A8_SRGB` or `R16G16B16A16_SFLOAT`; bloom levels `B10G11R11_UFLOAT_PACK32` when it can be drawn into, blended and filtered. Samplers are shared, not per texture: surfaces trilinear, repeating, anisotropy 16 (or the GPU's limit), any level (`VK_LOD_CLAMP_NONE`; SDL set each texture's own level count, which the GPU clamps to anyway); tables bilinear and clamped; nearest (scene for tone mapping, the overlay); linear clamped (bloom); shadow compare (`GREATER_OR_EQUAL`, linear) and shadow raw depth (nearest). Mipmaps are blits from the level above with a linear filter, each level `max(1, size >> level)` (SDL let a non-square texture's short side reach 0 in its smallest levels).

Uniform blocks (`FrameUniforms`): SDL's push semantics, kept. `push(stage, slot, data)` copies the block into the frame's 4 MB upload buffer at the next offset aligned to `minUniformBufferOffsetAlignment` (`UniformRing`: each slice leaves room for a whole 4 KB range, `maxUniformBlockBytes`, inside the buffer) and remembers it for the slot; `bind(commands, pipeline)` binds set 1 and set 3 (one descriptor set per stage and block count per buffer, every binding a `UNIFORM_BUFFER_DYNAMIC` with a 4 KB range) with the slots' latest offsets as dynamic offsets. A full buffer moves on to the next (made once, then reused every frame) and copies the slots' latest blocks along, so a draw's blocks are always in one buffer. `flush()` before submitting. Set 2 is written fresh per draw (`bindFragmentResources`) from `FrameDescriptors`, pools of 1024 sets (8192 textures, 1024 storage buffers, 16 uniform buffers for the scene set) reset together each frame, another pool added when one runs out.

Synchronisation (`image_state`): an `ImageState` names a kind of use (`Undefined`, `Acquired`, `ColourTarget`, `DepthTarget`, `FragmentRead`, `DepthFragmentRead`, `DepthComputeRead`, `TransferSource`, `TransferDestination`, `Present`) and `imageStateUse` its stages, reads, writes and layout; `imageBarrier(image, aspect, from, to, ImageContents, levels)` waits for the old state's stages, flushes only its writes, makes the data visible to all of the new state's accesses, and changes the layout (from undefined when `ImageContents::Discard`); `needsBarrier` is false only for the same read-only state twice. `VulkanImage::transition` and `transitionImage` (for swapchain images) record the barrier and remember the state, which persists across frames, so a write after last frame's read still waits for it. `Acquired` starts from the colour output stage, the stage the frame's submission waits for the acquire semaphore at (`acquireWaitStage`), so the first barrier on a swapchain image chains after the semaphore. `Present` has no stage or access: the render-finished semaphore orders presentation. Tested in `image_state_test`.

A frame (`render`): `updateDisplayOutput` (window HDR properties every frame; `swapchain.supportsHdr()` only when HDR comes on; `chooseDisplayOutput`), `prepareSwapchain` (rebuild, after `waitIdle`, when missing, out of date, resized, HDR changed or the present mode changed; HDR refused falls back to SDR and is marked unsupported; the tone mapping, debug line and overlay pipelines remade for a new format; false while minimised, after a 10 ms sleep), `beginFrame` (wait for the frame's fence, reset its descriptor pools, uniform buffers and command pool, begin the command buffer), acquire (signals the frame's `imageAcquired`; out of date submits the empty buffer and draws nothing), `ensureFrameTextures` (scene `R16G16B16A16_SFLOAT` and depth `D32_SFLOAT` at the swapchain's size, and the cluster masks buffer, remade after `waitIdle`), `drawScene`, then the swapchain image `Acquired` to `ColourTarget` (discarded), one pass of tone mapping, debug lines and the overlay, to `Present`, and `submitFrame` (wait for `imageAcquired` at the colour output stage, signal the image's render-finished semaphore, one per swapchain image; the fence reset just before submitting; present). `drawScene` starts on the CPU (camera, frustum, `prioritizeLights`, `packLighting`, `planShadows`), then: debug line vertices and shadow tile data written straight into the frame's upload buffers (no copy passes), the UI into the overlay, the clusters' light lists (when `RenderSettings::clusteredShading`, on by default, or `clusterHeatmap`; see Clustered shading), shadows, the depth prepass (when `RenderSettings::depthPrepass`, on by default), main pass, the depth measurement for the sun's cascades (when `ShadowSettings::fitCascadesToDepth`; see Cascaded sun shadows), bloom. Shadows: atlas `DepthFragmentRead` to `DepthTarget` (kept), one pass over the atlas loading and storing depth, per tile a viewport, the reset pipeline (`fullscreen_triangle.vert`, depth `ALWAYS`) and the casters, then back to `DepthFragmentRead`; the atlas is cleared to `gpuFarDepth` at creation. Depth prepass (`drawDepthPrepass`, `render/gpu/depth_prepass`): depth to `DepthTarget` (discarded), a rendering block with no colour attachment that clears depth to far and stores it, `depthPrepassPipeline` (the main pass's `triangle.vert` and vertex layout with no fragment shader and no colour format; `GREATER`, written: `prepassDepthState`) and the same `drawBatches` as the main pass, so the depth image holds the nearest surface at every pixel. Main pass: scene to `ColourTarget` (discarded, cleared to 0, 0, 0, 1) and depth to `DepthTarget`: after the prepass kept (the barrier from depth target to depth target makes the prepass's writes visible to this pass's tests) and loaded, with `mainAfterPrepassPipeline` (`EQUAL`, not written: `mainPassDepthState(true)`), so `triangle.frag` runs once per pixel whatever the draw order; without it discarded and cleared to far, with `mainPipeline` (`GREATER`, written). The scene's two sets bound once, one instanced draw per mesh (`drawBatches`), then the scene to `FragmentRead`. `EQUAL` needs both passes to compute each vertex's depth bit for bit the same: they share `triangle.vert`, whose `gl_Position` is declared `invariant` (GLSL promises identical results for an invariant output only; without it a compiler may, for instance, fuse a multiply and an add in one pipeline and not the other). Measured: every golden image identical with the prepass on and off; adding `invariant` changed 10 of the 12 references by rounding alone (separate multiplies and adds instead of fused ones; single pixels along silhouettes and shadow edges). `RenderStats::drawCalls` counts both passes' calls. In `triangle.frag` each light is skipped before its shadow lookups when `facesLight` says it is behind the surface (the same test `addLight` makes, on the normal-mapped normal, so the result is unchanged bit for bit). GPU time, release, RTX 5080, mean of 200 captures (main pass plus prepass, without and with the prepass): at 1280x720 start 0.092 and 0.093 ms, gallery 0.082 and 0.079, lamp field 0.346 and 0.351, floodlights 0.128 and 0.105; at 2560x1440 start 0.259 and 0.254, gallery 0.227 and 0.218, lamp field 1.203 and 1.207, floodlights 0.388 and 0.324. The prepass itself costs 0.005 to 0.017 ms; it pays where surfaces hide each other (the floodlights view, 16%), not in the lamp field, whose cost was every pixel looping over all 64 point light seats (clustered shading's job, which took it to 0.75 ms; see Clustered shading). The skip of lights from behind saved about 3% of the lamp field's main pass at 1440p. Bloom (`VulkanBloom`): the chain of `render/gpu/bloom` (see Light, HDR, tone mapping, bloom and shading), each step its level to `ColourTarget` (discarded when overwritten, kept when added onto), the filter, then `FragmentRead`. Debug lines (`VulkanDebugLines`): one growing upload vertex buffer per frame in flight. Overlay (`VulkanOverlay`): ImGui's changed textures uploaded first (`ImGui_ImplVulkan_UpdateTexture`, which submits and waits on its own), then the UI drawn into the `R8G8B8A8_UNORM` overlay (cleared to transparent) with `ImGui_ImplVulkan_RenderDrawData`; `startDebugUi` gives ImGui the device, queue, dynamic rendering with that format, and two frames' buffers. On an error mid-frame `abandonFrame` ends an open pass, moves an acquired image to `Present`, submits and presents, and the shadow cache is forgotten.

`capture` draws `drawScene` and the tone mapping pass into a capture image (its own tone mapping pipeline for that format) at the golden size, copies the scene and final images into one read-back buffer, adds a transfer-to-host barrier, submits, waits for the GPU and reads both back; the display output is restored afterwards. Frames in flight: `EngineSettings::framesInFlight` (default 2, 1 to `maxFramesInFlight` = 2, `validFramesInFlight` clamps; `render/frames_in_flight.h`), given to the constructor and applied live by `Application::applyPresentation` through `setFramesInFlight` (waits for the GPU, `createFrames` anew, `VulkanDebugLines::setFramesInFlight`, and the swapchain rebuilt by `prepareSwapchain` because `swapchainFramesInFlight` differs; ImGui's backend keeps `maxFramesInFlight` vertex buffer sets throughout), each frame with its own command pool and buffer, fence (created signalled), acquire semaphore, descriptors, uniforms, shadow tile buffer and timestamp query pool; the swapchain has at least one image per frame in flight, the surface's minimum, and three for Mailbox (`chooseSwapchainImageCount`, tested in `swapchain_choice_test` with the format, present mode and extent choices).

GPU timing and debug labels: `render/gpu/gpu_timing` (no graphics API, tested in `gpu_timing_test`) lists the timed passes in recording order (`GpuPass`: `DebugUi` (the UI drawn into its overlay image), `RayScene` (the ray tracing scene's top-level structure, only while something traces rays), `Clusters` (the clusters' light lists, a compute pass), `Shadows`, `DepthPrepass`, `Main`, `RayDebug` (the ray tracing debug view), `DepthRange` (the screen's depths measured for the sun's cascades, a compute pass), `Bloom`, `ToneMap`, `DebugLines`, `Overlay` (the composite); `gpuPassName` gives the readout's short names UI, TLAS, CLUSTERS, SHADOW, PREPASS, MAIN, RAYS, DEPTHS, BLOOM, TONE, LINES, OVERLAY, also used as the debug labels), `gpuTimestampCount` (one stamp before the first pass and one after each), `timestampTicksBetween` (the difference masked to the queue's `timestampValidBits`, so a counter that rolls over still gives the right count) and `gpuTimingsFromTicks` (seconds per pass from the device's `timestampPeriod`; the passes add up to `totalSeconds`; not `valid` with zero valid bits). Each frame in flight has a timestamp query pool of `gpuTimestampCount` (none when the queue's `timestampValidBits` is 0), reset with `vkCmdResetQueryPool` at the start of its command buffer. `beginGpuPass`/`endGpuPass` wrap each pass: `writeTimestampsThrough` writes every stamp up to the pass's start or end with `vkCmdWriteTimestamp2` at `ALL_COMMANDS` (so a stamp lands when everything before it has finished, and a pass skipped this frame gets two stamps at the same moment, lasting 0), and a debug label (`VulkanDevice::beginLabel`/`endLabel`) marks the pass in between; the tone mapping, debug line and overlay labels sit inside their one rendering block. `finishGpuTimings` writes any stamps left and marks the frame complete (`render` and `capture` only, so an abandoned frame or one without a swapchain image is never read). `beginFrame` reads a complete frame's stamps after its fence with `vkGetQueryPoolResults` (64-bit, no wait; `VK_NOT_READY` skips the frame) into `unreportedGpuTimings`, which `drawScene` moves into `RenderStats::gpu`, so each measured frame is reported once, as many frames late as there are in flight. `Application` records them into its `gpuProfiler` (`makeGpuProfiler`: GPU (the total) as section 0, then one section per pass; `recordGpuTimings` skips invalid timings), updated with the CPU profiler and drawn on readout line `gpuProfileReadoutLine` (6) in the F4 view. `VulkanDevice` turns on `VK_EXT_debug_utils` whenever the instance has it (vk-bootstrap already adds it for validation messages), in release builds too, since labels and names cost nothing without a tool attached; `nameObject` names objects (`ImageDescription::name`, a string literal, names each `VulkanImage`: Scene colour, Scene depth, Shadow atlas, Bloom level, Debug UI overlay, Golden capture; the frame command buffers are Frame commands), so RenderDoc, Nsight and validation messages show names instead of handles.

## GPU scene

The scene's two passes (main and shadows) read everything from storage buffers written once per frame, so nothing is bound or pushed per object and every object with the same mesh is one instanced draw in each view (phase 6c, `gpu-scene`). The API-free parts are in `render/gpu/gpu_scene` (tested in `gpu_scene_test`), `light_uniforms`, `material_uniforms` and `shadow_map`; the Vulkan parts in `render/vulkan/bindless_textures` and `scene_layout`.

Records (std430, mirrored byte for byte in the shaders, each with a `static_assert` on its size): `GpuInstance` (160 bytes: world model matrix, normal matrix, handedness, material number, mesh number (for ray hits); `packInstance(draw, material)`), one per `DrawItem` of the frame, instance i being draw i, the same for every view (ray tracing instances and GPU culling can read the same records later); `GpuMaterial` (64 bytes, see Assets and materials), deduplicated per frame by `MaterialTable::add` (an FNV-1a hash of the packed bytes, then a full comparison; packing has no padding); `GpuDirectionalLight` (48: direction towards the light, radiance, `shadowTile` (its first cascade), `cascadeCount`, `tanAngularRadius`), `GpuPointLight` (48: position and range, radiance and source radius, `firstShadowTile`, `shadowStrength`, `emitterRadius`) and `GpuSpotLight` (64), in `GpuLights` from `packLighting` with `ambient` and `counts`, shadows filled in by `attachShadows`; the buffers hold `maxPointLights` (1024) point, `maxSpotLights` (256) spot and `maxDirectionalLights` (4) directional lights, all seated by default since clustered shading (each pixel loops only over its cluster's lights); `ShadowTileData` as before; and a draw list of `uint32` instance numbers. `GpuFrameData` (256 bytes, std140 uniform buffer, vertex, fragment and compute): the camera-relative view-projection, the camera position, ambient, counts, the atlas texel size, the cluster grid (`clusterTiles`, `clusterScreen`, `clusterSlicing`, `viewRight`, `viewUp`, `viewForward`, laid out as `clusters.glsl`'s `ClusterGrid`) `shadingOptions` (x clustered shading, y the heatmap) and `cascadeOptions` (x the cascades' blend band, y 1 to dither between them) (`makeFrameData(lights, relativeViewProjection, cameraOrigin, clusters, clusteredShading, clusterHeatmap, shadows)`; the atlas texel size comes from `shadowAtlasSizeFor(shadows)`). `GpuShadowView` (64 bytes): a tile's world view-projection, the scene layout's one push constant (vertex stage).

Batching: `batchByMesh(draws, chosen, firstInstance)` stable-sorts the chosen draw indices by mesh (each mesh's draws keep their order, so a frame always gives the same draw list) and cuts the runs into `DrawBatch`es {mesh, firstInstance, instanceCount}; `drawBatches` binds each mesh's buffers and calls `vkCmdDrawIndexed(indexCount, instanceCount, 0, 0, firstInstance)`, so `gl_InstanceIndex` is the draw list entry. The draw list is the main pass's visible draws in batch order (entries from 0), then each redrawn shadow tile's casters in batch order (`prepareShadowDraws`, entries from the main pass's count). Lamp field with every tile redrawn: 161 visible draws in 10 calls, 1861 caster instances in 783 calls; about 61 KB uploaded per frame; CPU recording 1.75 ms before the GPU scene, about 1.15 ms after (release, RTX 5080, measured around golden captures).

Shaders: `instances.glsl` (the `InstanceData` struct, `Instances` at set 1 binding 1 and `DrawList` at binding 10), `frame_data.glsl` (the `FrameData` block, binding 0), `materials.glsl` (the bindless texture array and the `MaterialData` buffer, shared by `triangle.frag` and `ray_debug.frag`) and `scene_lights.glsl` (the light records and their buffers, bindings 3 to 5, shared by `triangle.frag` and `cluster_lights.comp`) are declaration-only includes; `frame_clusters.glsl` builds the frame's `ClusterGrid` from the block (`frameClusterGrid`). `triangle.vert` reads `instances[drawList[gl_InstanceIndex]]`, subtracts `cameraOrigin` from the model matrix's translation (exactly `relativeTo`), and passes the material number flat to `triangle.frag`, which reads `materials[materialIndex]` and its textures as `textures[nonuniformEXT(slot)]` (neighbouring pixels of one shading group may be different objects; `GL_EXT_nonuniform_qualifier`), and each light's shadow from its record. `shadow.vert` computes `tileMatrix * (model * position)` in world space, so cached tiles stay keyed on world matrices.

Descriptors (`scene_layout`): set 0 is `BindlessTextures` (one binding of 16384 combined image samplers, or `getBindlessTextureLimit` if lower, all with the surface sampler; layout and pool update-after-bind, binding partially bound and update-unused-while-pending, so `uploadTexture` writes slot handle + 1 while frames using other slots are in flight; the white stand-in in slot 0 at start-up; `checkTexturesUploaded` throws for a material texture never uploaded); set 1 is the frame's scene (`SceneBinding`: 0 `FrameData` uniform, 1 instances, 2 materials, 3 to 5 directional, point and spot lights, 6 shadow tiles, 7 the atlas with the comparison sampler, 8 the atlas raw, 9 the BRDF table, 10 the draw list, 11 the cluster masks; the frame data and the point and spot lights are visible to the compute stage too, and the masks to fragment and compute), written once per frame by `writeSceneSet` from the frame's `FrameDescriptors` pools. `SceneLayout` owns set 1's layout and the pipeline layout of both sets plus the push constant, shared by the main, shadow and tile reset pipelines (`PipelineDescription::sharedLayout`) and the cluster pass (`ComputePipelineDescription::sharedLayout`), so `bindScene` (graphics bind point by default; compute for the cluster pass, whose bound sets are kept apart) binds both sets once per pass and they stay bound across those pipelines (the debug UI's pass binds sets of its own before the shadow pass, hence once per pass rather than once per frame). Each frame in flight has its own `SceneBuffers`: `UploadArray`s in upload memory (frame data, instances, materials, three light buffers, shadow tiles, draw list), each grown (to twice its size, or what is needed) when a frame needs more, safe because the frame's fence has passed. `writeScene` fills them before any pass is recorded: `drawScene` first settles every view's draws (`visibleDraws` and `batchByMesh` for the camera, `prepareShadowDraws` for the tiles).

## Clustered shading

Each pixel of the main pass loops only over the lights that may reach its cluster, instead of every light in the frame (phase 6c, `clustered-shading`). The maths is in `render/gpu/clusters` (API-free, tested in `clusters_test`) and `clusters.glsl` (mirrored, GPU-tested in `tests/gpu/clusters_gpu_test`); its numbers in `render/gpu/clusters_shared.h`.

The grid: `ClusterGrid` (`makeClusterGrid(camera, screenWidth, screenHeight)`, throws for an empty screen) cuts the view into square tiles of `clusterTilePixels` (64; the last column and row cut off by the screen's edge: 2560x1440 is 40 x 23 tiles) and each tile into `clusterDepthSlices` (24) depth slices spaced exponentially, slice k starting at near * (far / near)^(k / 24) (`sliceStartDepth`; each about 1.33 times deeper than the last for near 0.1 and far 100). Positions are in cluster view space: x right, y up, z the depth along the view (positive in front), measured from the camera (`toClusterView`, with the view matrix's rows as `right`, `up`, `forward`). A depth's slice is `floor(log(depth) * sliceScale + sliceBias)`, clamped to the grid (`clusterSlice`; 0 for depths at or behind the camera); clusters are numbered along a row, then down the screen, then slice by slice (`clusterIndex`); a pixel (from the top-left corner, like `gl_FragCoord`; the viewport flips y) finds its cluster with `clusterOfPixel`. `clusterBounds` is the box around a cluster's piece of the frustum (its eight corners; slice 0 starts at the camera), grown on every side by `clusterBoundsMargin` (0.001) times its far depth, so a pixel whose depth or tile rounds into a neighbour still finds every light that reaches it. Tests: the grid against the camera's own projection, the slices' spacing, the bounds.

The lists: one bit per light per cluster, `clusterWords` (40) words per cluster, the point lights' `clusterPointWords` (32, for `maxPointLights`) then the spotlights' `clusterSpotWords` (8, for `maxSpotLights`; both checked by `static_assert`), 160 bytes per cluster (`clusterMaskBytes`: about 3.5 MB at 2560x1440). A light's bit is set where its range sphere touches the cluster's box (`sphereTouchesBox`) and, for a spotlight, its cone (outer angle, range) touches the box's bounding sphere (`coneTouchesSphere`, Wronski 2016 "Cull that cone": the signed distance from the cone's slanted edge, `cos * across - sin * along`, then past the range or behind the apex; cones of 90 degrees or wider are only range tested). Both tests are conservative. `buildClusterMasks(grid, lights)` is the CPU mirror of the whole pass; the tests check the property everything rests on, that every light reaching a point is listed in that point's cluster (random lights around random points all over the view), and that lights are listed only near where they reach.

The pass: `cluster_lights.comp` (`GpuPass::Clusters`, CLUSTERS in F4; `clusterLightsPipeline`, a `ComputePipeline` on the scene's pipeline layout), one invocation per cluster in groups of `clusterGroupSize` (32), dispatched with `workgroupCount`. Lights are taken one word (32) at a time: each invocation of a group turns one light into cluster view space into shared memory, a `barrier()`, then every invocation tests its cluster against all 32 and writes its own word, another `barrier()` before the next word. Each light is read from its buffer once per group, no two invocations write the same word, and the result does not depend on which finishes first. Only words for the frame's light counts are written, and only those are read. It reads the frame's `FrameData` (the grid) and light buffers through set 1 and writes binding 11, `clusterMasks`: one `VulkanBuffer` in GPU memory (`BufferMemory::Gpu`), sized with the frame in `ensureFrameTextures`, shared by the frames in flight like the frame images. `buildClusterLists` records it after the debug UI and before the shadows, bound at the compute bind point, between two buffer barriers (`bufferBarrier(commands, buffer, before, after)` with `BufferUse{stages, access}`, `render/vulkan/buffer_barrier`): fragment shader (no access: a write after a read needs only the order) to compute shader storage writes, then compute storage writes to fragment shader storage reads. It runs when `RenderSettings::clusteredShading` (on, switchable live) or `clusterHeatmap` is on.

Shading: `triangle.frag`, when `shadingOptions.x`, finds its cluster's first word (`firstClusterWord`), and for each word up to the frame's counts walks the set bits lowest first (`findLSB`, then clearing it), calling `addPointLight` or `addSpotLight` (the per-light shading, unchanged, shared with the plain loops used when clustering is off). Lowest bit first is slot order, and every light that reaches the pixel is listed, so the pixel adds exactly the lights it added before, in the same order: all twelve golden images were identical bit for bit with clustering on and off. Each word is first OR-ed across the wave (`lightsOfTheWave`, `subgroupOr`, `GL_KHR_shader_subgroup_arithmetic`), so the pixels shaded together walk one list and read the same light records at once; a light from a neighbour's list cannot reach this pixel (it would be in its own list), so it adds nothing. `checkFormats` throws if the GPU lacks subgroup arithmetic in fragment shaders. The heatmap (`RenderSettings::clusterHeatmap`, off, a debug view; `shadingOptions.y`) mixes three quarters of `clusterHeatColour(clusterLightCount())` over the pixel: black for no lights, then blue, green, yellow and red at `clusterHeatmapLights` (16) and above (`clusterHeatRamp`, branch-free clamped lines). Seen on the golden views: the lamp field's near ground lists about 8 to 12 lamps per cluster and its far rows 16 or more, while only 4 to 8 reach any point (far slices are deep and grazing tiles cover a lot of ground); each extra listed light costs a pixel one distance check.

Measured (release, RTX 5080, 2560x1440, mean of 100 captures, main pass): lamp field 1.18 ms looped, 0.75 clustered (0.62 and 0.30 with point light shadows off: what remains is the soft shadows of the lamps that do reach), start 0.22 and 0.20, gallery 0.19 and 0.17, floodlights 0.30 both; the cluster pass 0.004 to 0.008 ms. Walking each pixel's own list instead of the wave's union measured the same at today's light counts. With every light seated (`defaultPointSeats = maxPointLights`, `defaultSpotSeats = maxSpotLights`), the lamp field draws all 88 lamps in view in 0.78 ms (the old loop: 1.40).

## Cascaded sun shadows

The brightest directional light (slot 0 after `prioritizeLights` ranks them by brightness; `maxShadowedDirectionalLights` = 1) gets `ShadowSettings::cascadeCount` (4, 1 to `maxShadowCascades`) box views, finest first, as tiles in a row from its `LightShadow::firstTile` (`LightShadow::cascades` says how many; `emitterRadius` holds tan of `DirectionalLight::angularRadius`, 0.00465 rad, the sun's). `render/gpu/cascades` (mirrored by `assets/shaders/cascades.glsl`, tested in `cascades_test` and `tests/gpu/cascades_gpu_test`):

- Splits: `cascadeSplits(near, far, count, lambda)` from the camera's near plane to `min(ShadowSettings::directionalDistance, far plane, fitted distance)` (200 m unfitted; see Fitted to the screen below), the practical scheme `lambda × logarithmic + (1 − lambda) × even` with `cascadeSplitLambda` 0.95 (about 3, 9, 36 and 200 m for a 70° 16:9 view); the ends set exactly.
- Fit: `cascadeSphere(camera, near, far)`, the slice's smallest bounding sphere, on the view axis at `(f + n)(1 + t²) / 2` (t² the sum of the squared half-width and half-height tangents), or at the far end's centre with radius `f t` when that is nearer; its radius depends only on the lens, so it is identical however the camera turns (tested with `==`). `cascadeBox(direction, sphere, casterReach, tileSize)`: a box looking along the light (`shadowViewUp`, shared with the spot and point views), its centre snapped to whole texels across the light, reaching `directionalCasterReach` (200) further towards the light; returns the GPU matrix, `depthRange` (2 r + reach) and `texelSize` (2 r / tile size).
- Tiles: `cascadeTilePixels(ShadowSettings::cascadeResolution)`, 1024, 2048 or 4096 (default `Pixels4096`, the Ultra preset). `shadowAtlasSizeFor(settings)` is the usual 8192 x 4096 atlas (squares of up to 2048) unless the cascades are 4096, when it grows by their 4 x 4096² texels to 8192 x 12288 (384 MB, squares of up to 4096; `ShadowAtlasSize` in `render/gpu/shadow_atlas`, which also holds the tile size constants). `planShadows` throws `std::invalid_argument` when its layout is for another size; `VulkanRenderer::ensureShadowAtlas`, called in `drawScene` before planning (so golden captures get it too), waits for the GPU, remakes the atlas image, the layout and the tile memory when the size changes, and the next set 1 points at the new image. Each cascade's `ShadowTileData`: the box times `translation(camera)` for the shader, `offset.y` = `normalOffsetTexels` × texel size, `lens` = (0, depth range, texel size, radius); a zero `lens.x` tells boxes from perspective tiles. Cached like every tile: a box that did not move (the camera moved under a texel) and whose casters did not change is not redrawn.
- Lookup (`sunShadow` in `triangle.frag`): for each cascade, finest first, the point moved towards the sun by `sunShadowBias(offset.y, n·l)` = base × (1 + min(tan θ, `MAX_SUN_BIAS_SLOPE` = 10), in `shader_shared.h`), then `cascadeEdgeDistance(projected, depthRange / radius)` (1 at the centre, 0 at any face of the box, in radii: across, and from the far and near sides); the first cascade with a positive edge distance is used. `cascadeBlendWeight(edge, band)` (`cascadeBlendBand` 0.1 of the radius; 0 switches at once) mixes in the next cascade near the edge, or full light past the last one; a point the next box misses stays with this one. `CascadeTransition::Dither` instead keeps one cascade per pixel (`cascadeDitherKeeps(weight, interleaved gradient noise)`), one lookup instead of two. Blend band and transition reach the shader as `GpuFrameData::cascadeOptions`.
- Why the bias moves along the light: an offset along the normal moves the point sideways as the sun sees it, by an amount that grows with the texel, so cascades of different texel sizes found a shadow's edge in different places (a visible step at the seam under a low sun). Moving along the rays changes only the depth in every cascade (`testMovingTowardsTheSunKeepsThePlaceInEveryCascade`). It also removed the stair-stepped edge of the sunlit room's window patch.
- Soft edges: `softShadowFromTile` handles boxes too: distances from the box's near side (`boxShadowDistance(depth, depthRange)`), blocker search `sunBlockerSearchTexels(tan, receiver, texel)` (a blocker at the near side), penumbra `sunPenumbraTexels(tan, receiver, blocker, texel)` = tan × (receiver − blocker) in the cascade's texels, clamped to 1-12 like the lamps'. The width is worked out in metres and converted per cascade, so it matches across a seam where the coarser cascade can show it.
- Measured texels for a 70° 16:9 view, 4096 (2048) tiles, unfitted: 0.22 (0.44) cm in the first cascade, 0.65 (1.3) cm to 9 m, 2.5 (5) cm to 36 m, 14 (28) cm to 200 m. A cascade's box is about 2.9 times its far distance across, so fitting the far end to the screen shrinks every one.
- Fitted to the screen (sample distribution shadow maps, Lauritzen 2011; `ShadowSettings::fitCascadesToDepth`, on): the cascades end at the farthest surface on screen instead of the shadow distance. Only the far end is fitted: starting the splits at the nearest surface pushes every split outwards and makes the nearest surfaces coarser. The measurement (`render/gpu/depth_range`, mirrored by `depth_range.glsl`; numbers in `depth_range_shared.h`): `depth_range.comp` (`GpuPass::DepthRange`, DEPTHS in F4) reads the depth image after the main pass (which then stores its depth, `drawMainPass(..., keepDepth, ...)`; the depth image is `SAMPLED` too and goes to `ImageState::DepthComputeRead`), each invocation a 2x2 square of pixels in 16x16 groups, keeping `ScreenDepthRange` {farthest bits, nearest bits}: reversed-Z, so the farthest surface has the smallest depth, and the far depth itself (0) is sky and skipped (`isSurfaceDepth`); positive floats' bits sort like the numbers, so `subgroupMin`/`subgroupMax` across the wave, shared-memory atomics per group and two global atomics per group combine them in any order. `VulkanDepthRange` (`render/vulkan/vulkan_depth_range`) owns the pipeline (`ComputePipelineDescription::sampledImages`: the depth at binding 1, the range buffer at 0), the range in GPU memory (reset by `vkCmdUpdateBuffer`, then copied) and a read-back buffer per frame in flight; `measure` records it, `collect(frameIndex)` reads it once after that frame's fence (`beginFrame`), so the CPU uses a measurement a frame or two late (`unusedDepthRange`). Depth to distance: `farthestSurfaceDistance` (`linearShadowDepth` with the camera's planes). The fit (`cascades.h`): `ShadowDistanceFit {optional step}`, the distance `shadowDistanceStep` (1.25) to the step's power in metres from 1 m; `fitShadowDistance(previous, farthest)` takes the step reaching `farthest × shadowDistanceMargin` (1.1, for the frames it is late), climbing at once but coming down only once the need is `shadowDistanceShrinkSteps` (2) steps lower, so the boxes keep one size (and stay cached) while the view moves a little; no surface (only sky) leaves it unfitted. `fittedShadowDistance` (infinity unfitted) goes to `planShadows(..., fittedSunDistance)`; `RenderStats::sunShadowDistance` shows where the cascades end (SUN TO on the F4 tile line). Golden captures first draw the frame once to measure it (`measureDepthsBeforeCapture`), then restore the light history, atlas layout and shadow cache, so a capture is still a first frame plus its measurement. Measured (RTX 5080): the sunlit room fits to 11.6 m, texels 0.032, 0.092, 0.27 and 0.81 cm (from 0.22, 0.65, 2.5 and 14); views reaching the horizon stay at 200 m. The pass costs 0.015-0.04 ms at 2560x1440; the main pass grew 0.06 ms in the demo's start view and 0.09 ms in the sunlit room, since a penumbra once under one texel now spans several and its samples spread wider in the atlas.

## Ray tracing

Hardware ray tracing through ray queries (phase 6d, `ray-queries`): any shader asks the GPU what a ray hits first and gets the distance, the instance, the triangle, its barycentric coordinates and whether it struck the front or the back. Optional: `VulkanDevice` turns on `VK_KHR_acceleration_structure`, `VK_KHR_ray_query` and `VK_KHR_deferred_host_operations` with their features when the GPU has them (`supportsRayQueries`, `getScratchAlignment`); without them `VulkanRenderer::rayTracing` stays null and everything ray-traced is off. Buffer device addresses (a buffer's place in GPU memory, which shaders follow like a pointer and structures are built from) are required, as Vulkan 1.3 itself requires them: `bufferDeviceAddress`, VMA's `BUFFER_DEVICE_ADDRESS` flag, `VulkanBuffer::getDeviceAddress`, `UploadArray::getDeviceAddress`. Every `VulkanMesh` buffer has `SHADER_DEVICE_ADDRESS` usage (and, with ray tracing, `ACCELERATION_STRUCTURE_BUILD_INPUT_READ_ONLY`), `getVertexAddress`, `getIndexAddress`, `getVertexCount`; its upload barrier also makes the data visible to fragment and compute storage reads and, with ray tracing, to structure builds.

API-free (`render/gpu/ray_tracing`, numbers in `ray_tracing_shared.h`, tested in `ray_tracing_test`): masks `solidRayMask` (1, shadow casters: they block light) and `visualOnlyRayMask` (2, the rest: the glowing faces of lights already counted directly, the sun disc, the moon, bulbs), `everythingRayMask`, `rayMaskFor(draw)`; `GpuRayInstance` (64 bytes, `VkAccelerationStructureInstanceKHR`'s layout, checked by `static_assert` in `vulkan_ray_tracing.cpp`: the model's top three rows row-major, the instance number (24 bits, `maxRayInstances`) under the mask, the record offset under the flags, the mesh structure's address) from `packRayInstance(draw, instanceNumber, meshStructure, flags)`; `hitsFrontFace(a, b, c, direction, handedness)` (the front is the side the corners turn anticlockwise when seen from; the GPU decides it in the instance's own coordinates, so a mirrored instance's outside stays its front; no instance flags needed, checked against the GPU); `RayDebugView` (Off, Normals, Albedo, Faces), `GpuRayDebugView` (80 bytes of push constants: right and up scaled by the tangents of half the view, forward, the camera's position with the view in w, the screen's size) from `packRayDebugView`, `cameraRayDirection` and `hitCornerWeights` (mirrored by `assets/shaders/ray_tracing.glsl`). `GpuInstance::material[1]` holds the draw's mesh number, so a hit finds its triangle's corners.

`VulkanRayTracing` (`render/vulkan/vulkan_ray_tracing`): one bottom-level structure per mesh, built at upload by `addMesh` (opaque triangles from the vertex and index buffers by address, 48-byte stride, `PREFER_FAST_TRACE | ALLOW_COMPACTION`; the compacted size read through a `ACCELERATION_STRUCTURE_COMPACTED_SIZE` query once the build is done, then copied into a buffer of that size with `COMPACT` and the original dropped; a barrier makes it readable by top-level builds and ray queries in later submissions), called by `VulkanRenderer::uploadMesh`. Scratch memory is allocated one alignment larger and its address rounded up (`createScratch`, `scratchAddress`). Each frame in flight has its own top-level structure, scratch, instance and mesh table `UploadArray`s and descriptor set (from a pool of exactly that many): `packInstances(draws)` (instance i is draw i; throws for a mesh without a structure) and `buildScene(commands, frameIndex, instances)` write the mesh table and the instances, grow the structure (from 256 instances, doubling) when needed, rebuild it from scratch every frame (simple, never stale; 0.05-0.11 ms for 29-900 instances on the RTX 5080), barrier it to fragment and compute ray queries, and rewrite the frame's set: binding 0 the structure, binding 1 the mesh table (`{vertices, indices}` addresses per mesh). `ray_scene.glsl` declares that set (set 2 by default, `RAY_SCENE_SET`), the buffers by address (`GL_EXT_buffer_reference_uvec2`: addresses as two 32-bit halves, so no 64-bit integers are needed; vertices read as a float array of `MESH_VERTEX_FLOATS` per vertex, since std430 would pad a struct of vec3s) and `meshSurfaceAt(mesh, triangle, barycentrics)` (the interpolated normal and texture coordinates in the mesh's own space).

The debug view (`RenderSettings::rayDebugView`, F5 Passes; Off by default): while it is on the renderer builds the frame's structure after the debug UI (`GpuPass::RayScene`, TLAS in F4) and, after the main pass, draws `ray_debug.frag` over the scene image (`GpuPass::RayDebug`, RAYS; `drawRayDebugView`, the scene colour discarded and redrawn), its layout the scene's two sets plus the ray tracing set and the camera as push constants (`rayDebugLayout`). One ray per pixel against every mask bit shows the hit's world normal (through the instance's normal matrix), its albedo (`materials.glsl`, the colour texture's full-size level times the base colour) or its facing (front green, back red, shaded by the angle), misses dark grey. The scene layout's instance binding is visible to fragment and compute shaders for it (and materials to compute), for DDGI later. Measured at 2560x1440: 0.09-0.28 ms for one primary ray per pixel.

## Depth and camera-relative rendering

Reversed-Z (`render/gpu/gpu_depth_range`): `toGpuDepthRange(projection)` turns OpenGL clip depth (-w..w, what `Mat4::perspective` and `Mat4::orthographic` give) into the GPU's reversed w..0 (correction row: depth = 0.5 w - 0.5 z), so the near plane is stored as `gpuNearDepth` (1) and the far plane as `gpuFarDepth` (0), both from `render/gpu/depth_shared.h` (`GPU_NEAR_DEPTH`, `GPU_FAR_DEPTH`, read by `fullscreen_triangle.vert` too). Every GPU projection goes through it (the camera, point and spot shadow faces, the sun's cascade boxes, the debug lines' screen pixels), so the whole renderer shares one convention: depth tests `GREATER` (main and shadow pipelines), the main depth image is cleared to `gpuFarDepth`, shadow tiles are reset to it, the shadow sampler compares `GREATER_OR_EQUAL`, the blocker search counts stored depths greater than the receiver's, and `linearShadowDepth` is `f n / (n + depth (f - n))`. Why: perspective depth goes as 1/distance and float values are densest near 0, so with the far plane at 0 the two nearly cancel and precision is close to even over the view (two surfaces 1 cm apart at 1 km get about 270 floats between their depths; with the far plane at 1 they got the same depth; `gpu_depth_range_test`). `Frustum::fromClipMatrix` takes `ClipDepth::OneToZero` for GPU matrices (planes 4 and 5 stay near and far); the far plane stays finite (an infinite one would need a separate draw distance for culling and shadow fitting).

Camera-relative rendering (`render/gpu/camera_relative`): everything the main pass's shaders see is measured from the camera along the world's axes. `cameraRelativeViewProjection(camera)` is the camera's view-projection with the camera moved to the origin (rotation only), and `triangle.vert` subtracts the camera position (`GpuFrameData::cameraOrigin`) from each instance's world model matrix's translation before any product, which is exactly `relativeTo(model, cameraOrigin)` (checked in `gpu_scene_test`), then multiplies by the relative view-projection; the normal matrix is unchanged. `triangle.vert` outputs `relativePosition`, `packLighting` subtracts the camera from point and spot positions, and each `ShadowTileData::matrix` is the tile's view for camera-relative points: point and spot faces are built again from `position - camera` (one subtraction on positions, before any matrix), each cascade box is its world matrix times `translation(camera)` (it is snapped to texels in world space, so it must not be rebuilt around the camera). The shadow pass itself still draws with the world matrices in `ShadowTile::matrix`, because the shadow cache recognises tiles by their matrix and casters: camera-relative drawing would redraw every cached tile whenever the camera moved. Culling, light priority and the debug lines also stay in world space (`VulkanRenderer::viewProjection`, next to `relativeViewProjection` and `cameraOrigin`). Why: 12 km from the origin a float's steps are about 1 mm, and multiplying a view matrix holding -camera by a model matrix holding +object subtracts two such rounded numbers; measured there, the world-space path missed the exact screen position by about a quarter of a pixel on a 1920-pixel-wide screen (visible as shimmer), the relative path by about 20,000 times less (`camera_relative_test` asserts at least 20). Positions are still floats in the `World`, so phase 13 moves the subtraction to doubles.

## Assets and materials

Assets: `MeshHandle` and `TextureHandle` (`scene/asset_handles.h`) are typed indices; a default handle means "none" (no texture = plain colour). `AssetManager` (`assets/`) owns CPU-side meshes, images and imported models, loads each file once (`loadMesh` for OBJ, with optional `MeshLoadOptions{.smoothNormals, .creaseAngle}` that are part of the cache key, `loadTexture` by path+flip or embedded buffer, `loadModel` for glTF, which returns a stable `const Model&`), and gives the same handle for the same shared mesh pointer. Assets are append-only, so handles never go stale (add a generation like `Entity` if unloading is added). Loaders produce `Model`s whose parts hold a shared `Mesh` and a `MaterialSource` (colour, `metallic`, `roughness`, linear `emissive`, and three `TextureSource`s, `colourTexture`, `metallicRoughnessTexture` and `normalTexture` (with `normalScale`, glTF's `normalTexture.scale`, default 1), each a path or embedded bytes, sharing one flip); `AssetManager::makeMaterial` turns that into a `Material` (colour + `TextureHandle`, `metallic` 0 and `roughness` 0.5 by default (the old Blinn-Phong default, shininess 32, matches roughness 0.5), an optional `metallicRoughnessTexture` (glTF packing: roughness in green, metallic in blue, multiplying the numbers), an optional linear `normalTexture` with `normalScale`, and `emissive`), loading the colour texture as `TextureEncoding::Srgb` and the metallic-roughness and normal ones as `Linear` (`AssetManager::loadTexture(TextureSource, flip, encoding)`; the encoding is part of both texture caches' keys and is stored in `ImageData::encoding`). The glTF loader reads `metallicFactor`, `roughnessFactor`, the metallic-roughness texture, the normal texture and its scale, `emissiveFactor` and `KHR_materials_emissive_strength` (`readTexture` handles both textures, files and embedded alike); a part with no material gets glTF's defaults, metallic and roughness 1. `packMaterial` (`render/gpu/material_uniforms`) turns a `Material` into `GpuMaterial`, which mirrors the shader's `MaterialData` struct (64 bytes, std430: base colour, `surface` = metallic and roughness clamped to 0..1 and the normal scale (0 when there is no normal texture, so the white stand-in tilts nothing), emissive, and `textures`: the slots of the colour, metallic-roughness and normal textures in the bindless array, `bindlessTextureSlot` = handle + 1, `whiteTextureSlot` 0 for none), one entry per different material in the frame's material buffer (see GPU scene).

## Input

`Input` is a once-per-frame snapshot with no SDL dependency: `isKeyHeld`, `wasKeyPressed`, `wasKeyReleased` take an engine `Key` (`key.h`, physical US-layout positions), plus accumulated `getMouseDelta`. Mouse buttons (`MouseButton`) work like keys, and each press is also recorded as a `MouseButtonPress` with the exact event position (window pixels) and timestamp (ns, `SDL_GetTicksNS` clock): use `getLastMouseButtonPress` for clicks, `getCursorPosition`/`isCursorInWindow`/`getWindowSize` for continuous things. It is filled through `pressKey`/`releaseKey`/`pressMouseButton`/`releaseMouseButton`/`addMouseMotion`/`setCursor`/`setWindowSize`. `sdl_input` is the only SDL-to-engine translation (`keyFromScancode`, `mouseButtonFromSdl`, `applySdlEvent`, which also drops key repeat). `Window::processEvents(input)` resets and fills it. Mouse motion is only forwarded while the mouse is captured, and is discarded when capture or control mode changes. Game code reads keys from `Input` as `Key` values, never SDL scancodes or `SDL_GetKeyboardState`.

## Entities and components

Entities and components (`ecs/`): an `Entity` is an index plus a generation (handles to destroyed entities go stale even after their slot is reused; `Entity{}` is never alive and means "none"). `World` creates/destroys entities and stores one `ComponentStorage<T>` (sparse set: packed `components`, owning `entities`, and a `sparse` index) per component type. Components are plain structs; systems are free functions run with `world.each<A, B>([](Entity, A&, B&) { ... })`, which walks the first type's packed array, so list the rarest component first. Inside `each`, `destroy` and `remove<T>` are deferred: the `World` counts running walks (`activeWalks`, also per storage in `ComponentStorageBase::activeWalks`; they nest, and the const `each` counts too) and queues them as type-erased `PendingChange`s, applied in order by `applyPendingIfIdle` when the outermost walk ends (also when a system throws, so the world never stays locked); until then the entity and its components stay visible. `create` is always immediate. `add<T>` throws `std::logic_error` while a walk over `T` runs; `addLater<T>` adds at once outside a walk and queues inside one (skipped if the entity is dead by then). A queued destroy of a dead entity is a no-op. Tests: `deferred_changes_test`.

## Components today

Components today (`ModelRenderer` also has `castsShadows`): `Transform` (`math/`: `position`, `rotation` as a unit `Quat` (`math/quat`, x y z w as glTF; `a * b` turns by b first, then a, like matrices; Euler angles only describe poses, through `Quat::fromEulerAngles`, x first, then y, then z), `scale`; `getMatrix` is translation times rotation times scale, written out directly), `PreviousTransform`, `ModelRenderer`, `DirectionalLight`, `PointLight`, `SpotLight`, `AmbientLight` and `SkyBackground` (`scene/`), `Spinner`, `Firefly`, `CharacterMovement`, `FirstPersonBody` and `Grenade` (`gameplay/`), `Collider`, `CharacterController` and `Particle` (`physics/`). `ModelRenderer` is a list of `RenderPart`s (mesh, material, `localTransform` with the model's normalization folded in) plus `visible`; a multi-part model is one entity. Parts hold a `MeshHandle` and a `Material`, so the component is small and copyable. Build with `assets.makeModelRenderer(model, normalization)` or `makeMeshRenderer(meshHandle, material)`.

## Main loop

Main loop: `FixedTimestep` (120 Hz and frame time clamped to 0.25 s by default, from `EngineSettings`) turns real frame time into a whole number of ticks plus an interpolation `alpha`. Each frame: `game.onInput` turns input into commands, `runFixedUpdate` runs zero or more ticks, `game.onUpdate` moves the camera, then `render(alpha)`. Never read `Input` inside a tick; key/click edges are handled once per frame and reach the simulation as commands. Mouse look and camera movement are per frame, not per tick.

## Each tick

Each tick: `savePreviousTransforms` (engine), then `DemoGame::onFixedUpdate` runs `updateCharacters`, `updateFirstPersonBodies`, `updateSpinners`, `updateFireflies`, `moveParticles` and `updateGrenades` in that order (spinners and fireflies compute their pose from the total simulation time, so no error builds up; a `Spinner` keeps Euler `initialAngles` and per-axis `speed` and sets the whole rotation with `Quat::fromEulerAngles`; `DemoGame` keeps `latestSimulationSeconds` so lamps created between ticks start mid-flight). Determinism: the same build given the same commands reaches a bit-identical state; `hashSimulationState(world)` (`engine/state_hash`) hashes every component ticks change (Transform, PreviousTransform, CharacterController, CharacterMovement with `MoveToController::getTarget` and `yaw`, FirstPersonBody, Particle, Grenade) field by field with `Fnv1aHash` (`core/hash.h`, shared with `shadowCasterSignature`), and `determinism_test` plays a scripted demo (walking, jumps, grenades, the lamp field, MOBA right-click) in two worlds and compares the hash every frame, plus a third world one grenade throw short that must differ, and the same for the light lab (walking with the sun's clock running, jumps, a drop in from the free camera; the one-jump-short world is compared before the drop, which puts every run's body in the same place). A new component that ticks change must be added to the hash. Interpolation: only entities that move continuously get a `PreviousTransform`; `getRenderTransform(world, entity, alpha)` blends it with `Transform` (`interpolate` lerps position and scale and `slerp`s the rotation, the short way round), and entities without one are drawn at their `Transform`. Things that teleport (the destination marker) therefore have no `PreviousTransform`. Create moving entities with `PreviousTransform` equal to their starting `Transform`.

## Cameras

Cameras: `Camera` (`scene/`) is a plain lens: position, forward, up, vertical FOV, aspect, near/far; view and projection matrices are built on request, so `setVerticalFov` works (aim-down-sights zoom). It has no movement logic. Controllers in `gameplay/camera/` move it, each a concrete class with no shared interface (a real game uses one): `FreeFlyCameraController` (look + fly, Space/Ctrl up/down; holding Shift multiplies its speed by `LookSettings::sprintMultiplier`, 2; it uses `look_controls`' shared `turnCamera` and `moveCamera`, and the first-person controller only `turnCamera`: walking, and its 1.5 sprint, belong to the first-person body), `FirstPersonCameraController` (look only: mouse turns it every frame; the game places it at the first-person body's eyes), `MobaCameraController` (fixed-angle offset; follows an optional target, otherwise edge-pans while the cursor is confined). Look controllers store yaw/pitch as `ViewAngles` (spherical coordinates, yaw 0 = -Z, positive yaw turns right, pitch clamped to 89 degrees) and pause while the mouse is not captured; `takeOver(camera)` continues from the camera's current direction.

## Characters

Characters: `spawnCharacter(world, assets, model, config, position)` creates an entity with `Transform` (its position is the feet), `PreviousTransform`, `ModelRenderer`, `CharacterMovement` (a `MoveToController` plus turning state; `moveTo`/`stop`/`isMoving`), a fitted `Collider` capsule and a `CharacterController` with `CharacterConfig::controller` (validated: positive radius, height at least two radii). `updateCharacters(world, level, dt)` sets each controller's `wishVelocity` from `MoveToController::desiredVelocity(position, dt)` (across the ground at `speed`, cut on the last step to land exactly; zero with no target or time), runs `moveCharacter`, calls `updateArrival` (stops within `arrivalDistance`, 1e-4; a wall in the way means it never arrives: no path finding) and turns `CharacterMovement::yaw` towards the displacement at `turnSpeed`, then writes the Transform's rotation from it as a turn about +Y (the yaw is the character's own angle: set it, not the Transform, to face a character somewhere); `getCharacterVisualCentre(world, entity, alpha)` gives the interpolated camera target and `getCharacterFacing` the model's forward axis turned by the interpolated rotation. `math/ray` provides `Ray` and `intersectGround`; `scene/camera_ray` provides `makeCameraRay`. Together they turn mouse clicks into ground positions.

## Collision, particles and the character controller

Collision (`physics/`): shapes live in one shared (world) space: `Sphere` (centre, radius), `Capsule` (segment `a`-`b` grown by `radius`; `a == b` is a sphere) and `Aabb` (`math/aabb`, also used for mesh bounds: `meshBounds`, `Model::getBounds`); `Shape` is a `std::variant` of the three. `overlaps(a, b)` exists for every pair in either order and for two `Shape`s (`std::visit`); touching counts as overlapping. Rounded shapes reduce to closest points between their cores (`math/closest_points`: `closestPointOnSegment`, `closestPointInBox`, `closestPointsBetweenSegments` after Ericson, and `closestPointsSegmentBox`, which cuts the segment where it crosses the box planes and minimises each quadratic piece exactly), compared with the summed radii. Raycasts (`physics/raycast`): `raycast(ray, Sphere | Capsule | Aabb | Shape | TriangleMesh, maxDistance = unlimitedRayDistance)` returns `std::optional<RayHit>` (`distance` in world units, the direction is normalised inside; `point`; unit `normal` always against the ray). Starting inside a shape hits at distance 0 with the normal opposite the ray; a zero direction hits nothing. Spheres and capsule ends solve the ball quadratic, the capsule side drops the motion along its axis, boxes use slabs (the latest entry axis is the face), triangles use Moller-Trumbore from both sides and keep the nearest. `TriangleMesh` (`physics/triangle_mesh`: `positions` plus 3 `indices` per triangle, usually in world space) is built by `collisionMesh(mesh, transform)` (`scene/collision_mesh`, which checks indices). `Vec3::operator[]` reads x, y, z by index for per-axis loops. Colliders (`physics/collider`): the `Collider` component is a `Shape` in the entity's own coordinates plus an optional `std::shared_ptr<const TriangleMesh> detail` (exact triangles, same coordinates, shared between entities; the shape must enclose them). `worldShape(shape, model)` moves a shape by a model matrix: points exactly, radii times the largest column length of the 3x3 part (exact for a `Transform`'s rotation times scale), boxes to the axis-aligned box around the turned box (half-size `sum_j |A_ij| h_j`). `triangleMeshBounds`, and `meshCollider(mesh)` (box around the mesh plus the mesh). `raycastColliders(world, ray, RaycastDetail::Shapes | Triangles, maxDistance)` (`physics/collider_raycast`) builds a `CollisionScene` and asks it once (current poses, not interpolated); the nearest `ColliderHit{entity, hit}` wins and shrinks the reach; in `Triangles` mode a shape hit must be confirmed by `raycast(ray, mesh, model, maxDistance)`, which carries the ray into the mesh's coordinates with `affineInverse` (`math/mat4`: `[A t; 0 1]^-1 = [A^-1, -A^-1 t; 0 1]`, `A^-1` from the cofactors `normalMatrix` also uses, nothing for a flat matrix), scales distances by world length per local length along the ray, and brings the normal back through `normalMatrix`; a ray that slips between the triangles goes on to what is behind. `transformPoint` and `transformDirection` (`math/mat4`) apply a matrix with w = 1 or 0. `appendCollisionMesh` (`scene/collision_mesh`) adds a mesh to an existing `TriangleMesh` with shifted indices, and `AssetManager::makeCollisionMesh(renderer)` merges every part of a `ModelRenderer` (placed by its `localTransform`) into one. `spawnCharacter` gives characters a `Collider` capsule fitted to the drawn model (radius half its wider horizontal side, feet to head), with no detail. `DebugDraw::shape(shape, colour)` draws any `Shape`; `drawColliders(world, alpha, debug)` (`engine/debug_views`, interpolated pose, `colliderDebugColour` orange) runs in the F4 view. Broad phase: `UniformGrid` (`physics/uniform_grid`; cells of `CollisionSettings::gridCellSize`, default 2, `cellOf` uses floor; a `std::unordered_map` of occupied cells with the Teschner hash; an item goes in every cell its box touches, or on the large list past `largeItemCells`, 64; `clear` keeps memory and drops cells unused since the previous clear; mailboxing with per-item query numbers (`seenBy`, mutable, so not thread-safe); `query(region, found)` keeps items whose own box overlaps; `walkRay(ray, reach, visit)` (template, in the header) visits large items, clips the ray to the occupied cells' box, then steps cells near to far (Amanatides and Woo: `tMax`, `tDelta`) and stops when the next crossing is beyond the reach `visit(item, reach)` returns, returning `GridRayWalk{cells, items}`). `CollisionScene` (`physics/collision_scene`, owns `CollisionSettings`, read at each `rebuild(world)`, which clears and refills from every `Collider` + `Transform`: world shape, model matrix, detail) answers `raycast(scene, ray, detail, maxDistance, CollisionQueryStats*)` (narrow phase per visited collider; a triangle miss leaves the reach) and `overlapping(scene, shape)` (shapes only). Rebuilding rather than updating is deliberate: the ECS has no change tracking, so incremental updates could leave ghost entries. `boundsOf(Shape)` (`physics/shapes`). `debugReadoutLine(n)` and `debugReadoutTextHeight` (`engine/debug_views`) place readout lines; the engine uses 0-6 (`videoMemoryReadoutLine` 4 the video memory, `engineProfileReadoutLine` 5 its CPU timings, `gpuProfileReadoutLine` 6 its GPU timings per pass) and a game starts at `firstGameReadoutLine` (7). Profiling: `Profiler` (`core/profiler`, plain C++ so games and tests stay headless) has numbered sections (`addSection` once, `record(section, seconds)`), counts per call and publishes each section's average, worst call and call count (`SectionTiming`) when `update(now)` (once a frame) finds a window (`defaultProfileWindowSeconds`, 0.5) has passed, zeros for a section that did not run; `profilerSeconds()` is `steady_clock` in seconds; `ScopedTimer` records its block and `timeSection(profiler, section, work)` times a callable. `Application` owns one (FRAME, WORK = frame minus the cap's sleep, TICK per tick, UPDATE, SCENE = building the frame and debug lines, RENDER = `renderer.render`, which includes waiting for the GPU) and draws it with `drawProfile` (`profileText`: name, average/worst ms); `DemoGame` times each system in `onFixedUpdate` into its own `systemTimes`, advanced in `onUpdate` and drawn on the first game line (averages, three decimals). Static level (`physics/static_level`): `StaticLevel` holds everything that never moves as one world-space `TriangleMesh` plus its own `UniformGrid` over triangle numbers, built as `add(piece, model)` is called (validated first, so a bad piece changes nothing) and never rebuilt; cell size from the `CollisionSettings` given at construction. `raycast(level, ray, maxDistance, stats)` walks the grid with `raycastTriangle` and returns `LevelHit{hit, triangle}`; `contacts(level, capsule)` queries the grid with `boundsOf` and returns a `Contact{point, normal, depth, triangle}` (`physics/triangle_contact`) per touched triangle (touching counts, depth 0). `contact(capsule or sphere, a, b, c)`: nearest points between core and triangle (`closestPointsSegmentTriangle`: a piercing crossing, else the best of both ends against the triangle and the segment against each edge; `closestPointOnTriangle` by Voronoi region, Ericson 5.1.5, nearest edge for a flat triangle), normal from triangle to core and depth radius minus distance; a core touching the triangle uses the face normal on its middle's side and depth = deepest end behind the plane + radius. Triangles are two-sided. `raycastTriangle` (`physics/raycast`) is the one Moller-Trumbore test, shared with mesh raycasts; its barycentric checks allow `edgeTolerance` (1e-5) outside 0..1 so rays through a seam shared by two triangles cannot slip between them (a demo bug, kept as a bit-exact regression test). `CollisionQueryStats{tested, cellsWalked}` lives in `physics/query_stats`. Sphere sweeps: `sweepSphere(sphere, motion, a, b, c)` (`physics/raycast`) is the first touch of a moving sphere against one triangle: the centre's path raycast against the triangle grown by the radius (two faces offset along the normal plus a `Capsule` per edge); a sphere already touching hits at distance 0 with the contact normal if moving into it (more than `glancing`, 1e-5) and ignores it otherwise; the hit's `point` is the centre at the touch, its normal from the triangle to the centre. `sweepSphere(level, sphere, motion)` (`physics/static_level`) queries the grid with the box round the start and end spheres and returns a `LevelHit`. Not built: box against triangle (separating axes), capsule and box sweeps. Particles (`physics/particle`): `ParticleSettings` (radius 0.1, gravity 9.81, restitution 0.45, friction 0.4, restingSpeed 1, maxBounces 4); the `Particle` component (settings, `velocity`; the `Transform` position is the centre). `fly(velocity, acceleration, seconds)` returns a `FlightStep` moved by the average of the start and end velocities, exact for constant acceleration. `bounceVelocity(velocity, normal, settings)`: the normal part comes back times restitution (0 below restingSpeed), friction slows the sliding part by at most friction (1 + e) times the speed in, never reversing it (resting contact therefore decelerates at mu g). `moveParticle(particle, centre, level, seconds)`: push out of overlaps (deepest first, ending `clearance` 1e-3 clear); if a surface within 2 clearance is moved into, gravity is added at once and the surfaces push back (`pressAgainstTouching`) and the ball moves at the result, otherwise it flies under gravity; then sweeps, stopping `clearance` off each surface hit, bouncing with the velocity at the moment of the hit (share of the path stands in for share of the time) and flying on, up to maxBounces. A resting ball stays exactly still. `moveParticles(world, level, seconds)` for every `Particle` + `Transform`. Grenades (`gameplay/grenade`): `GrenadeSettings` (throwSpeed 15, lifetimeSeconds 5, `particle`), the `Grenade` component (`secondsLeft`), `throwGrenade(world, from, direction, looks, settings)` (Transform scaled to the radius, PreviousTransform, the looks, a unit `Sphere` `Collider`, a `Particle` with velocity along the normalised direction, the thrower's velocity not added), `updateGrenades(world, seconds)` destroys expired ones inside its `each` (deferred by the `World`). `Contact::faceNormal` is the triangle's own normal turned to the shape's side (equal to `normal` on the face, different on an edge or corner). Character controller (`physics/character_controller`): `CharacterControllerSettings` (radius 0.4, height 1.8, maxSlopeDegrees 45, stepHeight 0.3, snapDistance 0.3, gravity 17.5, maxFallSpeed 30, jumpSpeed 5.72 (Overwatch's community-measured values), groundAcceleration 100, airAcceleration 30 (guesses to tune by feel), substepFraction 0.5, pushOutPasses 8); the `CharacterController` component holds the settings, the commands `wishVelocity` and `wantsJump` (used up by the next tick, honoured only on the ground) and the state `velocity`, `grounded`, `groundNormal`, `lastSubsteps`, `groundKnown` (a new controller probes the ground on its first tick). `controllerCapsule(settings, feet)`. `moveCharacter(controller, feet, level, seconds)`: jump first (so take-off uses air rules); `steer` (ground: `moveTowards` the wish at groundAcceleration; air: no wish keeps momentum, steering at airAcceleration keeps the speed, up to the wished speed, for turns of 90 degrees or less); vertical velocity by semi-implicit Euler with quadratic drag while falling (`a = -g + (g / v_t^2) v^2`, v_t = maxFallSpeed); grounded movement is the horizontal velocity tilted into the ground plane and rescaled to full speed (slopes walked at the same speed); substeps of at most radius * substepFraction (64 at most), each followed by `pushOut` (deepest contact first, re-queried each pass: contacts that `supports` the character push straight up by depth / normal.y and stop falling; others push along the normal and remove the velocity into it, steep upward normals only sideways while walking). `supports`: a walkable face (normal.y >= cos maxSlope), or an edge or corner contact (normal differs from `faceNormal`) facing up at least `leastStepNormalY` no higher than stepHeight above the feet, so the capsule rides up low ledges (no separate step-up move). Then, if it was grounded and did not jump, `descend` settles it onto the ground up to snapDistance in `descentIncrement` (0.05) drops, pushing out at the first overlap (dropping the whole way at once let a kerb's edge win the push-out and shove it sideways), which also removes hovering; `groundUnder` (contacts of the capsule lowered `groundProbeDistance`, 0.01, that support it) decides `grounded` and `groundNormal`. `moveCharacters(world, level, seconds)` runs it for every `CharacterController` + `Transform`. `degreesFromRadians` joins `math/angles`.

## Meshes and colour

Meshes: `Mesh` (`scene/`) is the import format: `Vec4` positions plus triangles with an optional normal, UV and tangent per corner, and `uvOrigin` (`UvOrigin::BottomLeft` for OBJ and code, `TopLeft` for glTF). Loaders, bounds and the software renderer use it. `buildIndexedMesh` (`scene/indexed_mesh`) turns it into the render format, `IndexedMesh`: unique `MeshVertex` (position, normal, UV, tangent: 48 bytes, the exact GPU vertex layout, read with `offsetof`) plus 32-bit indices. `resolveCorners` gives each corner its file normal or its face normal, its UV or (0,0), and its tangent; `buildIndexedMesh` then merges corners identical in every component (the key normalises -0.0 to +0.0). Files without normals stay flat shaded, so their corners rarely merge, unless loaded with `smoothNormals`: `generateSmoothNormals(mesh, creaseAngle)` (`scene/smooth_normals`) fills in missing corner normals by averaging the faces around each position (grouped by exact position, so seams with duplicated vertices smooth too), weighted by corner angle, counting only faces within the crease angle (default 60 degrees) of the corner's own face. It is opt-in because only the game knows whether a shape is meant to be faceted. `faceNormal` lives in `scene/mesh`. Tangents (`MeshVertex::tangent`: xyz the unit direction of increasing u, w = ±1 with the bitangent "up the picture" = w · (N × T)) come from the file when every corner has one (glTF `TANGENT`, normalised, w must be ±1), else from `generateTangents(corners, origin)` (`scene/tangents`): vendored MikkTSpace (`external/mikktspace`, compiled as C99 by its own makefile rule) on the unshared corners, given (u, 1 − v) for `TopLeft` meshes so the bitangent points up the picture as Blender's exporter makes it (`tangents_test` regenerates NormalTangentMirrorTest's exported tangents and matches at least 99% of corners, signs included); a mesh whose UVs are all equal gets any tangent across each normal with sign +1, and MikkTSpace's placeholder for UV-less patches is put across the normal by one Gram-Schmidt step. Mirror seams (same position, normal and UV, opposite sign) stay separate vertices. The engine builds the `IndexedMesh` once when a mesh is first uploaded; `VulkanMesh` only validates (`checkMeshUpload`) and uploads it. Colour is gamma-correct: shading happens in linear light. `VulkanTexture` takes a `VulkanTextureDescription` (format, bytes per texel, and `surface`: a full mip chain, repeat and anisotropy, or else a one-level clamped lookup table); `surfaceTexture(encoding)` gives `R8G8B8A8_SRGB` for colour (the GPU decodes texels when sampling and when averaging mips) or plain `R8G8B8A8_UNORM` for data (metallic-roughness and normal maps); `VulkanRenderer::uploadTexture` takes the `TextureEncoding`, and `textureOrWhite` picks a material's texture or the white stand-in (white multiplies colours and factors by 1); the SDR swapchain has an sRGB format that encodes on write (`B8G8R8A8_SRGB`, see VulkanRenderer). `Material::colour` bytes are sRGB like image files; `packMaterial` decodes them with `srgbByteToLinear` (`core/srgb`). glTF colour factors are linear, so the loader encodes them with `linearToSrgbByte`. Light colours, intensities and `emissive` are linear. `VulkanTexture` uploads RGBA pixels with a full mip chain (`mipLevelCount`, `render/gpu/mip_levels`; each smaller level blitted from the one above) and samples them with trilinear and 16x anisotropic filtering (the sampler's `maxLod` is `VK_LOD_CLAMP_NONE`: 0 would lock sampling to the full-size level). `Material::emissive` (a `Vec3`, black by default) is light the surface gives off itself, added after lighting; with a black `colour` the surface shows only its glow and never changes with lighting (the demo's moon and MOBA marker). `GpuMaterial` is 64 bytes. `Mesh::sphere(segments, rings)` builds a unit UV sphere with smooth normals.

## Loaders

Loaders: `obj_loader` (quads/convex polygons, normals, UVs), `gltf_loader` (cgltf; returns a `Model` of `ModelPart`s with world transforms, the material (see Assets and materials) with its textures external or embedded in `.glb`, and per-corner normals, UVs and tangents). Occlusion and emissive textures are ignored for now. glTF texture transforms are not supported.

## Software renderer

Software renderer (reference path, used only by tests): `Renderer`, `Display`, `PixelBuffer`, `DepthBuffer`, `rasterizer`, `clipper`, `shading`. It does flat shading only and ignores per-vertex normals and UVs.

## Light, HDR, tone mapping, bloom and shading

lights are components (`scene/light.h`): `DirectionalLight` (stores the direction the light travels; no `Transform` needed), `PointLight` (position from the entity's `Transform`, fades to exactly zero at `range`, `sourceRadius` like a spotlight's, packed into `radiance.w`), `SpotLight` (a point light in a cone: stores its `direction`, full brightness inside `innerAngle`, smoothly fading to zero at `outerAngle`, and a `sourceRadius` that softens the falloff up close, `intensity / (d² + r²)`; the shader compares cosines, which `packLighting` precomputes and clamps inner to outer) and `AmbientLight` (several add up). `SkyBackground` lights nothing: its colour (linear, several add up, black without one) becomes `FrameLighting::background`, the colour the main pass clears the scene image to, so it shows wherever nothing is drawn; a stand-in for 6d's sky. Colours are 0..1 tints with a separate unbounded `intensity`. Each frame `buildFrame` calls `collectLighting(world, alpha)` (`scene/lighting`, point light positions interpolated like meshes) and `VulkanRenderer::drawScene` (after `prioritizeLights`) uses `packLighting` (`render/gpu/light_uniforms`) to fill `LightUniformData` and pushes it once to fragment uniform slot 1. That struct mirrors the `LightData` block in `triangle.frag` byte for byte (all `vec4`, `static_assert` 2720 bytes); light positions are measured from the camera (`packLighting(lighting, cameraPosition)` subtracts it), so the viewer sits at the shader's origin and has no field. HDR and tone mapping: `triangle.frag` writes unbounded linear colour into `sceneColour`, an `R16G16B16A16_SFLOAT` texture the size of the frame (made with the depth texture in `ensureFrameTextures`); a final pass (`beginToneMapPass`, `fullscreen_triangle.vert` + `tone_map.frag`, `ToneMapUniformData` at fragment slot 0, the scene read with `texelFetch`) multiplies by `ToneMappingSettings::exposure` (1.5, so scenes tuned for the old clipped look keep their shadows and mid-tones), applies the curve (`ToneMapCurve`: `Clamp`, the pre-HDR look; `Reinhard`; `Aces`, Narkowicz's fit; `AgX`, the default, Wrensch's minimal form) stretched to the screen's peak (`peak * curve(x / peak)`, `sdrPeakBrightness` 1 on an SDR screen), and writes the swapchain, times the white level. HDR output: before acquiring each frame, `updateDisplayOutput` reads the window's `SDL_PROP_WINDOW_HDR_ENABLED_BOOLEAN`, headroom and SDR white level (`readWindowDisplay`; whether an `EXTENDED_SRGB_LINEAR` swapchain is supported is asked only when HDR comes on) and `chooseDisplayOutput` picks `DisplayOutput{hdr, peakBrightness, whiteLevel}`: HDR when `DisplaySettings::hdrOutput` and the screen allow it, white at `paperWhiteNits / 80` (scRGB's 1 is `scrgbWhiteNits`, 80) or Windows' level, the peak at `peakNits` or the monitor's (headroom times its white), never past the monitor's nor below white, in units of white. When `hdr` changes `prepareSwapchain` waits for the GPU, rebuilds the swapchain in the other format and colour space (keeping the present mode; a refused HDR swapchain is logged and marked unsupported) and rebuilds the swapchain-format pipelines (`createScreenPipelines`: tone mapping, debug lines and the overlay), logging the peak and white. `ToneMapUniformData` (32 bytes) carries the white level and whether to dither (only on SDR), plus the bloom strength (`parameters.w`, 0 = none) and scale (`output.z`); debug line colours are multiplied by the white level (`buildDebugLineVertices(lines, colourScale)`). Bloom (`render/gpu/bloom`, `BloomSettings`: `enabled`, `strength` 0.04, `radius` 1, `fireflyReduction`, `maxLevels` 6 of at most `BLOOM_LEVEL_LIMIT` 8): between the main pass and tone mapping, `VulkanBloom` (`render/vulkan/vulkan_bloom`, owned by `VulkanRenderer`) halves the scene down a chain of separate `B10G11R11_UFLOAT_PACK32` images (16-bit float if unsupported; separate textures, not mips, so a pass never reads what it draws into), level 0 half the frame, `bloomLevelCount` stopping before a side drops below `BLOOM_SMALLEST_LEVEL_SIDE` (4), with `bloom_downsample.frag` (Jimenez's 13-tap filter as five weighted 4x4 boxes; the Karis average, boxes weighted by 1 / (1 + luminance) and renormalised, on the first halving only), then grows it back with `bloom_upsample.frag` (3x3 tent, reads `radius` texels apart, additive blending onto the level's own halving). `tone_map.frag` reads level 0 with a linear sampler (fragment sampler slot 1; the scene stands in when there is no bloom) and mixes `mix(scene, bloom / levelCount, strength)` before exposure, so light is moved, never added. `bloomBlur`, `bloomDownsample`, `bloomUpsampleAdd`, `sampleBilinear` and `mixBloom` mirror the shaders on the CPU for tests (energy kept, flat images unchanged, mirror symmetry). `getDisplayOutput()`. Its last step dithers: it encodes the colour to sRGB, adds up to half an 8-bit step of interleaved gradient noise (from `gl_FragCoord`), and decodes, so dark gradients do not band (`core/dither` mirrors and tests it; the GLSL lives in `assets/shaders/dither.glsl`, a shader-only include with the sRGB curve and the noise, which `triangle.frag` also uses for soft shadows; `tools/package_demo.py` skips `.glsl` files). Shading is physically based (glTF metallic-roughness, `render/gpu/brdf`, mirrored and tested on the CPU like the other shader maths; its numbers, dielectric reflectance 0.04, smallest roughness 0.045, smallest view cosine and the table size 32, in the macro header `render/gpu/brdf_shared.h`): per light, the GGX distribution times Smith height-correlated visibility times Schlick Fresnel, scaled by a multiple-scattering energy compensation `1 + f0 (1 / E - 1)` (Turquin 2019), plus Lambert diffuse weighted by `1 - specular albedo`, so a white surface under uniform light returns exactly what it receives (the white furnace test). Unit convention: the BRDF is multiplied by pi, so a light's radiance is the irradiance it gives a surface facing it and a white matte surface lit head-on by 1 shows 1 (the pre-PBR brightness). `ShadingPoint` (shader and CPU, `prepareShading`) is worked out once per pixel: `f0 = mix(0.04, baseColour, metallic)`, alpha = roughness squared, and from the specular albedo table (`BrdfTable`: scale and bias for f0 over n.v and roughness, texel i at i / (size - 1), integrated at start-up by `buildBrdfTable` with GGX importance sampling along a Hammersley sequence, 4096 samples per texel, about 85 ms in release; uploaded by `VulkanRenderer::createFixedTextures` as `R16G16_UNORM` via `brdfTableTexels`) the compensation, the specular albedo and the weighted diffuse colour. Ambient returns `ambient * (diffuse + specularAlbedo)`, so metals are not black under ambient light. Fragment samplers: 0 colour, 1 shadow atlas (compared), 2 shadow atlas (raw), 3 metallic-roughness, 4 BRDF table, 5 normal map. Normal mapping (mirrored in `render/gpu/normal_mapping`: `decodeNormalTexel`, `perturbNormal`, `transformTangent`): `triangle.vert` carries the tangent with the model matrix, normalises it like the normal and multiplies its sign by `handedness(model)` (`math/mat4`, pushed per draw after the three matrices, 52 floats); `triangle.frag` decodes the texel as (2c − 1) · (scale, scale, 1), rebuilds the bitangent as w · (N × T) from the interpolated, unnormalised normal and tangent (MikkTSpace's rule) and normalises only the sum; shadow offsets use the geometric normal. The demo's glowing materials (moon, bulbs, floodlight heads, marker) share `glowMaterial` (black, roughness 1); the teapot is real gold (metallic 1, roughness 0.35); `Vec3 * Vec3` multiplies component by component, as GLSL does; limits are 4 directional, 64 point and 8 spotlights (2736 bytes); with more, `prioritizeLights` picks the most important (see Shadows above). The software renderer still hardcodes a light at `(-1, 2, 1)`. The demo's ambient 0.2 plus sun 0.8 reproduces the old hardcoded look; it is night (ambient 0.012 (`nightAmbient`), tiny because linear values are brightened a lot by the sRGB encoding); a glowing moon sphere sits at a fixed place 64 units from the free camera's start (about 20 seconds of flying in F3 mode, so it can be reached; it therefore shows parallax, unlike the real moon), in the direction the moonlight comes from; the moonlight is a bluish shadow-casting `DirectionalLight` at intensity 0.06 (`moonlightIntensity`) (it was a `PointLight` inside the sphere for a while, to try point light shadows; directional shadows are much sharper because their box covers only 30 units), and the sphere's `ModelRenderer` has `castsShadows = false` so it does not block the light it stands for; F toggles a flashlight (a `SpotLight` entity, removed when off) that `DemoGame::updateFlashlight` places every frame in `onUpdate`: in the right hand (0.4 right of and 0.3 below the eye, aimed at the point 8 units straight ahead, so its shadows show beside things), or in MOBA mode held by the duck using its interpolated pose and `getCharacterFacing` (`gameplay/character`), tilted down 20 degrees and held 1.2 units in front of it, past its body, so the duck does not block its own light. L toggles a lamp field (`DemoGame::toggleLamps`): 100 coloured point lights, more than the 64 point light shadows, so light priority has to choose (emissive bulb spheres with `castsShadows = false`; a 10 x 11 grid 3.5 apart minus 10 places in a keep-clear box around the spinning objects, the duck and the first-person start), each with a stone pillar beside it turned a golden angle further each time; each lamp is a `Firefly` (`gameplay/firefly`: `fireflyPosition(firefly, seconds)`, a circle round the pillar whose radius, height and speed wobble as sums of sines, staying 0.55-0.95 from the pillar and below its top) with a `PreviousTransform`, so the pillar shadows sweep round and every lit lamp's shadow tiles are redrawn each frame (a shadow stress test); the entities are destroyed when toggled off. K toggles four floodlights over the obstacle course (`DemoGame::toggleFloodlights`, on at the start, `getFloodlights`): shadow-casting cool-white `SpotLight`s (intensity 40, range 25, cone 20 to 35 degrees, `emitterRadius` 0.15 for soft shadows) whose glowing cube heads (`castsShadows = false`) hang 0.5 out from poles at `floodlightPoleFeet()` (just inside the slab's corners, `floodlightHeight` 8 up), each aimed 0.3 of the way past the course's middle so the beams cross; the poles are parts of the course renderer, so they are in the static level and stay when the lamps are off; all tuning is in named `floodlight...` constants in `demo_game.cpp` (`floodlightCount` and `floodlightHeight` in `demo_game.h`, which `floodlightPoleFeet` also needs).
