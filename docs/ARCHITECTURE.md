# Architecture reference

The detailed reference for how each system is built today: names, files, numbers and the reasons behind them. `CLAUDE.md` holds the rules and a short summary and points here; `docs/ENGINE_GUIDE.md` explains the concepts for a human reader. Read the section for a system before changing it, and keep it in sync in the branch that changes it.

Live path: `main` creates a `DemoGame` and an `Application` (the engine), which drives the game through the `Game` hooks, fills `Input` from the `Window`, and draws the `World` with the `GpuRenderer`.

## Settings

Settings: every value a game, the debug UI or a player may tune lives in one settings struct owned by its system, read every frame unless noted, with defaults that are the engine's values. `EngineSettings` (`engine/engine_settings.h`: `ticksPerSecond` 120 and `maxFrameSeconds` 0.25, both read only at start-up; `targetFPS` 240, 0 = unlimited; `presentMode`, applied when it changes; `gpuValidation`, read at start-up and passed to `GpuRenderer`'s constructor as SDL's debug mode (SDL's checks plus Vulkan's validation layers when installed; they are not installed on the development machine yet), defaulting to `isDebugBuild` from `core/build_info.h`, which the makefile sets by defining `ENGINE_DEBUG_BUILD` in debug builds only; and `render`) is owned by `Application` (constructor argument, `getSettings()`). `RenderSettings` (`render/gpu/render_settings.h`) = `LightPrioritySettings lights` + `ShadowSettings shadows` + `BloomSettings bloom` + `ToneMappingSettings toneMapping` + `DisplaySettings display`, passed to `GpuRenderer::render(frame, settings)` each frame. Camera controllers each own a settings struct (`FreeFlyCameraSettings`, `FirstPersonCameraSettings`, `MobaCameraSettings`; the look ones nest the shared `LookSettings`: `radiansPerPixel`, `sprintMultiplier`), passed to the constructor and editable through `getSettings()`. Fixed capacities (shader array sizes, atlas size, tile counts) stay compile-time constants. Games cannot reach `EngineSettings` yet (it pulls in `render/` headers); `main` uses the defaults.

## Application (the engine)

`Application` (`engine/`) runs the main loop (fixed timestep, frame cap) for a borrowed `Game` (declare the game first so it outlives the engine). It owns the `Window`, `GpuRenderer`, `Input`, the `World` and the `AssetManager`. Before each frame it uploads every mesh and texture the `AssetManager` gained since the last frame (the ones past the renderer's counts), so games can load and spawn at any time. It applies `game.wantsMouseLook()` to the window only when it changes (re-applying would undo Escape).

## The Game interface, debug drawing, culling and render stats

`Game` (`engine/game.h`) hooks, called each frame in this order: `onInput(world, input)` once, `onFixedUpdate(world, tickSeconds, simulationSeconds)` per tick (no `Input` parameter on purpose), `onUpdate(world, input, frameSeconds, alpha)` once; plus `onInit(world, assets)`, `getCamera()` (the engine sets its aspect ratio), `wantsMouseLook()` and optional `getLightFocus()` (where lights are ranked, default the camera position); optional `onDebugDraw(const World&, DebugDraw&, alpha)` (called every frame after `onUpdate`) and `wantsDebugView()`. Debug drawing: `DebugDraw` (`scene/debug_draw`) collects `DebugLine`s (`line`, `box(bounds, transform)`, `sphere` as three circles, `capsule`); `Application` clears it every frame, adds `drawBoundingBoxes` (`engine/debug_views`, from `boundsByMesh`, filled with `meshBounds` as meshes upload) and `drawRenderStats` (last frame's `RenderStats`, `render/render_stats.h`, as text in the top-left) when the game wants the debug view, calls `onDebugDraw`, and puts the lines in `FrameDescription::debugLines` and `debugScreenLines`. `DebugDraw::screenLine` adds lines in window pixels (top-left origin); `debugText`/`debugTextWidth` (`scene/debug_text`) write text with a stroke font (A-Z, 0-9, : - / . ?, on a 4x6 grid; lower case drawn as upper, unknown characters as ?), a stopgap until phase 9's font rendering. The renderer draws world lines with the camera and screen lines with a flipped pixel orthographic matrix (`Mat4::orthographic` accepts flipped boxes, rejects empty ones). `GpuRenderer` hands them to its `DebugLineRenderer` (`render/gpu/debug_line_renderer`: owns the line pipeline and a growing vertex buffer; `upload` builds the vertices with `buildDebugLineVertices` in a copy pass before the render passes, `draw` runs in the tone mapping pass, after the scene is tone mapped, so line colours are exact), which draws them last as a line list with no depth test, so they show through everything; colours are linear. `World::each` has a const overload that passes const components. Culling: `Frustum::fromClipMatrix(viewProjection, ClipDepth)` (`math/frustum`; six inward unit-normal planes from the matrix rows, either depth convention; the renderer's matrices are `ZeroToOne`) and `intersectsSphere`, plus `corners` and `mayIntersect` (false only when one view lies wholly outside a side of the other, tested both ways). Each `DrawItem` has a `BoundingSphere bounds` (radius < 0 = unknown, never culled); `Application` fills it with `attachBoundingSpheres(frame.draws, boundsByMesh)` (`scene/culling`: the box's centre through the model matrix, half-diagonal times the largest axis scale). `GpuRenderer` draws only `visibleDraws(draws, cameraFrustum)` in the main pass and only `shadowCasters(draws, tileFrustum)` in each shadow tile; shadow passes must never use the camera's frustum (off-screen casters still throw shadows into view). `getLastFrameStats()` returns `RenderStats` (drawn, culled, shadowDrawn, shadowCulled, and point lights total, in view, lit and shadowed, shown as a third line of the debug readout; then shadowTilesDrawn, shadowTilesCached and shadowTilesSkipped, a fourth line). The demo toggles its debug view with F4 (bounding boxes, the culling readout, a sphere in its colour at each point and spot light, a beam line for spotlights, and a line to the walk target). Always run ticks through `runFixedUpdate`, which saves previous transforms first; tests use it too. `DemoGame` (`games/demo/`) holds the camera, control modes, player and marker entities, and all demo input rules. `window` is declared first and `renderer` second: members are destroyed in reverse order, so the renderer goes before the window it draws into, and the GPU device outlives every uploaded mesh.

## Window

`Window` (`platform/`) owns SDL video and the `SDL_Window`: event polling into `Input`, quit, focus loss (releases everything), click to capture (mouse look) or confine (MOBA cursor), Escape to release, Alt+Enter fullscreen. After the events it records the cursor position, window size, keyboard focus, mouse capture and cursor confinement into `Input`, so games read those facts from `Input` instead of the window. It reports raw facts only; game rules live in game code.

## GpuRenderer, shadows and light priority

`GpuRenderer` (`render/gpu/`) uses SDL3's GPU API (SDL_GPU) with the Vulkan backend and SPIR-V shaders, drawing into a window it does not own. It owns the device, pipeline, depth texture, and GPU copies of meshes and textures in arrays indexed exactly like the handles (`uploadMesh`, `uploadTexture`). Each frame it gets one call, `render(frame, settings)` (the frame plus `RenderSettings`), with a `FrameDescription` (`scene/frame_description`: a copy of the camera, the `FrameLighting` and a list of `DrawItem`s, each `{MeshHandle, model matrix, Material}`), built by `buildFrame(world, camera, alpha)` from every visible `ModelRenderer` with a `Transform` (one item per part, interpolated). Having the whole frame lets it draw the scene more than once (shadow maps) and cull; the per-frame steps (`acquireFrame`, `drawShadows`, `beginMainPass`, `drawMesh`, `endFrame`, and `abandonFrame` to submit after an error) are private. Shadows: every light casts shadows unless its `castsShadows` is off (default on for directional, point and spot lights; `ModelRenderer::castsShadows`, default true, carried on each `DrawItem`, decides which meshes block light). `planShadows(lighting, camera)` (`render/gpu/shadow_map`) hands out square tiles of one D32 depth atlas (8192 x 4096, 128 MB; this SDL version cannot target one layer of an array texture), numbered directional lights first, then spotlights, then point lights, in slot order: 1 per directional light (always `standardShadowTileSize`, 1024 px; an orthographic box covering `ShadowSettings::directionalDistance` = 30 in front of the camera, reaching `directionalCasterReach` = 50 back towards the light, centre snapped to whole texels against shimmer, `directionalShadowMatrix`), 1 per spotlight (perspective down the beam, `spotShadowMatrix`), 6 per point light (cube faces, `pointShadowFace` = largest axis, mirrored in the shader; a face whose widest view misses the camera frustum, by `mayIntersect`, gets no atlas square and no draw: it keeps its place in `tiles`/`tileData` with size 0 and an empty rect, which the shader counts as lit, so `firstTile + face` still works). Shadow caching: `GpuRenderer` keeps a `ShadowAtlasLayout` (`render/gpu/shadow_atlas`; `planShadows(lighting, camera, layout)` asks it for squares by `ShadowTileKey` = light kind, entity (slot when the entity is `Entity{}`) and face, and gets last frame's square back for the same size; a buddy `ShadowAtlasAllocator` merges freed quarters; on fragmentation it repacks everything once; the two-argument `planShadows` uses a fresh layout) and a `ShadowTileMemory` (`render/gpu/shadow_cache`: per square, the matrix and `shadowCasterSignature`, an FNV-1a hash of each caster's mesh index and model matrix; `remember` forgets overlapped squares; `forgetAll` after any render error). `drawShadows` skips tiles whose matrix and signature match, loads the atlas (`LOADOP_LOAD`, `cycle = false`), resets each redrawn tile with `shadowClearPipeline` (`fullscreen_triangle.vert`, a viewport-covering triangle at depth 1, also used by the tone mapping pass, compare `ALWAYS`) and skips the pass when nothing changed; up to 4 directional, 8 spot and 64 point lights (`maxShadowTiles` = 396; at most 4 x 16 + 8 + 64 x 6 = 456 of the 512 smallest-tile places, so everything fits at the smallest size); lights past that still light, unshadowed. Tile size: `shadowTileSizeFor(halfWidth, range, texelTarget, largestSize)` picks a power of two from 256 px up to `largestSize` (1024 `standardShadowTileSize` for point faces, 2048 `largestShadowTileSize` for spotlights) so one texel covers about `ShadowSettings::texelTarget` = 0.04 units (`spotTexelTarget` = 0.02 for spotlights, whose beams land at a slant short of their reach; the floodlights get 2048, the flashlight 512) across the far end of the view; if the total would overflow, `shrinkToFit` halves the least important (last) requests first, so every point light reaches the smallest size before a spotlight shrinks (directional never shrink); the `ShadowAtlasLayout` places them, largest first, with its buddy `ShadowAtlasAllocator` (power-of-two squares split into quarters and merged back), so they never leave gaps. `ShadowPlan::tiles` holds each `ShadowTile` (matrix, x, y, size in pixels) for the shadow pass's viewports; matrices and offsets depend on the tile size (`pointShadowFaceMatrix`/`spotShadowMatrix` take it, default 1024; the `ShadowAtlasAllocator` starts as 8 squares of 2048). Perspective views are a little wider than needed so 3x3 PCF never leaves a tile. `selectDrawableLights` (`light_uniforms`, with `canBeDrawn` per light) is the single rule for which lights reach the shader and in which slot, used by both `packLighting` and `planShadows`. Before them, `GpuRenderer::render` runs `prioritizeLights(lighting, frame.lightFocus, cameraFrustum, lightHistory)` (`render/gpu/light_priority`): it drops lights whose range sphere misses the camera frustum, ranks the rest by `priority` (an int on `PointLight` and `SpotLight`, default 0; higher always wins), then by `lightImportance` at the focus (`intensity * brightest channel / (d² + r²)`, no range window so far lights do not tie at zero; directional lights by brightness alone), seats the top 64 point and 8 spot lights, gives shadows to the top seated casters up to the shadow caps (`LightPrioritySettings`, an optional last parameter: seats defaulting to 64 point and 8 spot, the same shadow caps, clamped to those limits, plus `incumbentAdvantage` and `fadeSeconds`; tests lower the point shadow cap to 16 to exercise shadow-only handovers; the shader skips a light, and so its shadow lookups, for pixels beyond its range) (switching `castsShadows` off on the others' copies, so `planShadows` needs no change), and returns a `LightHistory` (entities in view, and each seat holder's `LightFade`: entity, light and shadow strength 0..1) that the renderer keeps. Handovers fade over `fadeSeconds` (0.25; 0 hands over at once): a holder that is no longer wanted keeps its seat or shadow while fading out and frees it at zero, then the wanted newcomer fades in (from 0 if it was on screen last frame, at full if not: a light just switched on or come into view appears at once); a light leaving the view is dropped at once. The strengths reach the GPU as `PlacedPointLight`/`PlacedSpotLight::fade` (multiplied into the radiance by `packLighting`) and `shadowFade` (`ShadowUniformData::pointShadowStrengths`/`spotShadowStrengths`, 896 bytes, with `pointEmitterRadii`/`spotEmitterRadii` for soft shadows; the shader mixes the shadow towards lit). `prioritizeLights` takes the frame time, from `FrameDescription::frameSeconds` (set by `Application` from the timestep); last frame's choices count `incumbentAdvantage` (1.25, `LightPrioritySettings`) times as much (hysteresis, between equal priorities only). `PlacedPointLight`/`PlacedSpotLight` carry their `Entity` for this (`Entity{}` never counts as last frame's). `FrameDescription::lightFocus` is the camera position from `buildFrame`, then `Application` sets it from `Game::getLightFocus()` (default: camera position; `DemoGame` returns `MobaCameraController::getLookPoint` in MOBA mode, the ground point the camera looks at). `ShadowUniformData` (896 bytes, fragment uniform slot 2) holds each light slot's first tile at `[slot / 4][slot % 4]` (-1 none) and the atlas texel size. Per-tile data, `ShadowTileData` (112 bytes: column-major matrix, normal offset per unit of distance for perspective tiles or fixed for boxes, atlas rectangle 0..1, and `lens`: near, far and world size of a texel per unit of distance for perspective tiles, zeros for boxes), is too big for a uniform block, so `ShadowPlan::tileData` goes to a fragment storage buffer (`shadowTileBuffer`, std430 `ShadowTiles` at set 2 binding 5, after the five samplers; uploaded by `uploadShadowTiles` in a copy pass before the shadow pass, bound with `SDL_BindGPUFragmentStorageBuffers`; `loadShader` takes a storage buffer count). **Uniform blocks must stay at or under 4096 bytes** (`maxUniformBlockBytes`, `render/gpu/uniform_limits.h`): SDL's Vulkan backend binds a 4 KB window (`MAX_UBO_SECTION_SIZE`), and anything past it silently reads as zero; every uniform struct has a `static_assert` on it. The shadow pass is one render pass with a depth-only pipeline (`shadow.vert`/`shadow.frag`, positions only, no culling, no hardware depth bias: its slope-scaled part detached shadows from pillars seen edge-on by small tiles), the viewport moved to each tile. The main shader samples the atlas as `sampler2DShadow` (fragment sampler slot 1, compare `LESS_OR_EQUAL`, linear), after offsetting the point along its normal by 2.5 texels of its tile (`ShadowSettings::normalOffsetTexels`, the only bias), averages 3x3 for directional boxes, and treats points outside a tile's view as lit. Point and spot lights get soft shadows (PCSS, `softShadowFromTile`; the arithmetic is mirrored and tested in `render/gpu/soft_shadow`): a 16-sample Poisson-disc blocker search in the atlas read as raw depths (`shadowDepths`, fragment sampler slot 2, a nearest non-comparison `shadowDepthSampler`), the penumbra `emitterRadius * (receiver - blocker) / blocker` in texels (1 to 12), then 16 comparison samples over it, rotated per pixel by interleaved gradient noise, clamped a texel inside the tile, each compared against the receiver's plane (receiver plane depth bias from `dFdx`/`dFdy` of the world position, taken at the start of `main` in uniform control flow and projected through the tile). `PointLight::emitterRadius` (0.05) and `SpotLight::emitterRadius` (0.025) are the glowing size for shadows, separate from `sourceRadius`, which only shapes the falloff (the demo flashlight's is 4.5). `Mat4::orthographic` builds the box projection (OpenGL depth convention like `perspective`). It fits its camera copy's aspect ratio to the acquired frame, and `Application` then copies that ratio into the game's camera for click rays. It never reads files.

## Assets and materials

Assets: `MeshHandle` and `TextureHandle` (`scene/asset_handles.h`) are typed indices; a default handle means "none" (no texture = plain colour). `AssetManager` (`assets/`) owns CPU-side meshes, images and imported models, loads each file once (`loadMesh` for OBJ, with optional `MeshLoadOptions{.smoothNormals, .creaseAngle}` that are part of the cache key, `loadTexture` by path+flip or embedded buffer, `loadModel` for glTF, which returns a stable `const Model&`), and gives the same handle for the same shared mesh pointer. Assets are append-only, so handles never go stale (add a generation like `Entity` if unloading is added). Loaders produce `Model`s whose parts hold a shared `Mesh` and a `MaterialSource` (colour, `metallic`, `roughness`, linear `emissive`, and two `TextureSource`s, `colourTexture` and `metallicRoughnessTexture`, each a path or embedded bytes, sharing one flip); `AssetManager::makeMaterial` turns that into a `Material` (colour + `TextureHandle`, `metallic` 0 and `roughness` 0.5 by default (the old Blinn-Phong default, shininess 32, matches roughness 0.5), an optional `metallicRoughnessTexture` (glTF packing: roughness in green, metallic in blue, multiplying the numbers), and `emissive`), loading the colour texture as `TextureEncoding::Srgb` and the metallic-roughness one as `Linear` (`AssetManager::loadTexture(TextureSource, flip, encoding)`; the encoding is part of both texture caches' keys and is stored in `ImageData::encoding`). The glTF loader reads `metallicFactor`, `roughnessFactor`, the metallic-roughness texture, `emissiveFactor` and `KHR_materials_emissive_strength` (`readTexture` handles both textures, files and embedded alike); a part with no material gets glTF's defaults, metallic and roughness 1. `packMaterial` (`render/gpu/material_uniforms`) turns a `Material` into `MaterialUniformData`, which mirrors the shader's `MaterialData` block (48 bytes: base colour, `surface` = metallic and roughness clamped to 0..1, emissive; fragment slot 0, pushed per draw).

## Input

`Input` is a once-per-frame snapshot with no SDL dependency: `isKeyHeld`, `wasKeyPressed`, `wasKeyReleased` take an engine `Key` (`key.h`, physical US-layout positions), plus accumulated `getMouseDelta`. Mouse buttons (`MouseButton`) work like keys, and each press is also recorded as a `MouseButtonPress` with the exact event position (window pixels) and timestamp (ns, `SDL_GetTicksNS` clock): use `getLastMouseButtonPress` for clicks, `getCursorPosition`/`isCursorInWindow`/`getWindowSize` for continuous things. It is filled through `pressKey`/`releaseKey`/`pressMouseButton`/`releaseMouseButton`/`addMouseMotion`/`setCursor`/`setWindowSize`. `sdl_input` is the only SDL-to-engine translation (`keyFromScancode`, `mouseButtonFromSdl`, `applySdlEvent`, which also drops key repeat). `Window::processEvents(input)` resets and fills it. Mouse motion is only forwarded while the mouse is captured, and is discarded when capture or control mode changes. Game code reads keys from `Input` as `Key` values, never SDL scancodes or `SDL_GetKeyboardState`.

## Entities and components

Entities and components (`ecs/`): an `Entity` is an index plus a generation (handles to destroyed entities go stale even after their slot is reused; `Entity{}` is never alive and means "none"). `World` creates/destroys entities and stores one `ComponentStorage<T>` (sparse set: packed `components`, owning `entities`, and a `sparse` index) per component type. Components are plain structs; systems are free functions run with `world.each<A, B>([](Entity, A&, B&) { ... })`, which walks the first type's packed array, so list the rarest component first. Inside `each`, `destroy` and `remove<T>` are deferred: the `World` counts running walks (`activeWalks`, also per storage in `ComponentStorageBase::activeWalks`; they nest, and the const `each` counts too) and queues them as type-erased `PendingChange`s, applied in order by `applyPendingIfIdle` when the outermost walk ends (also when a system throws, so the world never stays locked); until then the entity and its components stay visible. `create` is always immediate. `add<T>` throws `std::logic_error` while a walk over `T` runs; `addLater<T>` adds at once outside a walk and queues inside one (skipped if the entity is dead by then). A queued destroy of a dead entity is a no-op. Tests: `deferred_changes_test`.

## Components today

Components today (`ModelRenderer` also has `castsShadows`): `Transform` (`math/`), `PreviousTransform`, `ModelRenderer`, `DirectionalLight`, `PointLight`, `SpotLight` and `AmbientLight` (`scene/`), `Spinner`, `Firefly`, `CharacterMovement`, `FirstPersonBody` and `Grenade` (`gameplay/`), `Collider`, `CharacterController` and `Particle` (`physics/`). `ModelRenderer` is a list of `RenderPart`s (mesh, material, `localTransform` with the model's normalization folded in) plus `visible`; a multi-part model is one entity. Parts hold a `MeshHandle` and a `Material`, so the component is small and copyable. Build with `assets.makeModelRenderer(model, normalization)` or `makeMeshRenderer(meshHandle, material)`.

## Main loop

Main loop: `FixedTimestep` (120 Hz and frame time clamped to 0.25 s by default, from `EngineSettings`) turns real frame time into a whole number of ticks plus an interpolation `alpha`. Each frame: `game.onInput` turns input into commands, `runFixedUpdate` runs zero or more ticks, `game.onUpdate` moves the camera, then `render(alpha)`. Never read `Input` inside a tick; key/click edges are handled once per frame and reach the simulation as commands. Mouse look and camera movement are per frame, not per tick.

## Each tick

Each tick: `savePreviousTransforms` (engine), then `DemoGame::onFixedUpdate` runs `updateCharacters`, `updateFirstPersonBodies`, `updateSpinners`, `updateFireflies`, `moveParticles` and `updateGrenades` in that order (spinners and fireflies compute their pose from the total simulation time, so no error builds up; `DemoGame` keeps `latestSimulationSeconds` so lamps created between ticks start mid-flight). Determinism: the same build given the same commands reaches a bit-identical state; `hashSimulationState(world)` (`engine/state_hash`) hashes every component ticks change (Transform, PreviousTransform, CharacterController, CharacterMovement with `MoveToController::getTarget`, FirstPersonBody, Particle, Grenade) field by field with `Fnv1aHash` (`core/hash.h`, shared with `shadowCasterSignature`), and `determinism_test` plays a scripted demo (walking, jumps, grenades, the lamp field, MOBA right-click) in two worlds and compares the hash every frame, plus a third world one grenade throw short that must differ. A new component that ticks change must be added to the hash. Interpolation: only entities that move continuously get a `PreviousTransform`; `getRenderTransform(world, entity, alpha)` blends it with `Transform` (`interpolate` takes the shortest way around for angles), and entities without one are drawn at their `Transform`. Things that teleport (the destination marker) therefore have no `PreviousTransform`. Create moving entities with `PreviousTransform` equal to their starting `Transform`.

## Cameras

Cameras: `Camera` (`scene/`) is a plain lens: position, forward, up, vertical FOV, aspect, near/far; view and projection matrices are built on request, so `setVerticalFov` works (aim-down-sights zoom). It has no movement logic. Controllers in `gameplay/camera/` move it, each a concrete class with no shared interface (a real game uses one): `FreeFlyCameraController` (look + fly, Space/Ctrl up/down; holding Shift multiplies its speed by `LookSettings::sprintMultiplier`, 2; it uses `look_controls`' shared `turnCamera` and `moveCamera`, and the first-person controller only `turnCamera`: walking, and its 1.5 sprint, belong to the first-person body), `FirstPersonCameraController` (look only: mouse turns it every frame; the game places it at the first-person body's eyes), `MobaCameraController` (fixed-angle offset; follows an optional target, otherwise edge-pans while the cursor is confined). Look controllers store yaw/pitch as `ViewAngles` (spherical coordinates, yaw 0 = -Z, positive yaw turns right, pitch clamped to 89 degrees) and pause while the mouse is not captured; `takeOver(camera)` continues from the camera's current direction.

## Control modes and the demo

Control modes (`ControlMode`, demo only): F1 first-person, F2 MOBA, F3 free camera (debug switching, the `DemoGame` constructor's `debugModeSwitching`). First person is a body (`gameplay/first_person_body`): `spawnFirstPersonBody` makes an entity with `Transform` (feet), `PreviousTransform`, `CharacterController` and `FirstPersonBody` (`FirstPersonMoveSettings`: walkSpeed 5.5, backwardMultiplier 0.9, backwardDiagonalMultiplier 0.93333, crouchSpeed 3, sprintMultiplier 1.5, standing height / eyes 1.8 / 1.6, crouching 1.2 / 1.0, eyeHeightSpeed 6; the command `wantsCrouch`; the state `crouching` and eased `eyeHeight`). `DemoGame::updateFirstPersonCommands` (in `onInput`) sets the controller's `wishVelocity` from `firstPersonWishVelocity(getMoveAxes, camera yaw, crouching, Shift held, settings)` (level forward turned by yaw, normalised, speed from the eight-direction table), `wantsJump` on a fresh Space press, `wantsCrouch` while Ctrl is held, throws a grenade on a fresh G press (`throwGrenade` from the camera along its forward, with `DemoGame::grenadeSettings` and `grenadeLooks`, a dark sphere), and clears them outside first person or with the mouse released. `updateFirstPersonBodies(world, level, seconds)` crouches at once, stands up only if `characterFits` the standing capsule, eases the eyes and runs `moveCharacter`. The camera sits at `firstPersonEyePosition(world, body, alpha)` (interpolated feet plus eye height). F1 from the free camera calls `placeFirstPersonBody` (moves `Transform` and `PreviousTransform`, clears velocity, ground looked up afresh) with the feet an eye height below the camera; F1 from elsewhere looks straight ahead (-z) from the body. The body has no `Collider`, so picking never finds it. `characterFits(settings, feet, level)` (`physics/character_controller`) is true when the capsule overlaps nothing. MOBA mode uses a confined visible cursor, edge panning (`gameplay/edge_pan`, from the cursor in `Input`), Space to lock the camera on the player, left-click to select (`DemoGame::updateSelection`: a `CollisionScene` rebuilt and raycast in `Triangles` mode from the exact click position, through `rayThroughPixel`, shared with moving; nothing hit deselects; `getSelected`; `onDebugDraw` outlines the selection's collider in cyan even without F4; the demo's cubes and pillars share `cubeCollider`, the pyramid and teapot get their own mesh colliders, the moon and lamp bulbs unit spheres), hovering (`updateHover` in `onUpdate` after the camera moves: `pick(world, ray)`, shared with selection, raycasts the collision scene, then the static level up to that distance, and the nearer wins, so walls hide what is behind them; `getHovered` is the entity, outlined in dimmed cyan, `getHoveredTriangle` the level triangle, outlined with its normal only in the F4 view; with F4, readout lines 6 and 7 show colliders and level triangles, tested and cells walked, and line 8 the duck's controller (grounded or airborne, slope, substeps) with its ground normal drawn at its feet; the duck's controller has radius 0.5 and `mobaUnitAcceleration` (1000) so it starts and stops within a tick), the obstacle course (`buildObstacleCourse`: cube parts of one entity at `obstacleCourseOrigin` (17, 0, -4) with the slab top at `obstacleCourseFloorTop`, a wall with a doorway, five 0.25-high steps to a platform, 20 and 50 degree ramps; its collision mesh comes from the same parts, and it and the ground form `DemoGame::staticLevel`, `getLevel`), and right-click (or hold) to move the player (`DemoGame::updatePlayerCommands`: the click ray hits the static level, so a step or platform top is the target, the marker sits `markerLift` above the hit; a click uses its exact event position; holding steers towards the live cursor via `groundSteeringActive`).

## Characters

Characters: `spawnCharacter(world, assets, model, config, position)` creates an entity with `Transform` (its position is the feet), `PreviousTransform`, `ModelRenderer`, `CharacterMovement` (a `MoveToController` plus turning state; `moveTo`/`stop`/`isMoving`), a fitted `Collider` capsule and a `CharacterController` with `CharacterConfig::controller` (validated: positive radius, height at least two radii). `updateCharacters(world, level, dt)` sets each controller's `wishVelocity` from `MoveToController::desiredVelocity(position, dt)` (across the ground at `speed`, cut on the last step to land exactly; zero with no target or time), runs `moveCharacter`, calls `updateArrival` (stops within `arrivalDistance`, 1e-4; a wall in the way means it never arrives: no path finding) and turns towards the displacement at `turnSpeed`; `getCharacterVisualCentre(world, entity, alpha)` gives the interpolated camera target. `math/ray` provides `Ray` and `intersectGround`; `scene/camera_ray` provides `makeCameraRay`. Together they turn mouse clicks into ground positions.

## Collision, particles and the character controller

Collision (`physics/`): shapes live in one shared (world) space: `Sphere` (centre, radius), `Capsule` (segment `a`-`b` grown by `radius`; `a == b` is a sphere) and `Aabb` (`math/aabb`, also used for mesh bounds: `meshBounds`, `Model::getBounds`); `Shape` is a `std::variant` of the three. `overlaps(a, b)` exists for every pair in either order and for two `Shape`s (`std::visit`); touching counts as overlapping. Rounded shapes reduce to closest points between their cores (`math/closest_points`: `closestPointOnSegment`, `closestPointInBox`, `closestPointsBetweenSegments` after Ericson, and `closestPointsSegmentBox`, which cuts the segment where it crosses the box planes and minimises each quadratic piece exactly), compared with the summed radii. Raycasts (`physics/raycast`): `raycast(ray, Sphere | Capsule | Aabb | Shape | TriangleMesh, maxDistance = unlimitedRayDistance)` returns `std::optional<RayHit>` (`distance` in world units, the direction is normalised inside; `point`; unit `normal` always against the ray). Starting inside a shape hits at distance 0 with the normal opposite the ray; a zero direction hits nothing. Spheres and capsule ends solve the ball quadratic, the capsule side drops the motion along its axis, boxes use slabs (the latest entry axis is the face), triangles use Moller-Trumbore from both sides and keep the nearest. `TriangleMesh` (`physics/triangle_mesh`: `positions` plus 3 `indices` per triangle, usually in world space) is built by `collisionMesh(mesh, transform)` (`scene/collision_mesh`, which checks indices). `Vec3::operator[]` reads x, y, z by index for per-axis loops. Colliders (`physics/collider`): the `Collider` component is a `Shape` in the entity's own coordinates plus an optional `std::shared_ptr<const TriangleMesh> detail` (exact triangles, same coordinates, shared between entities; the shape must enclose them). `worldShape(shape, model)` moves a shape by a model matrix: points exactly, radii times the largest column length of the 3x3 part (exact for a `Transform`'s rotation times scale), boxes to the axis-aligned box around the turned box (half-size `sum_j |A_ij| h_j`). `triangleMeshBounds`, and `meshCollider(mesh)` (box around the mesh plus the mesh). `raycastColliders(world, ray, RaycastDetail::Shapes | Triangles, maxDistance)` (`physics/collider_raycast`) builds a `CollisionScene` and asks it once (current poses, not interpolated); the nearest `ColliderHit{entity, hit}` wins and shrinks the reach; in `Triangles` mode a shape hit must be confirmed by `raycast(ray, mesh, model, maxDistance)`, which carries the ray into the mesh's coordinates with `affineInverse` (`math/mat4`: `[A t; 0 1]^-1 = [A^-1, -A^-1 t; 0 1]`, `A^-1` from the cofactors `normalMatrix` also uses, nothing for a flat matrix), scales distances by world length per local length along the ray, and brings the normal back through `normalMatrix`; a ray that slips between the triangles goes on to what is behind. `transformPoint` and `transformDirection` (`math/mat4`) apply a matrix with w = 1 or 0. `appendCollisionMesh` (`scene/collision_mesh`) adds a mesh to an existing `TriangleMesh` with shifted indices, and `AssetManager::makeCollisionMesh(renderer)` merges every part of a `ModelRenderer` (placed by its `localTransform`) into one. `spawnCharacter` gives characters a `Collider` capsule fitted to the drawn model (radius half its wider horizontal side, feet to head), with no detail. `DebugDraw::shape(shape, colour)` draws any `Shape`; `drawColliders(world, alpha, debug)` (`engine/debug_views`, interpolated pose, `colliderDebugColour` orange) runs in the F4 view. Broad phase: `UniformGrid` (`physics/uniform_grid`; cells of `CollisionSettings::gridCellSize`, default 2, `cellOf` uses floor; a `std::unordered_map` of occupied cells with the Teschner hash; an item goes in every cell its box touches, or on the large list past `largeItemCells`, 64; `clear` keeps memory and drops cells unused since the previous clear; mailboxing with per-item query numbers (`seenBy`, mutable, so not thread-safe); `query(region, found)` keeps items whose own box overlaps; `walkRay(ray, reach, visit)` (template, in the header) visits large items, clips the ray to the occupied cells' box, then steps cells near to far (Amanatides and Woo: `tMax`, `tDelta`) and stops when the next crossing is beyond the reach `visit(item, reach)` returns, returning `GridRayWalk{cells, items}`). `CollisionScene` (`physics/collision_scene`, owns `CollisionSettings`, read at each `rebuild(world)`, which clears and refills from every `Collider` + `Transform`: world shape, model matrix, detail) answers `raycast(scene, ray, detail, maxDistance, CollisionQueryStats*)` (narrow phase per visited collider; a triangle miss leaves the reach) and `overlapping(scene, shape)` (shapes only). Rebuilding rather than updating is deliberate: the ECS has no change tracking, so incremental updates could leave ghost entries. `boundsOf(Shape)` (`physics/shapes`). `debugReadoutLine(n)` and `debugReadoutTextHeight` (`engine/debug_views`) place readout lines; the engine uses 0-4 (`engineProfileReadoutLine` 4 is its timings) and a game starts at `firstGameReadoutLine` (5). Profiling: `Profiler` (`core/profiler`, plain C++ so games and tests stay headless) has numbered sections (`addSection` once, `record(section, seconds)`), counts per call and publishes each section's average, worst call and call count (`SectionTiming`) when `update(now)` (once a frame) finds a window (`defaultProfileWindowSeconds`, 0.5) has passed, zeros for a section that did not run; `profilerSeconds()` is `steady_clock` in seconds; `ScopedTimer` records its block and `timeSection(profiler, section, work)` times a callable. `Application` owns one (FRAME, WORK = frame minus the cap's sleep, TICK per tick, UPDATE, SCENE = building the frame and debug lines, RENDER = `renderer.render`, which includes waiting for the GPU) and draws it with `drawProfile` (`profileText`: name, average/worst ms); `DemoGame` times each system in `onFixedUpdate` into its own `systemTimes`, advanced in `onUpdate` and drawn on the first game line (averages, three decimals). Static level (`physics/static_level`): `StaticLevel` holds everything that never moves as one world-space `TriangleMesh` plus its own `UniformGrid` over triangle numbers, built as `add(piece, model)` is called (validated first, so a bad piece changes nothing) and never rebuilt; cell size from the `CollisionSettings` given at construction. `raycast(level, ray, maxDistance, stats)` walks the grid with `raycastTriangle` and returns `LevelHit{hit, triangle}`; `contacts(level, capsule)` queries the grid with `boundsOf` and returns a `Contact{point, normal, depth, triangle}` (`physics/triangle_contact`) per touched triangle (touching counts, depth 0). `contact(capsule or sphere, a, b, c)`: nearest points between core and triangle (`closestPointsSegmentTriangle`: a piercing crossing, else the best of both ends against the triangle and the segment against each edge; `closestPointOnTriangle` by Voronoi region, Ericson 5.1.5, nearest edge for a flat triangle), normal from triangle to core and depth radius minus distance; a core touching the triangle uses the face normal on its middle's side and depth = deepest end behind the plane + radius. Triangles are two-sided. `raycastTriangle` (`physics/raycast`) is the one Moller-Trumbore test, shared with mesh raycasts; its barycentric checks allow `edgeTolerance` (1e-5) outside 0..1 so rays through a seam shared by two triangles cannot slip between them (a demo bug, kept as a bit-exact regression test). `CollisionQueryStats{tested, cellsWalked}` lives in `physics/query_stats`. Sphere sweeps: `sweepSphere(sphere, motion, a, b, c)` (`physics/raycast`) is the first touch of a moving sphere against one triangle: the centre's path raycast against the triangle grown by the radius (two faces offset along the normal plus a `Capsule` per edge); a sphere already touching hits at distance 0 with the contact normal if moving into it (more than `glancing`, 1e-5) and ignores it otherwise; the hit's `point` is the centre at the touch, its normal from the triangle to the centre. `sweepSphere(level, sphere, motion)` (`physics/static_level`) queries the grid with the box round the start and end spheres and returns a `LevelHit`. Not built: box against triangle (separating axes), capsule and box sweeps. Particles (`physics/particle`): `ParticleSettings` (radius 0.1, gravity 9.81, restitution 0.45, friction 0.4, restingSpeed 1, maxBounces 4); the `Particle` component (settings, `velocity`; the `Transform` position is the centre). `fly(velocity, acceleration, seconds)` returns a `FlightStep` moved by the average of the start and end velocities, exact for constant acceleration. `bounceVelocity(velocity, normal, settings)`: the normal part comes back times restitution (0 below restingSpeed), friction slows the sliding part by at most friction (1 + e) times the speed in, never reversing it (resting contact therefore decelerates at mu g). `moveParticle(particle, centre, level, seconds)`: push out of overlaps (deepest first, ending `clearance` 1e-3 clear); if a surface within 2 clearance is moved into, gravity is added at once and the surfaces push back (`pressAgainstTouching`) and the ball moves at the result, otherwise it flies under gravity; then sweeps, stopping `clearance` off each surface hit, bouncing with the velocity at the moment of the hit (share of the path stands in for share of the time) and flying on, up to maxBounces. A resting ball stays exactly still. `moveParticles(world, level, seconds)` for every `Particle` + `Transform`. Grenades (`gameplay/grenade`): `GrenadeSettings` (throwSpeed 15, lifetimeSeconds 5, `particle`), the `Grenade` component (`secondsLeft`), `throwGrenade(world, from, direction, looks, settings)` (Transform scaled to the radius, PreviousTransform, the looks, a unit `Sphere` `Collider`, a `Particle` with velocity along the normalised direction, the thrower's velocity not added), `updateGrenades(world, seconds)` destroys expired ones inside its `each` (deferred by the `World`). `Contact::faceNormal` is the triangle's own normal turned to the shape's side (equal to `normal` on the face, different on an edge or corner). Character controller (`physics/character_controller`): `CharacterControllerSettings` (radius 0.4, height 1.8, maxSlopeDegrees 45, stepHeight 0.3, snapDistance 0.3, gravity 17.5, maxFallSpeed 30, jumpSpeed 5.72 (Overwatch's community-measured values), groundAcceleration 100, airAcceleration 30 (guesses to tune by feel), substepFraction 0.5, pushOutPasses 8); the `CharacterController` component holds the settings, the commands `wishVelocity` and `wantsJump` (used up by the next tick, honoured only on the ground) and the state `velocity`, `grounded`, `groundNormal`, `lastSubsteps`, `groundKnown` (a new controller probes the ground on its first tick). `controllerCapsule(settings, feet)`. `moveCharacter(controller, feet, level, seconds)`: jump first (so take-off uses air rules); `steer` (ground: `moveTowards` the wish at groundAcceleration; air: no wish keeps momentum, steering at airAcceleration keeps the speed, up to the wished speed, for turns of 90 degrees or less); vertical velocity by semi-implicit Euler with quadratic drag while falling (`a = -g + (g / v_t^2) v^2`, v_t = maxFallSpeed); grounded movement is the horizontal velocity tilted into the ground plane and rescaled to full speed (slopes walked at the same speed); substeps of at most radius * substepFraction (64 at most), each followed by `pushOut` (deepest contact first, re-queried each pass: contacts that `supports` the character push straight up by depth / normal.y and stop falling; others push along the normal and remove the velocity into it, steep upward normals only sideways while walking). `supports`: a walkable face (normal.y >= cos maxSlope), or an edge or corner contact (normal differs from `faceNormal`) facing up at least `leastStepNormalY` no higher than stepHeight above the feet, so the capsule rides up low ledges (no separate step-up move). Then, if it was grounded and did not jump, `descend` settles it onto the ground up to snapDistance in `descentIncrement` (0.05) drops, pushing out at the first overlap (dropping the whole way at once let a kerb's edge win the push-out and shove it sideways), which also removes hovering; `groundUnder` (contacts of the capsule lowered `groundProbeDistance`, 0.01, that support it) decides `grounded` and `groundNormal`. `moveCharacters(world, level, seconds)` runs it for every `CharacterController` + `Transform`. `degreesFromRadians` joins `math/angles`.

## Meshes and colour

Meshes: `Mesh` (`scene/`) is the import format: `Vec4` positions plus triangles with an optional normal and UV per corner. Loaders, bounds and the software renderer use it. `buildIndexedMesh` (`scene/indexed_mesh`) turns it into the render format, `IndexedMesh`: unique `MeshVertex` (position, normal, UV; the exact GPU vertex layout, read with `offsetof`) plus 32-bit indices. Each corner gets its file normal or its face normal and its UV or (0,0); corners identical in every component are merged (the key normalises -0.0 to +0.0). Files without normals stay flat shaded, so their corners rarely merge, unless loaded with `smoothNormals`: `generateSmoothNormals(mesh, creaseAngle)` (`scene/smooth_normals`) fills in missing corner normals by averaging the faces around each position (grouped by exact position, so seams with duplicated vertices smooth too), weighted by corner angle, counting only faces within the crease angle (default 60 degrees) of the corner's own face. It is opt-in because only the game knows whether a shape is meant to be faceted. `faceNormal` lives in `scene/mesh`. The engine builds the `IndexedMesh` once when a mesh is first uploaded; `GpuMesh` only validates and uploads it. Colour is gamma-correct: shading happens in linear light. `GpuTexture` takes a `GpuTextureDescription` (format, bytes per texel, and `surface`: a full mip chain, repeat and anisotropy, or else a one-level clamped lookup table); `surfaceTextureDescription(encoding)` gives `R8G8B8A8_UNORM_SRGB` for colour (the GPU decodes texels when sampling and when averaging mips) or plain `R8G8B8A8_UNORM` for data (metallic-roughness now, normal maps later); `GpuRenderer::uploadTexture` takes the `TextureEncoding`, and `textureOrWhite` picks a material's texture or the white stand-in (white multiplies colours and factors by 1), and `GpuRenderer::useLinearSwapchain` switches the swapchain to `SDR_LINEAR` (an sRGB format that encodes on write) before the pipeline is built, logging a warning and keeping `SDR` if unsupported. `Material::colour` bytes are sRGB like image files; `packMaterial` decodes them with `srgbByteToLinear` (`core/srgb`). glTF colour factors are linear, so the loader encodes them with `linearToSrgbByte`. Light colours, intensities and `emissive` are linear. `GpuTexture` uploads RGBA pixels with a full mip chain (`mipLevelCount`, `render/gpu/mip_levels`; the texture is also a colour target so `SDL_GenerateMipmapsForGPUTexture` can build the smaller levels) and samples them with trilinear and 16x anisotropic filtering (`max_lod` must be raised, its default 0 locks sampling to the full-size level). `Material::emissive` (a `Vec3`, black by default) is light the surface gives off itself, added after lighting; with a black `colour` the surface shows only its glow and never changes with lighting (the demo's moon and MOBA marker). `MaterialUniformData` is 48 bytes. `Mesh::sphere(segments, rings)` builds a unit UV sphere with smooth normals.

## Loaders

Loaders: `obj_loader` (quads/convex polygons, normals, UVs), `gltf_loader` (cgltf; returns a `Model` of `ModelPart`s with world transforms, base colour and base colour texture, external or embedded in `.glb`). glTF texture transforms are not supported.

## Software renderer

Software renderer (reference path, used only by tests): `Renderer`, `Display`, `PixelBuffer`, `DepthBuffer`, `rasterizer`, `clipper`, `shading`. It does flat shading only and ignores per-vertex normals and UVs.

## Light, HDR, tone mapping, bloom and shading

lights are components (`scene/light.h`): `DirectionalLight` (stores the direction the light travels; no `Transform` needed), `PointLight` (position from the entity's `Transform`, fades to exactly zero at `range`, `sourceRadius` like a spotlight's, packed into `radiance.w`), `SpotLight` (a point light in a cone: stores its `direction`, full brightness inside `innerAngle`, smoothly fading to zero at `outerAngle`, and a `sourceRadius` that softens the falloff up close, `intensity / (d² + r²)`; the shader compares cosines, which `packLighting` precomputes and clamps inner to outer) and `AmbientLight` (several add up). Colours are 0..1 tints with a separate unbounded `intensity`. Each frame `buildFrame` calls `collectLighting(world, alpha)` (`scene/lighting`, point light positions interpolated like meshes) and `GpuRenderer::render` (after `prioritizeLights`) uses `packLighting` (`render/gpu/light_uniforms`) to fill `LightUniformData` and pushes it once to fragment uniform slot 1. That struct mirrors the `LightData` block in `triangle.frag` byte for byte (all `vec4`, `static_assert` 2736 bytes) and includes the camera position for specular highlights. HDR and tone mapping: `triangle.frag` writes unbounded linear colour into `sceneColour`, an `R16G16B16A16_FLOAT` texture the size of the frame (made with the depth texture in `ensureFrameTextures`); a final pass (`beginToneMapPass`, `fullscreen_triangle.vert` + `tone_map.frag`, `ToneMapUniformData` at fragment slot 0, the scene read with `texelFetch`) multiplies by `ToneMappingSettings::exposure` (1.5, so scenes tuned for the old clipped look keep their shadows and mid-tones), applies the curve (`ToneMapCurve`: `Clamp`, the pre-HDR look; `Reinhard`; `Aces`, Narkowicz's fit; `AgX`, the default, Wrensch's minimal form) stretched to the screen's peak (`peak * curve(x / peak)`, `sdrPeakBrightness` 1 on an SDR screen), and writes the swapchain, times the white level. HDR output: before acquiring each frame, `updateDisplayOutput` reads the window's `SDL_PROP_WINDOW_HDR_ENABLED_BOOLEAN`, headroom and SDR white level (`readDisplayCapabilities`; whether an `HDR_EXTENDED_LINEAR` swapchain is supported is asked only when HDR comes on) and `chooseDisplayOutput` picks `DisplayOutput{hdr, peakBrightness, whiteLevel}`: HDR when `DisplaySettings::hdrOutput` and the screen allow it, white at `paperWhiteNits / 80` (scRGB's 1 is `scrgbWhiteNits`, 80) or Windows' level, the peak at `peakNits` or the monitor's (headroom times its white), never past the monitor's nor below white, in units of white. When `hdr` changes it waits for the GPU, switches the composition (`setSwapchainComposition`, keeping the present mode; a refused HDR swapchain is logged and marked unsupported) and rebuilds the swapchain-format pipelines (`createScreenPipelines`: tone mapping and `DebugLineRenderer`), logging the peak and white. `ToneMapUniformData` (32 bytes) carries the white level and whether to dither (only on SDR), plus the bloom strength (`parameters.w`, 0 = none) and scale (`output.z`); debug line colours are multiplied by the white level (`buildDebugLineVertices(lines, colourScale)`). Bloom (`render/gpu/bloom`, `BloomSettings`: `enabled`, `strength` 0.04, `radius` 1, `fireflyReduction`, `maxLevels` 6 of at most `BLOOM_LEVEL_LIMIT` 8): between the main pass and tone mapping, `BloomRenderer` (`render/gpu/bloom_renderer`, owned by `GpuRenderer`) halves the scene down a chain of separate `R11G11B10_UFLOAT` textures (16-bit float if unsupported; separate textures, not mips, so a pass never reads what it draws into), level 0 half the frame, `bloomLevelCount` stopping before a side drops below `BLOOM_SMALLEST_LEVEL_SIDE` (4), with `bloom_downsample.frag` (Jimenez's 13-tap filter as five weighted 4x4 boxes; the Karis average, boxes weighted by 1 / (1 + luminance) and renormalised, on the first halving only), then grows it back with `bloom_upsample.frag` (3x3 tent, reads `radius` texels apart, additive blending onto the level's own halving). `tone_map.frag` reads level 0 with a linear sampler (fragment sampler slot 1; the scene stands in when there is no bloom) and mixes `mix(scene, bloom / levelCount, strength)` before exposure, so light is moved, never added. `bloomBlur`, `bloomDownsample`, `bloomUpsampleAdd`, `sampleBilinear` and `mixBloom` mirror the shaders on the CPU for tests (energy kept, flat images unchanged, mirror symmetry). `getDisplayOutput()`. Its last step dithers: it encodes the colour to sRGB, adds up to half an 8-bit step of interleaved gradient noise (from `gl_FragCoord`), and decodes, so dark gradients do not band (`core/dither` mirrors and tests it; the GLSL lives in `assets/shaders/dither.glsl`, a shader-only include with the sRGB curve and the noise, which `triangle.frag` also uses for soft shadows; `tools/package_demo.py` skips `.glsl` files). Shading is physically based (glTF metallic-roughness, `render/gpu/brdf`, mirrored and tested on the CPU like the other shader maths; its numbers, dielectric reflectance 0.04, smallest roughness 0.045, smallest view cosine and the table size 32, in the macro header `render/gpu/brdf_shared.h`): per light, the GGX distribution times Smith height-correlated visibility times Schlick Fresnel, scaled by a multiple-scattering energy compensation `1 + f0 (1 / E - 1)` (Turquin 2019), plus Lambert diffuse weighted by `1 - specular albedo`, so a white surface under uniform light returns exactly what it receives (the white furnace test). Unit convention: the BRDF is multiplied by pi, so a light's radiance is the irradiance it gives a surface facing it and a white matte surface lit head-on by 1 shows 1 (the pre-PBR brightness). `ShadingPoint` (shader and CPU, `prepareShading`) is worked out once per pixel: `f0 = mix(0.04, baseColour, metallic)`, alpha = roughness squared, and from the specular albedo table (`BrdfTable`: scale and bias for f0 over n.v and roughness, texel i at i / (size - 1), integrated at start-up by `buildBrdfTable` with GGX importance sampling along a Hammersley sequence, 4096 samples per texel, about 85 ms in release; uploaded by `GpuRenderer::createBrdfTable` as `R16G16_UNORM` via `brdfTableTexels`) the compensation, the specular albedo and the weighted diffuse colour. Ambient returns `ambient * (diffuse + specularAlbedo)`, so metals are not black under ambient light. Fragment samplers: 0 colour, 1 shadow atlas (compared), 2 shadow atlas (raw), 3 metallic-roughness, 4 BRDF table. The demo's glowing materials (moon, bulbs, floodlight heads, marker) share `glowMaterial` (black, roughness 1); the teapot is real gold (metallic 1, roughness 0.35); `Vec3 * Vec3` multiplies component by component, as GLSL does; limits are 4 directional, 64 point and 8 spotlights (2736 bytes); with more, `prioritizeLights` picks the most important (see Shadows above). The software renderer still hardcodes a light at `(-1, 2, 1)`. The demo's ambient 0.2 plus sun 0.8 reproduces the old hardcoded look; it is night (ambient 0.012 (`nightAmbient`), tiny because linear values are brightened a lot by the sRGB encoding); a glowing moon sphere sits at a fixed place 64 units from the free camera's start (about 20 seconds of flying in F3 mode, so it can be reached; it therefore shows parallax, unlike the real moon), in the direction the moonlight comes from; the moonlight is a bluish shadow-casting `DirectionalLight` at intensity 0.06 (`moonlightIntensity`) (it was a `PointLight` inside the sphere for a while, to try point light shadows; directional shadows are much sharper because their box covers only 30 units), and the sphere's `ModelRenderer` has `castsShadows = false` so it does not block the light it stands for; F toggles a flashlight (a `SpotLight` entity, removed when off) that `DemoGame::updateFlashlight` places every frame in `onUpdate`: in the right hand (0.4 right of and 0.3 below the eye, aimed at the point 8 units straight ahead, so its shadows show beside things), or in MOBA mode held by the duck using its interpolated pose and `getCharacterFacing` (`gameplay/character`), tilted down 20 degrees and held 1.2 units in front of it, past its body, so the duck does not block its own light. L toggles a lamp field (`DemoGame::toggleLamps`): 100 coloured point lights, more than the 64 seats, so light priority has to choose (emissive bulb spheres with `castsShadows = false`; a 10 x 11 grid 3.5 apart minus 10 places in a keep-clear box around the spinning objects, the duck and the first-person start), each with a stone pillar beside it turned a golden angle further each time; each lamp is a `Firefly` (`gameplay/firefly`: `fireflyPosition(firefly, seconds)`, a circle round the pillar whose radius, height and speed wobble as sums of sines, staying 0.55-0.95 from the pillar and below its top) with a `PreviousTransform`, so the pillar shadows sweep round and every lit lamp's shadow tiles are redrawn each frame (a shadow stress test); the entities are destroyed when toggled off. K toggles four floodlights over the obstacle course (`DemoGame::toggleFloodlights`, on at the start, `getFloodlights`): shadow-casting cool-white `SpotLight`s (intensity 40, range 25, cone 20 to 35 degrees, `emitterRadius` 0.15 for soft shadows) whose glowing cube heads (`castsShadows = false`) hang 0.5 out from poles at `floodlightPoleFeet()` (just inside the slab's corners, `floodlightHeight` 8 up), each aimed 0.3 of the way past the course's middle so the beams cross; the poles are parts of the course renderer, so they are in the static level and stay when the lamps are off; all tuning is in named `floodlight...` constants in `demo_game.cpp` (`floodlightCount` and `floodlightHeight` in `demo_game.h`, which `floodlightPoleFeet` also needs).
