# Build log: Phase 21: Virtual geometry and virtual shadow maps (Nov 21 2026 onwards)

## Phase 21: Virtual geometry and virtual shadow maps (Nov 21 2026 onwards)

- `clusters` (Nov 21 2026): stage 1, meshes cut into clusters culled one by one. The user chose mesh shaders over a compute-written index buffer (published numbers: Granite, RTX 3070, 3.3 ms against 3.9; both of the user's GPUs have `VK_EXT_mesh_shader`).
  - **1a, clusters built** (`scene/mesh_clusters`, meshoptimizer 0.22's builder): 64 vertices and 124 triangles at most, a sphere and a cone of facing each; the cone test is exact under any transform that does not mirror, so the GPU tests the eye brought into the mesh's space.
  - **Cone use measured:** a 48 x 24 sphere's clusters span about 60 degrees, wide cones, about a quarter culled from afar; a 192 x 96 sphere's 389 clusters 47% (half the surface faces away, so 50% is the most).
  - **1b, clusters culled on the GPU** (`render/gpu/mesh_cluster_culling`, four passes after the camera's culling, behind Passes "Mesh clusters", off until 1c draws the list): pairs (instance, cluster) by prefix sums in drawing order, each style from a 256-pair block, the test run twice (count, then write) rather than a flag kept a pair, which could take tens of MB.
  - **Found while building:** the camera culls with no velocity list and no sway (the main pass writes its own motion), so one list, not two; and the cluster passes need their own copy of the view with the wind's sway, or swaying trees would be culled by their rest spheres.
  - **Rigid draws only** are tested: sway leans a tree up to about half a radian and normals are not turned, so a swaying draw near the camera, terrain patches, impostor cards, ground-following plants, lianas and thinned cards keep every cluster.
  - **Merged on the way:** two private copies of `ensureBuffer` (camera culling, placed drawing) became one in `vulkan_memory`; the two places building a `GpuCullGroup` became `placedCullGroup`.
  - **1c, clusters drawn by mesh shaders** (`mesh_cluster_draw.glsl`, one 32-thread workgroup a survivor, one indirect draw a style written by the scan pass): the vertex shaders' body became `shadeVertex` (outputs written once through macros, since mesh shaders may not read theirs back), so both place and sway alike; `invariant` positions keep the prepass's depth equal bit for bit; buffers by address, not new bindings.
  - **Found while building:** the compiler gives a mesh shader's workgroup size as an id (`LocalSizeId`), which needs Vulkan 1.3's `maintenance4` turned on (the validation layer caught it); one draw's workgroups go in rows of 32768, since a dimension is only sure to take 65535.
  - **Measured (laptop, release, 300 frames):** a wash, as expected with 95% of clusters kept. Floor: prepass 2.85/2.70 ms on/off, main 9.97/9.71, GPU 23.43/22.67. 157 m up: prepass 3.27/3.16, main 10.88/11.49, GPU 23.58/23.72. Pictures alike. The gain waits for occlusion (1d), so the switch stays off.
  - **Open:** the UI timer reads 0.28 ms with the switch on, 0.02 off, at both spots, though it runs before the cluster passes; to look at with 1d's measurements.
- `clusters` 1d (Nov 21 2026): two-pass occlusion of the mesh clusters (the user's choice: last frame's matrices, as Nanite, over a visibility bit a cluster; two pyramid builds a frame).
  - **Early list** against last frame's farthest-depth pyramid through last frame's jittered view-projection; **late list** after the prepass: what that hid, retested against this frame's pyramid, its depth drawn alone; then the whole depth kept as the next frame's history. Both lists drawn by the main pass.
  - **The test:** the sphere's box (eight corners through any view-projection, no view-space step), its pixels clamped, the level spanning two cells at most, hidden if every cell is farther than its nearest corner. Looser than Mara and McGuire's sphere outline, but takes last frame's and jittered matrices alike.
  - **Two pyramids, not one:** the late list's candidates are what the history hid, so it must outlive this frame's build; about 15-20 MB more at 1440p, only while mesh clusters are on.
  - **Never pops by construction:** the early list's mistakes (turns, movers tested at their current place, no history) only cost late draws, since a depth from fewer draws is never nearer. No camera-cut handling needed.
  - **Found while building:** random holes in a test's partial depth made a farthest pyramid hide nothing (leaky occluders, as the research said), so the test leaves whole walls out; GPU pass names must be letters only (`LATEDEPTH`).
  - **Seen (forest, debug, laptop):** `CLUSTERS 5772/8808, LATE 17, HIDDEN 2560` (29% of what frustum and facing kept); `cluster-compare` agrees (2557 hidden, 0 extra); validation clean. The user: no popping new since yesterday.
- `clusters-default` (Nov 21 2026): Passes "Mesh clusters" on by default (the user's choice: the path stage 2 builds on), measured first.
  - **Measured (laptop, release, hidden copy, medians of three; GPU ms off / on / on with occlusion):** rim 20.43 / 20.55 / 20.35, path (the Ring view) 26.03 / 26.01 / 25.82, wall 18.94 / 18.90 / 18.58, trees (`forest-climber`) 26.27 / 26.13 / 26.22, 157 m above the rim 16.14 / 16.43 / 16.23.
  - **Occlusion cut the clusters' triangles** by 36% at the rim, 54% on the path, 56% at the wall, 4% among the trees and 17% up high, yet the frame moved at most 0.36 ms: the frame is bound by shading and shadows, not triangles, as `occlusion-measure` found. Clusters with occlusion are never slower than off beyond noise (about 0.2 ms); the gains wait for stage 2's levels and stage 4's shadows.
  - **Closed:** 1c's UI timer (0.28 ms on, 0.02 off) did not come back: 0.26 ms in every mode.
  - **Found while measuring:** `set` takes `<key> <value>`, not `key=value`; the first run's switches silently did nothing, so the script now logs each reply.
- `cluster-levels-2a` (Nov 21 2026): stage 2 begun (the user's picks: test every cluster first and walk the tree only if the culling shows in the timings; the terrain's levels later, their own step; no disk cache until building shows at load).
  - **meshoptimizer 0.22 to 1.3**: `external/meshoptimizer/clusterlod.h` (groups by `meshopt_partitionClusters`, half a level, borders locked, parent error at least the children's) needs 0.25 or newer; three analyser files became `indexanalyzer` and `rasterizer`, so the folder was replaced whole, not copied over.
  - Our calls (`meshopt_buildMeshlets`, `meshopt_simplify` with `LockBorder`) kept their meaning; debug and release built without warnings, `external/meshoptimizer/clusterlod.h`'s implementation compiled clean on its own (it is first built for 2b).
- `cluster-levels-2b` (Nov 21 2026): stage 2's hierarchy built on the CPU and uploaded, the GPU still culling only the mesh's own clusters; then built on the job system (the user's order after research: parallel first, then levels only for flagged meshes, then a disk cache only if still needed).
  - **One builder:** `buildMeshClusters` now `clusterlod` throughout (level 0 from `meshopt_buildMeshletsFlex` without the cone weight, 8518 clusters against 8517 on the forest's terrain; the sphere's facing test still culls over 40%); every level's corners are the mesh's own vertices, so the vertex pool serves them.
  - **Tests caught 9 planted bugs:** parent error halved, group sphere shrunk, a coarse cluster dropped (an empty cut, then a crack), a coarse triangle flipped, every error a tenth (volume past area times error), refined group off by one, results stored largest-first, a batch's count ignored.
  - **Volume bound, not a percentage:** the coarsest cut of a unit sphere (70 triangles, error 0.13) loses 18% of the volume, honest coarsening; the test allows area times the cut's largest error (37% there, far less for finer cuts).
  - **Start-up, every level on one thread** (laptop, release, forest, nothing else running): clusters 5.6 s to 27.3 s, start-up 32.8 s to 60.0 s. Timed while the user played: 24-58 s for the same work, so timings need an idle machine. The pool's old timer also counted GPU upload waits (6-39 s for the same one-level build); it now times the build alone.
  - **Research** (`docs/research/VIRTUALGEOMETRY.md`): Unreal, Bevy and `clusterlod`'s author all build ahead of time, only meshes flagged for it; `clusterlod` 0.66M triangles a second a thread on a 7950X against our 0.38M, parallel a mesh a thread, largest first.
  - **On the job system** (`buildMeshClusters(meshes, jobs)`, `VulkanRenderer::uploadMeshes`, loading batches of 1M triangles or 256 meshes; `stepsWithinBudget`'s step now says how many it did): clusters 3.85 and 4.23 s, start-up 27.2 and 28.2 s, faster than one level on one thread was.
